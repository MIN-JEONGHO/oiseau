# 공공데이터포털 등록 사전검토 프로그램  v3.0.0

> Powered by MIN · 배포 2026-08-03

공공데이터포털 등록 안내 매뉴얼(’26.2.~)을 코드로 옮긴 검토 도구입니다.
등록하기 전에 반려 사유가 될 항목을 **기준 조항 · 위치 · 조치 방법**으로 알려 줍니다.

**v3.0.0에서 OPEN API 검토가 추가되었습니다.** 안내 매뉴얼이 파일데이터용과 OPEN API용
두 권으로 나뉘어 있고 조항 번호가 서로 겹치므로(파일 10-라 ↔ API 10-나),
화면·픽스·리포트를 모두 **구분탭**으로 갈라 두었습니다.

| 구분 | 검토 대상 | 근거 매뉴얼 | 항목 수 |
|---|---|---|---|
| **파일데이터** | CSV · TSV · XLSX · JSON · ZIP 데이터 파일 | (파일데이터) 검토사항 및 반려 사유 안내 | 1~17번 |
| **OPEN API** | 등록 정보 + 기술문서(Swagger · 명세표) | (OPEN API) 검토사항 및 반려 사유 안내 | 1~23번 |

## 실행

```bash
pip install -r requirements.txt

python main.py                                  # GUI 실행 (구분탭 2개)

# 구분 01 — 파일데이터
python main.py data.csv                         # CLI 검토
python main.py 폴더경로 -x 검토결과.xlsx          # 폴더 일괄 검토 + 엑셀 리포트
python main.py data.csv -m meta.json            # 메타정보까지 함께 검토
python main.py data.csv --fix 서식               # 서식 정리만 적용 → data_수정.csv

# 구분 02 — OPEN API
python main.py --api -m api.json                          # 등록 정보만으로 검토
python main.py --api -m api.json --spec 기술문서.json      # 기술문서까지 함께
python main.py --api -m api.json --probe --key 인증키      # endPoint 실호출 포함
python main.py --api -m api.json --fix all --fix-out 수정.json

python tests/test_rules.py                      # 파일데이터 회귀 테스트 (18건)
python tests/test_api_rules.py                  # OPEN API 회귀 테스트 (44건)
```

CLI는 반려 항목이 하나라도 있으면 종료코드 1을 반환하므로 배치 스크립트에서 활용할 수 있습니다.

## 윈도우 exe 만들기

```bat
build_exe.bat
```

`dist\공공데이터_사전검토.exe` 단일 파일이 생성됩니다. GUI는 Edge WebView2 런타임을
사용하며 윈도우 10/11에는 대부분 기본 설치되어 있습니다. HTML·CSS·JS를 `checker/ui.py`
안에 문자열로 내장했으므로 `--add-data` 설정이 필요 없습니다.

## 셀 위치 지도

검토 결과를 파일의 셀 격자에 그대로 얹어 보여줍니다. **최대 100열 × 10000행**까지 표시하며,
보이는 영역만 캔버스에 그리는 방식이라 행이 많아도 스크롤이 끊기지 않습니다.
지적사항의 셀 좌표 칩을 누르면 지도가 이동하고, 지도의 색칠된 셀을 누르면 해당 카드로 갑니다.

## 픽스 — 선택한 조항만 자동 수정

**원본 파일은 그대로 두고** `파일명_수정.확장자`로 저장하며, **입력 형식(csv · tsv · xlsx · json)을
그대로 유지**합니다. 저장 후에는 수정본을 다시 검토해 결과 탭으로 추가합니다.

**① 서식 정리** — 값의 뜻은 그대로 두고 표기만 기준에 맞춥니다.

| 조항 | 자동 수정 내용 |
|---|---|
| 10-라 | 20231231 → 2023-12-31, 10;8;30 → 10:08:30 |
| 10-바 | 항목명 단위기호를 한글로(㎟ → (제곱밀리미터)), 나머지 특수문자 제거 |
| 10-차(하이픈) | 빈값 대체용 하이픈(-)을 공란으로 되돌림 |
| 10-타 · 10-하 | 천 단위 콤마 제거, 지수표기 펼치기 |
| 10-더 | 셀 안 줄바꿈을 공백 한 칸으로 |
| 10-버 | 0212345678 → 02-1234-5678 (지역번호 없는 번호는 손대지 않음) |
| 10-파 · 10-러 | 콤마 구분자로 저장, UTF-8(BOM)으로 저장 |

**② 내용 변경** — 행이나 값을 지우거나 바꿔 원래 값이 사라집니다. 일괄 선택에 포함되지 않습니다.

| 조항 | 자동 수정 내용 |
|---|---|
| 10-나 · 10-다 | 주석 행, 소계·합계·평균 행 삭제 |
| 10-거 · 17-다 | 수식 오류값·깨진 문자 제거 |
| 10-서 | HTML 태그 제거 |
| 10-머 | 주민번호·휴대전화·이메일 마스킹 |

**③ 자동 수정 불가** — 빈 항목명·빈 셀 채우기, 지역번호 추가, 열 수 불일치, 깨진 글자 복원,
한글 항목명 작명, 공란 사유 기재는 담당자의 판단이 필요해 프로그램이 손대지 않습니다.

## 지원 형식

| 형식 | 검토 | 픽스 |
|---|---|---|
| CSV · TSV · TXT | 전수 검사 | 지원 (원본 인코딩 유지, 필요 시 UTF-8 BOM) |
| XLSX · XLSM | 첫 시트 검사 | 지원 |

| ZIP | 내부 CSV 최대 5개 검사, 확장자·이중압축 점검 | 미지원 |
| 그 외 | 확장자·용량·비정형 기준만 검사 | 미지원 |

# 구분 02 · OPEN API

등록 정보(포털 등록 화면에 넣을 값)와 기술문서를 함께 보고 1~23번을 검토합니다.
기술문서를 올리지 않아도 등록 정보만으로 검토할 수 있고, 올리면 오퍼레이션·파라메터·
에러코드 기준(12~22번)까지 검사합니다.

## 무엇을 넣나

| 입력 | 필요 여부 | 설명 |
|---|---|---|
| **등록 정보** | 필수 | 목록명 · 기관코드 · API명(영문) · 등록유형 · 서비스URL · 응답포맷 등 |
| **기술문서** | 선택 | Swagger/OpenAPI JSON, 또는 오퍼레이션 명세표(xlsx · csv) |
| **endPoint 실호출** | 선택 | 켜면 기재한 URL 을 실제로 호출해 19번·16번을 검사 |

### 기술문서 판독

두 가지를 읽습니다. 어느 방식으로 읽었는지는 화면 상단에 표시됩니다.

**① Swagger / OpenAPI JSON** — Swagger 2.0과 OpenAPI 3.x를 모두 읽습니다.
`$ref` 를 따라가 정의를 펼치고, 배열 안 객체는 `items.항목명` 형태로 계층을 펴서
전체 응답 항목을 훑습니다. `produces` · `content` 에서 응답 포맷을, 200 외 상태코드와
`x-error-codes` 에서 에러코드를 모읍니다.

**② 오퍼레이션 명세표 (xlsx · csv)** — 공공데이터포털 기술문서 서식을 훑습니다.
기관마다 서식이 조금씩 달라 **열 위치가 아니라 머리글 이름**으로 열을 찾습니다.

```
오퍼레이션명(국문) | 자전거보관소 목록 조회
오퍼레이션명(영문) | getBikeList
요청 메시지 명세
항목명(국문) | 항목명(영문) | 항목크기 | 항목구분 | 샘플데이터 | 항목설명
인증키       | serviceKey   | 100     | 필수     | abcd      | 인증키
응답 메시지 명세
항목명(국문) | 항목명(영문) | 항목크기 | 항목구분 | 샘플데이터 | 항목설명
결과코드     | resultCode   | 2       | 필수     | 00        | 결과코드
```

`요청 메시지 명세` · `응답 메시지 명세` 같은 구역 제목을 만나면 그때부터 요청/응답을
갈라 담고, `에러코드` 표는 따로 모읍니다. 머리글을 못 찾으면 조용히 빈 결과를 내는 대신
**무엇을 못 찾았는지 알려 주고 멈춥니다.**

> 별칭 부분일치는 한글 낱말에만 적용합니다. 영문까지 부분일치를 허용하면 `code` 가
> `resultCode` 에 걸려 응답 파라메터 줄이 에러코드 머리글로 오인되고, 그 아래 항목이
> 통째로 사라집니다.

### endPoint 실호출 (선택)

19번(호출 오류 · 상태코드 · 응답 지연 · 항목명 일치)과 16번(Content-Type)은 실제로
불러 봐야 알 수 있습니다. 화면에서 켤 때만 동작하며 **바깥 서버로 실제 요청이 나갑니다.**
사내망에서 외부 호출이 막혀 있으면 꺼 두세요.

- 표준 라이브러리(`urllib`)만 씁니다 — exe 용량을 늘리지 않으려는 것입니다
- 최대 5개 URL 을 **GET 으로 한 번씩만** 호출하고 응답 본문도 앞 256KB만 읽습니다
  (검토 도구가 대상 서버에 부하를 주면 안 됩니다)
- 인증키는 실제 호출에는 들어가고 **화면·리포트 기록에서는 가려집니다**(`serviceKey=****`)
- URL 에 이미 `serviceKey` 가 있으면 덧붙이지 않습니다

| 23 비공개 정보·비정형 | 개인정보 의심 항목, 비정형 비식별화, 특수 프로그램 설명파일 | ● |

● 자동 판정 · ◐ 자동 감지 후 사람이 판단

판정은 **반려 / 보완필요 / 확인권장 / 적합** 4단계입니다.

### 등록유형에 따라 검사 범위가 달라집니다

12(PUBC) · 13(GW) · 14(멀티클라우드) · 11(링크)번은 해당 유형으로 등록할 때만 봅니다.
유형을 가리지 않고 전부 검사하면 오탐이 쏟아지기 때문입니다. `등록유형`을 비워 두면
PUBC 기준으로 봅니다.

### 12-나 기술문서 ↔ 등록내용 대조

이 프로그램이 가장 값을 내는 항목입니다. 기술문서를 함께 올리면 아래를 자동으로 대조합니다.

| 대조 항목 | 어긋나면 |
|---|---|
| 서비스 URL | 등록한 URL 이 기술문서의 어느 오퍼레이션 URL 과도 안 맞음 |
| 응답 포맷 | 등록 'JSON' ↔ 기술문서 'JSON+XML' |
| 전송방식 | 등록 'POST' ↔ 기술문서 'GET' |
| API명(영문) | 등록한 이름이 기술문서 URL 어디에도 없음 |

## 픽스 — 고친 값을 대조표로

파일데이터 픽스는 데이터 파일을 고쳐 새 파일로 저장하지만, OPEN API 는 고칠 대상이
**포털 등록 화면에 넣는 값**입니다. 그래서 결과물이 파일 하나가 아니라
**'무엇을 무엇으로 바꾸면 되는지'의 대조표**이고, 화면에서 `전 → 후` 로 보여 주면서
JSON 으로도 남깁니다. 그대로 복사해 포털에 붙여 넣으면 됩니다.

| 조항 | 등급 | 자동 수정 내용 |
|---|---|---|
| 5-가 | 서식 | 목록명에서 `_` `()` 외 특수문자 제거 |
| 5-나 | 내용 | 목록명에서 주기·연도 표기 제거 — `공공데이터_개방현황(연간)` → `공공데이터_개방현황` |
| 6-가 | 서식 | 키워드 특수문자 제거 |
| 6-다 | 서식 | 띄어쓰기만 다른 중복 키워드 중 첫 번째만 남김 |
| 7-가 | 서식 | 설명의 연속 띄어쓰기를 한 칸으로 |
| 10-나 | 서식 | 담당자 연락처 하이픈 정리 — `0212345678` → `02-1234-5678` |
| 18-가 | 서식 | URL 에 붙은 요청 파라메터 제거 — `.../getList?serviceKey=…` → `.../getList` |
| 22-나 | 내용 | 포털이 출력하는 표준 에러코드 행 삭제 |
| 22-다 | 내용 | 에러코드 200 행 삭제 |

**기술문서 자체는 고치지 않습니다.** 기관이 배포한 문서를 도구가 말없이 바꾸면 등록 내용과
어긋나 12-나를 새로 만들기 때문입니다. 문서에서 고쳐야 할 값은 `기술문서에서 직접 고칠 값`
목록으로 따로 알려 줍니다.

나머지 조항은 자동 수정 대상이 아닙니다. 오퍼레이션명 작명, 항목 설명·샘플 작성,
인증모듈·포트·페이징처럼 **API 구현이나 담당자의 판단이 필요한 일**이기 때문이며,
지적사항 카드에 잠금 표시와 사유가 함께 나옵니다.

# 결과 리포트

두 구분의 결과가 **한 엑셀 파일에 함께** 들어갑니다. `검토요약` 시트 맨 앞 열이 구분입니다.

| 시트 | 내용 |
|---|---|
| `검토요약` | 구분 · 대상 · 판정 · 규모 · 등급별 건수 |
| `상세지적사항` | 구분 · 등급 · 기준조항 · 항목 · 지적내용 · 조치방법 · 위치 · 값 예시 |
| `API명세` | 프로그램이 실제로 읽어 들인 오퍼레이션·파라메터 전체 |
| `API에러코드` | 기술문서에서 읽은 에러코드 표 |
| `API실호출` | 호출 URL · 상태코드 · 응답시간 · Content-Type · 응답 항목 |

지적사항만으로는 '무엇을 보고 그렇게 판정했는지' 되짚기 어려워서, 읽어 들인 명세를
그대로 남깁니다.

# 한계

**파일데이터** — 포털 등록 여부 조회(5번), 링크 접속 확인(6번), 공공누리 마크 육안 확인(7번),
이미지·영상 내 개인정보 판별(8번)은 자동화 대상이 아니며 체크리스트로만 안내합니다.

**OPEN API** — 목록명과 데이터의 관련성 판단(2번), 타기관 동의 공문(3번), 포털 중복 등록
조회(4번), 링크 페이지 내용 확인(11번), SWAGGER Example Value 대조(14·18-아번),
조건별 응답 구조 일치(21-나번)는 사람이 눈으로 확인해야 합니다.
실호출을 켜지 않으면 19번은 확인권장으로만 남습니다.

기준이 개정되면 파일데이터는 `checker/rules_*.py`, OPEN API 는 `checker/rules_api.py` 의
해당 조항 함수만 고치면 됩니다. 픽스 정책은 `checker/fixer.py` 의 `FIXABLE`,
`checker/api_fixer.py` 의 `API_FIXABLE` 표에 모여 있습니다.
