# 연구보안 등급분류 시뮬레이터 v16

- Windows 설치형 앱 한 창에서 과제정보·고시 근거·AI 에이전트 참고 의견·HWPX 의견서 확인
- 브라우저 창·웹사이트 배포 없음. 화면 자산과 글꼴은 실행 파일 안의 로컬 자산만 사용
- 출력물은 기관 심의·의결·등급 확정을 위한 참고자료. 위원회 의결·서명·행정기관 확정을 대신하지 않음
- 실제 운영 기준은 계속 v12. v16 완료는 운영 전환이 아님
- v12~v15와 그 이전 파일은 그대로 보존. v15는 2026-10-23 인계 상태 유지

## v16에서 바뀐 것

- 화면 문구
  - 화면에만 보이는 문구를 명사형 종결 개조식으로 변경(제목·설명·안내·버튼·오류·진행 메시지)
  - 프로그램 이름 '연구보안 등급분류 시뮬레이터'로 통일. 창 제목 `연구보안 등급분류 시뮬레이터 · v16`
  - 영문 소제목·상단 표어·'研'·'연구보안 검토실' 표시 제거
  - 메뉴 5개: 01 연구개발과제 검토, 02 연구개발과제 일괄 검토, 03 검토 결과, 04 참고 고시, 05 모델·설정
- 화면 용어
  - 「연구보안 등급분류 가이드라인」 용어로 맞춤(예: 공통 검토항목→검토항목, 참고 등급→보안등급(AI 참고), 후보 제외→대상 제외)
  - 화면에만 적용. 엑셀·HWPX·저장값의 용어는 v15 그대로
- 참고 고시 화면(새 메뉴 04)
  - 고시별 카드: 고시명·고시번호·고시일·시행일·공식 출처 주소(범위·조항 수 줄은 아래 보완에서 제거)
  - 571개 조항 검색(공백·줄바꿈·대소문자 무시), 범위 선택, 더 보기, 펼쳐서 원문 보기
  - 원문은 글자로만 표시. 외부 탐색·새 창은 v15처럼 차단
  - 검색 결과 없음은 비해당 판정이 아님
- 고시일과 새 고정본
  - 새 고정본 `kr-notices-v16-1`(`resources_v16/notices`). 출처마다 고시일(`announcement_date`) 추가
  - 원문·추출·정규화·검수 파일은 v15와 바이트까지 같음. `manifest.json`·`README.md`만 새로 작성
  - 기준본 내부 이름·확인값은 접힌 상세 정보로 이동. '확인일'은 '원문 수집일'로 이름 변경
- 화면-프로그램 연결 함수 9개→11개: 읽기 전용 `search_notice_clauses`, `get_notice_clause` 추가(아래 보완에서 12개)
- 가이드라인 창: 법·시행령·가이드라인 원문 그대로 표시(표시 전용)
- 저장 결과 schema 3. v15(schema 2) 이하 결과·중간 저장은 재사용·재출력하지 않음
- 결과 엑셀 `고시기준본` 시트에 `고시일` 열 추가(`시행일` 바로 앞). HWPX 출처 부록에 고시일 줄 추가
- 일괄 검토에서 이전 버전 결과 보호
  - 고른 결과 엑셀이 v16 결과가 아닌 기존 파일이거나 중간 저장에 v15·v14 기록이 있으면 쓰기 전 중단
  - 재개 여부와 무관. 기존 중간 저장·결과 엑셀·감사 기록은 그대로 남음
  - 화면 안내: '기존 결과 파일 보호를 위해 중단. 새 결과 엑셀 경로 선택 필요'

## v16 보완 (2026-10-24)

- 사용자가 v16을 Windows 125% 배율에서 실행해 본 뒤 요청한 화면 보완. 같은 이름의 실행 파일을 다시 빌드(아직 미배포)
- 판정 방식·AI 지시문·저장 문장·결과 엑셀/HWPX 문구·저장 상태값·결과 형식(schema 3)·입력 엑셀 읽기 규칙 변경 없음
- 일괄 검토 입력 양식 내려받기
  - 위치: 02 연구개발과제 일괄 검토 → '일괄 검토 파일' 패널 맨 위, '입력 엑셀 선택' 버튼 위의 '입력 양식 내려받기' 버튼
  - 저장 대화상자(.xlsx)에서 위치 선택. 기본 이름 `v16_일괄검토_입력양식.xlsx`. 화면에는 저장한 파일 이름만 표시
  - 저장한 양식은 입력 엑셀로 자동 선택하지 않음(예시 2행만 있어 검토 대상 0건). 대화상자 취소는 오류 아님
  - 시트 2개('작성안내'·'분류대상'). '분류대상' 머리글 9개 열, 순서는 기존과 같음
    - 기본 5개 '(필수)': 세부사업명·과제명·연구목표·연구내용·기대효과(2026-10-25 보완에서 세부사업명은 '(선택)'으로 변경)
    - 추가 4개 '(선택)': 추가 검토정보·부처 세부기준·현재 기술사양·개발목표 사양
  - 예시 2행 값은 기존과 같음. '(예시)'로 시작하므로 검토에서 제외
  - '작성안내'는 명사형 개조식(과제별 한 행, 필수·선택 구분, 제외 행, 사양 구분 입력, AI 의견은 참고 의견)
  - 필수 표시는 안내일 뿐. 실제로 막는 것은 지금처럼 과제명이 빈 행뿐이며 머리글의 '(필수)'·'(선택)'은 떼고 읽음
  - 입력 양식은 '엑셀·의견서 문구 v15 그대로' 원칙의 유일한 예외. 결과 엑셀·HWPX 의견서는 v15 문구 유지
  - 보호 경로: 다음 경로에는 저장하지 않고 기존 파일을 바이트까지 그대로 둠
    - 이번 실행 중 입력 엑셀이나 결과 엑셀로 고른 적이 있는 경로
    - 옆에 `<경로>.checkpoint.jsonl` 또는 `<경로>.audit.jsonl`이 있는 경로(검토 결과 엑셀)
    - 화면 안내: '검토에 쓰는 파일 보호를 위해 저장 중단. 다른 파일 이름 선택 필요'
    - 그 밖의 기존 파일은 Windows 덮어쓰기 확인 뒤 덮어씀
  - 진행 중인 작업이 있으면 버튼 비활성. 브리지 직접 호출은 `busy`
- AI 에이전트 구성 선택 문구
  - 선택지: 'AI 기술분야 전문가 1개'(값 1), 'AI 분야별* 전문가 3개'(값 3). 기본값은 3개
  - 선택 상자 아래 각주 한 줄 '* AI 기술분야 · 연구보안 · 기술사업화 전문가'를 선택과 관계없이 항상 표시
  - 선택에 따라 바뀌던 설명 줄('…의 독립 의견과 종합 검토') 제거
  - 일괄 검토 '이번 실행의 공통 설정' 요약은 'AI 기술분야 전문가 1개' 또는 'AI 분야별 전문가 3개'('*' 없음)
  - 결과·엑셀·HWPX의 에이전트 역할 이름은 그대로
- 필수 표시(화면): 단건 입력의 기본 5개 입력란은 필수(*), 추가 4개는 '선택'. 일괄 안내 '입력 엑셀은 기본 5개 항목 필수, 추가 4개 항목 선택. 과제명이 빈 행은 제외'. 시작을 막는 조건은 지금처럼 과제명 빈칸뿐(2026-10-25 보완에서 필수 4개·세부사업명 선택으로 변경)
- 창 크기를 작업 영역에 맞춤
  - 원인: pywebview가 창 크기(1366×900)와 최소 크기(760×560)에 배율을 곱함. 125%에서 1708×1125 물리 픽셀이 되어 1920×1080 화면의 작업 영역보다 커서 아래쪽이 잘림
  - 시작할 때 창이 뜰 모니터의 작업 영역(작업표시줄 제외)과 창 DPI를 Win32로 구해 논리 단위로 비교
  - 시작 크기 = (min(1366, 작업 영역 너비 − 32), min(900, 작업 영역 높이 − 32)), 작업 영역 가운데 배치
  - 최소 크기 = (min(760, 시작 너비), min(560, 시작 높이))
  - 창 표시 전 이벤트에서 네이티브 창에 최소 크기 → 크기 → 위치 순서로 직접 지정. 측정 실패 시 기존 1366×900
  - 예: 1920×1080 125%(작업 영역 1536×825) → 시작 1366×793, 최소 760×560
- 한글 줄바꿈·잘림
  - 화면 전체 `word-break: keep-all`로 단어 단위 줄바꿈(예: '시뮬레이 / 터', '검 / 토', '시 / 행일' 끊김 해소)
  - 공백 없는 긴 문자열(URL·지문·경로·조항 원문)은 `overflow-wrap: anywhere`로 칸 안에서 줄바꿈. `break-word`는 표를 넓히므로 미사용
  - 사이드바 이름은 공간이 부족하면 단어 단위로 두 줄
  - 일괄 검토 오른쪽 요약의 두 연결('검토항목 설정 →', '모델·공통 부처기준 설정 →')을 한 줄씩 분리
  - 사이드바 배경이 페이지를 내려도 화면 높이 전체를 덮음
- 참고 고시 카드에서 범위 이름과 조항 수(전체·자동 해석·미해석) 줄 제거. 고시명·고시번호·고시일·시행일·공식 출처만 표시
  - 조항 검색의 범위 선택, 검색 결과 줄과 펼친 조항의 범위 표시는 그대로
- 화면-프로그램 연결 함수 11개→12개: `save_input_template` 추가(목록 맨 끝), `select_path`에 용도 `input_template` 추가
  - 호스트 허용 목록과 브리지 공개 함수는 순서까지 같은 12개. 모르는 경로 선택 용도는 취소가 아니라 `validation`

## v16 보완 (2026-10-25): 실제 과제 입력 오류, 세부사업명 선택

- 사용자가 실제 과제를 넣었더니 검토 시작 직후 오류 발생. 같은 이름의 실행 파일을 다시 빌드(아직 미배포)
- 원인: Claude가 JSON 앞에 설명 문장을 붙여 답함(예: 설명 한 줄 + 빈 줄 + `{"facts": []}`). 기존 응답 검사가 응답 전체가 JSON일 때만 받아 거부. 사용자가 허락한 진단용 실제 호출 2회로 확인
- AI 응답 받기
  - 응답 안에 완전한 JSON 객체가 정확히 하나면 받음. 앞뒤 설명문은 제외
  - JSON 둘 이상, 깨지거나 잘린 JSON, 배열 형태는 지금처럼 오류. 다시 묻기 없음
  - v14·v15와 같이 쓰는 `llm_client_v14.py`는 그대로 두고 v16 전용 `llm_json_v16.py`에서 처리
- 입력 글 정리(단건·일괄 과제 9개 칸, 모델·설정의 공통 부처 세부기준)
  - 엑셀 줄바꿈 표시 `_x000D_`(CR)·`_x000A_`(LF)·`_x0009_`(탭)를 실제 줄바꿈·탭으로 바꿈. 지우지 않으므로 앞뒤 글자가 붙지 않음
  - 줄바꿈 방식 통일, 줄 끝 공백·탭 제거(들여쓰기 유지), 빈 줄은 최대 하나
  - 그 밖의 글자는 그대로. 정리한 글을 AI에 보내고 결과에 저장
  - 일괄 검토는 정리한 뒤 빈 과제명·'(예시)'·중복 과제명 판단. 줄바꿈 표시만 든 과제명은 빈 행으로 제외되고 나머지는 계속 처리
- 화면 진행 표시 알림(실제로 일어난 작업에만 한 번)
  - '입력 글의 엑셀 줄바꿈 표시·줄 끝 공백·연속 빈 줄 정리 후 검토'
  - 'AI 응답 앞뒤 설명문 제외 후 JSON 결과만 사용'
  - 결과·엑셀·의견서·감사 기록에는 남기지 않음
- 세부사업명 선택
  - 필수 표시 4개: 과제명·연구목표·연구내용·기대효과. 세부사업명과 추가 4개는 선택
  - 입력 양식 머리글 `세부사업명(선택)`, 작성안내 셋째 줄, 단건 화면 '선택' 표시, 일괄 안내 '입력 엑셀은 4개 항목 필수, 세부사업명과 추가 4개 항목 선택. 과제명이 빈 행은 제외'
  - 예전 양식(`세부사업명(필수)`)도 그대로 읽힘. 시작을 막는 조건은 지금처럼 과제명 빈칸뿐
- 이전 v16 시험 결과
  - 이번 보완 전 v16으로 돌린 일괄 검토의 중간 저장은 정리 전 글이 들어 있으면 재사용하지 않고 처음부터 다시 검토(화면 경고 '중간 저장파일에 구버전 또는 손상·불일치 구조 포함…')
  - 그 결과로 의견서를 다시 내보내는 것도 입력 지문 불일치로 거부. 다시 검토한 결과에서 내보내기 필요
- 판정 방식·AI 지시문의 틀과 문구·저장 문장·결과 엑셀/HWPX 문구·결과 형식(schema 3) 변경 없음

## 판정 방식 동일

- 분류 규칙·산식·상태 판정·고시 조건 해석·AI 지시문(시스템 지시문과 요청 구성)은 v15와 같음
- 결과에 저장되는 프로그램 문장(미해결 사유·부족정보 질문·오류 사유 등)과 AI 의견 문체도 v15 그대로
- v15와 같은 결과는 보장하지 않음
  - 새 고정본 때문에 AI에 함께 보내는 고시 정보(기준본 이름·확인값·출처별 날짜)가 달라짐
  - 같은 과제라도 AI 응답과 결과가 v15와 다를 수 있음

## 사용 순서

1. **05 모델·설정**: 모델 선택(Claude Sonnet 5.5 `claude-sonnet-5-5`, OpenAI GPT-6 Luna `gpt-6-luna`, Ollama, LM Studio)
   - 외부 모델 키는 현재 Windows 계정 자격 증명 관리자에 제공자별 자동 저장, 다음 실행에 재사용
   - 화면에는 저장 여부만 표시. 저장됨 표시는 인증 성공이 아님
2. **01 연구개발과제 검토**: 과제명·요약 입력. 현재 기술사양과 개발목표 사양 구분 입력
   - 법적 정의·기준 체크리스트 또는 국가영향 수준 지표 중 하나 선택
   - 검토항목 자동 선정 시 선택 항목 가중치 모두 1.0. 직접 선정 시 0.8~1.2, 평균 1.0 검사
   - 마지막 의견 엄격도는 항상 표준
3. AI 에이전트 구성 'AI 기술분야 전문가 1개' 또는 'AI 분야별* 전문가 3개'(AI 기술분야·연구보안·기술사업화 전문가)의 독립 의견 확인
4. **03 검토 결과**: 근거·부족정보·에이전트 의견·저장 상태 확인. 저장 결과로 의견서 재생성 가능
5. **04 참고 고시**: 고시별 정보 확인, 조항 원문 검색
6. **02 연구개발과제 일괄 검토**: 9열 입력 엑셀(`분류대상` 시트, 과제명·연구목표·연구내용·기대효과 필수 표시, 세부사업명과 추가 4개 선택, 실제 검사는 `과제명`만)과 입력과 다른 새 결과 경로 선택
   - 입력 양식은 '입력 양식 내려받기' 버튼으로 저장
   - 결과: 결과 엑셀(5개 시트), `<결과경로>.checkpoint.jsonl`, `<결과경로>.audit.jsonl`, 의견서 폴더
