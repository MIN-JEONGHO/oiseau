# 과제정보와 자격증명의 취급

보호 대상은 API 키, 입력 요약·추가 검토정보·부처 기준·현재/목표 사양, 에이전트별 판단, 참고 등급, HWPX, 결과 엑셀과 체크포인트다. 기관별 허용 사용자·파일 보관기간·삭제 책임·감사 필수 여부는 미정이다. 앱은 기관 로그인·역할별 권한·보관기간 강제를 제공하지 않으며 현재 Windows 계정과 파일 권한을 사용한다.

## 전송과 접근 범위

사용자가 수용한 범위는 분류에 필요한 과제요약정보의 외부 전송이다. 선택한 추가 정보·부처 기준·사양도 모델 요청에 포함되므로 입력 전에 범위를 확인한다. 전체 원문·첨부·기관의 모든 정보 반출 허용으로 확대하지 않는다. 외부 전송 불가 시 Ollama·LM Studio를 사용하며 서버 주소가 실제 내부 목적지인지 확인한다. 모델 이름만으로 내부 통신을 보장하지 않는다. 제공자 보관·학습 계약, 기관 반출 승인·비식별화 기준은 별도 확인 대상이다.

| 주체 | 허용 동작과 조건 | 허용하지 않는 동작 |
| --- | --- | --- |
| 현재 Windows 사용자 | 앱에서 입력·실행·키 저장/삭제, 네이티브 선택창으로 입력·저장 위치 선택 | 앱이 기관별 업무 권한을 대신 인증하는 것으로 간주 |
| 앱의 고정 UI | 로컬 원본에서 허용된 브리지 함수(v15 9개, v16 11개) 호출, 목적별 경로 토큰과 과거 작업 식별자로 요청 | 임의 파일 경로·결과 사전을 주입해 파일 접근/내보내기, 비공개·dunder·내장 함수 호출 |
| Python 분류 작업 | 시작 때 고정한 제공자·모델·기준본으로 필요한 입력 및 근거 전송 | 조용한 모델 대체, UI의 외부 페이지를 통해 키·과제정보 전달 |
| 문서 출력 작업 | 검증한 저장 결과로 문서를 생성하고 해당 배치 기록 갱신 | 키·모델 호출·현재 설치 고시를 다시 조회해 과거 결과 변경 |

WebView는 앱의 로컬 UI만 연다. 네이티브 메시지의 발신 원본·패킷·함수명을 첫 UI 로드 전에 검사하고 노출 이름은 get_initial_state, select_path, save_key, delete_key, start_single, start_batch, get_job, cancel_job, start_export로 한정한다. v16은 여기에 읽기 전용 search_notice_clauses, get_notice_clause를 더한 11개로 한정한다. 두 함수는 검증된 기준본만 읽고 파일·키·작업 상태를 바꾸지 않으며 모델을 부르지 않는다. js_api 객체와 비공개 속성을 노출하지 않으며 대입 인자 오류도 안전한 고정 오류로 반환한다. 외부 리소스·페이지 이동·새 창·파일 URL·다운로드를 차단한다. WebView2를 사용할 수 없으면 구형 MSHTML로 전환하지 않고 초기화를 중단한다.

## API 키

앱이 현재 Windows 계정의 일반 자격증명 저장소를 호출해 제공자별로 저장·불러오기·교체·삭제한다. 자격증명 이름은 ResearchSecurityGradeClassifier/api-key 아래 제공자별로 구분하며 버전별로 바꾸지 않는다. 같은 PC·계정에서 재사용하고 다른 PC로 동기화하거나 배포하지 않는다. 별도 Windows 창 조작·저장 비밀번호가 필요 없다.

사용 순서는 새 입력, 제공자별 저장 키, 기존 ANTHROPIC_API_KEY/OPENAI_API_KEY 환경변수다. 환경변수는 명시적 새 입력 적용 없이 영구 저장하지 않는다. 빈 입력은 기존 키를 덮어쓰지 않는다. 저장 실패는 알리고 유효한 입력 키는 이번 실행 메모리에서 사용할 수 있으며 평문 파일로 우회하지 않는다. 환경변수 사용도 출처 경고로 알린다. 불러오기 실패는 재입력을 안내한다. 삭제는 앱 저장 항목·현재 입력·메모리를 지우며 환경변수나 제공자 측 계정을 폐기하지 않는다.

키 입력은 가리고 적용 후 입력란을 비운다. 원문을 renderer 반환값·DOM 재주입·브라우저 저장소·소스·설정 JSON·예외·로그·지문·체크포인트·결과·문서·패키지에 넣지 않는다. 화면의 키 유무는 인증·권한·할당량 확인이 아니다. 실제 노출 키의 폐기·교체는 제공자 측에서 수행해야 한다.

## 기록과 배포

대량 감사에는 시각·실행식별·과제/옵션 지문·분류/문서 상태와 문서 재생성 기록 상태를 남기고 입력 원문·키·모델 요청문·예외 원문을 넣지 않는다. 감사 쓰기 실패는 경고와 상태로 알리되 분류 결과는 보존한다. 단건은 감사 미사용이며 법정 완전 감사·위변조 방지·누락 없는 기록으로 표시하지 않는다. 기준본의 해시·manifest는 구조와 무결성 비교용이며 파일 작성자 인증·전자서명이 아니다.

체크포인트에는 문서 재생성에 필요한 입력 스냅샷과 상세 평가·고시 근거가 남는다. 결과 엑셀과 HWPX에도 입력·판단 내용이 남으므로 감사에 원문이 없다는 이유로 모든 산출물을 비민감 자료로 보지 않는다. 화면 지우기·앱 종료·키 삭제는 산출 파일 삭제가 아니다. v12·v13 감사에는 입력 원문과 숨겨진 쓰기 실패가 있을 수 있으며 v15 정책을 과거 버전에 적용했다고 간주하지 않는다.

과거 v10/v12 Claude 변형 원본에는 키 형태 하드코딩 문자열 위험이 있다. 값을 재출력하지 않으며 새 작업 사본·빌드에서 제외하고 사용자 원본은 보존한다. 활성 키였는지는 확인되지 않았고 실제 키였다면 소유자가 제공자 측에서 폐기·교체해야 한다.

검증은 합성 입력·모의 응답·가짜 키 저장소를 사용하며 실제 자격증명을 열거·읽기·변경하지 않는다. 커밋·배포는 명시적 경로만 검토하고 실제 입력·감사·체크포인트·키·전체 가이드라인을 제외한다. 공개 고시 원문과 필요한 파생 템플릿은 분류 기준 자산으로 포함한다.
