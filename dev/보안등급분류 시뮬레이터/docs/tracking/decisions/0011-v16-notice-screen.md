# v16 화면 개조식·참고 고시·고시일 기준본

## 배경

사용자는 v15 화면이 구어체라 공문서 개조식으로 바꾸고, 특별한 설명이 필요한 경우가 아니면 최종 가이드라인 용어를 쓰고, 참고 고시를 한 화면에서 확인하고, 고시 기준 날짜를 실제 고시일로 바로잡도록 요청했다(2026-10-23). v15 화면의 기준본 이름 `kr-notices-2026-10-21-v3`에 든 날짜는 원문 수집일이었다.

## 결정

- v15를 보존하고 v16을 새 파일로 만든다.
- 고시일을 담은 새 기준본 `kr-notices-v16-1`을 만든다. 원문·조항·검수 파일은 v15와 바이트까지 같고 manifest 출처에 고시일만 더한다.
- 브리지 함수를 9개에서 11개로 늘린다(0008의 9개 원칙을 v16에서 변경). 늘어난 두 함수는 참고 고시 조항 검색·원문 조회용 읽기 전용이다.
- 개조식·용어 변경은 화면에만 적용한다. 결과에 저장되는 문장, 엑셀·의견서 문구와 저장 상태값, AI 지시문, AI가 쓰는 의견 문체는 v15 그대로 둔다.
- 가이드라인 창은 법령·가이드라인 원문을 그대로 보여 주고, AI 지시문의 정리 문장은 바꾸지 않는다.
- 참고 고시 화면은 대조에 쓰는 571개 조항만 보여 주고 본문 전체는 공식 출처를 안내한다.
- 이전 버전이 만든 결과 엑셀을 v16 일괄 검토의 결과 파일로 고르면 덮어쓰지 않고 멈춘다.

## 대안과 판단

- 기준본은 그대로 두고 고시일을 별도 표로 실행마다 대조하는 안은, 사용자가 '날짜만 바꾸는 수준이 아니면 별도 표'라고 했다가 생성 도구 재실행이 필요하다는 설명을 듣고 새 기준본을 골라 버렸다.
- AI에게 개조식으로 쓰라고 지시하는 안은 사용자가 처음 골랐다가 철회했다. 지시문이 바뀌면 결과 확인에 유료 호출이 다시 필요하기 때문이다.
- 고시일을 AI 전송에서 빼는 안은 거절했다. 새 기준본은 이름·지문도 바뀌므로 결과가 v15와 같다는 보장은 어차피 할 수 없다.
- 세 고시 본문 전체를 넣는 안은 생성 도구·기준본·검증 범위가 커져 채택하지 않았다.

## 영향

v16 결과는 schema3이고 v15 결과·중간 저장 기록과 서로 재사용하지 않는다. 판정 방식은 같지만 결과 동일은 보장하지 않는다. 화면과 엑셀·의견서의 용어가 일부 다르게 보인다(예: 화면 '대상 제외', 엑셀 '후보제외'). 기준본을 다시 만들 때 원문·파생 파일이 v15와 바이트까지 같아야 한다.
