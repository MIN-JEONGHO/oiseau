# 단일 창 설치형 웹 UI

## 배경

사용자는 기존 설치형 화면의 디자인을 개선하고 입력·에이전트별 의견·고시 근거·파일 출력을 정돈된 흐름에서 사용하기를 원했다. Tkinter는 기존 Python 처리와 연결이 쉽지만 장문 근거·접힘 영역·반응형 화면을 세밀하게 구성하는 데 제약이 있었다.

## 결정

v15는 pywebview와 Microsoft Edge WebView2의 단일 설치형 창 안에 로컬 HTML/CSS/JavaScript UI를 넣는다. Python 분류·문서 기능을 재사용하며 회녹색 탐색 영역·아이보리 작업 영역·teal 강조색과 로컬 폰트를 사용한다. 별도 웹사이트 배포나 브라우저 창·기관 서버를 요구하지 않는다.

## 대안과 판단

Tkinter 스타일만 교체하면 새 런타임 의존성을 줄일 수 있지만 사용자가 승인한 화면 재구성과 장문 근거 탐색의 표현 폭이 좁다. 외부 브라우저 웹앱은 접근성이 높지만 서버·인증·공개 포트·배포 운영을 추가한다. 설치형 웹 UI는 현재 Python 코어를 유지하면서 화면 구성 자유도를 확보하는 대신 WebView2 Runtime과 네이티브 메시지 경계를 추가한다.

## 영향

WebView2가 없으면 설치를 안내하고 종료하며 구형 MSHTML로 전환하지 않는다. 고정 로컬 UI만 열고 9개 브리지 함수·발신 원본·경로 토큰을 검사한다. 실제 SDK 요청은 Python에서 수행한다. 소스와 패키징 실행 파일 모두에서 UI/브리지·외부 접근 차단을 확인하며 pywebview 내부 연결 변경은 재검증해야 한다. 전경 한글·실제 Windows 배율 검증은 숨긴 WebView 확인과 별도로 남는다.
