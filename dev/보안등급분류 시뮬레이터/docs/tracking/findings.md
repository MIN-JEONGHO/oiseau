# 남은 문제와 확인 제한

## 한글 전체 실열람과 실제 Windows 배율 보류

v16도 같은 상태다. v16 의견서(고시일 부록 포함)의 한글 실열람, v16 전경 화면(참고 고시 화면·개조식 문구 포함)과 실제 125%/150% 배율은 확인하지 않았다. headless Edge·숨긴 WebView 확인만 했다.

v15의 두 방식·1/3개 에이전트·긴 근거·종합 의견서·고시 부록은 ZIP/XML과 내용·수량을 자동 검증했지만 모든 파일을 한글에서 직접 열지는 않았다. 표시검수용 합성 HWPX 12개도 생성·결과 구조 검증을 마쳤으나 한글 열람은 수행하지 않았다. 이 문서의 인위적 조건은 실제 고시 판정이나 예시과제집 정답이 아니다.

headless Edge에서 좁은 화면과 장문 결과를 렌더링하고 숨긴 실제 WebView에서 UI·9개 비동기 API를 확인했지만 사용자 전경 앱 및 실제 Windows 125%/150% 배율의 판독성을 증명하지 않는다. 사용자가 데스크톱 제어를 중단했으므로 직접 제어를 재개할 수 없다. 명시적 재개 후 합성 문서 전체 페이지와 정상·오류·검토필요 화면을 실제 배율에서 확인해야 한다. 미실시 자체를 코드 결함으로 단정하거나 자동 검증으로 대체 통과시키지 않는다.

과거 v14의 명칭·점수 표시 변경 전 지표·1개 에이전트 합성 의견서는 한글 2024에서 복구 경고 없는 3쪽과 첫 페이지 표를 확인했다. 이 관찰은 v15 출력 전체의 표시 검증이 아니다.

## 고시 의미 지원 범위

공식 기준본에는 571개 기록(실항목 507개·정의/주석 64개)을 확보했다. 실항목 중 414개는 미해석, 3개는 일부 조건만 구조화되어 있다. 관련 후보의 미해석 조건은 정보 부족과 질문으로 남으므로 이 조건을 포함한 과제를 모두 자동 확정할 수 없다. 전체 원문 확보와 전체 의미 해석은 다르다.

지원 확대에는 각 항목의 용도·예외·수치·단위·참조를 공식 원문과 대조하고 전문 검수·오프라인 회귀검증을 거친 새 기준본이 필요하다. 검수되지 않은 모델 추정으로 메우면 보호 필요성 또는 통제 해당 여부를 오표시할 수 있어 현재 자동 확정하지 않는다. 상황허가·국가별 제재·실제 수출허가 판단도 현재 범위 밖이다.

## 실제 모델·실무 정확도 미시험

정확한 모델 식별자와 SDK 요청·오류는 모의 검증했으나 실제 API 인증·계정 권한·할당량·유료 호출은 수행하지 않았다. 따라서 표시된 모델의 해당 계정 접근 가능성을 시험 통과로 보장할 수 없다. 실제 연구과제 분류 정확도도 별도 전문 검토 대상이며 AI 의견·기존 예시를 공식 판정 정답으로 승격하지 않는다. 실제 키·생산 자료를 사용하지 않는 검증 조건 때문에 이번 자동 회귀로 해결할 수 없다.

## 기관 정보 취급 정책 미정

앱 로그인·역할 분리가 없고 체크포인트·엑셀·문서에 입력과 상세 근거가 남는다. 기관별 허용 사용자·보관기간·삭제 책임·감사 필수 여부·반출 절차는 미정이며 개발자가 임의로 결정할 수 없다. 기관이 정한 정책에 따라 파일 권한·전송 대상·산출물 보관을 정해야 한다. 대량 감사는 지문·상태 중심이며 실패를 알리고 단건 감사는 미사용이므로 법정 완전 감사로 사용할 수 없다.

## 과거 변형의 하드코딩 자격증명 위험

기존 v10/v12 Claude 변형 원본에 API 키 형태 리터럴이 있다. 값을 재출력하지 않고 새 작업 사본·빌드에서 제외했으며 사용자 원본은 보존했다. 활성 키 여부와 소유자 측 폐기는 확인되지 않았다. 실제 키였다면 소유자가 제공자 측에서 폐기·교체해야 하며 앱 파일 제외만으로 계정 키가 무효화되지는 않는다.

## 과거 실행 경로의 한계

v12·v13은 과제명만으로 완료 결과를 재사용하므로 같은 이름의 다른 내용·모델·기준이 섞일 수 있다. 누락 점수의 대체·복제·범위 자르기, 빈 criteria·부분 항목명·불완전 의견 처리, 숨겨지는 감사 실패와 문서 누락·파일명 충돌·1,000건 초과 출력 중단 위험이 남아 있다. 별도 운영 전환 전에는 기존 결과 경로를 분리하고 실제 자료의 누락을 확인해야 한다.

v14는 분류 본문이 같은 오래된 보고서로 연속 재출력하면 앞서 갱신한 다른 과제의 문서 상태가 엑셀에서 되돌아갈 수 있음을 합성 재현했다. v15는 최신 체크포인트와 문서 상태까지 대조해 쓰기 전에 거부하고 화면의 배치 문맥도 공유하지만 과거 v14 원본은 수정하지 않았다. 과거 파일 보존 범위 때문에 기존 버전의 해결로 표시하지 않으며 재출력 기록을 따로 확인해야 한다.

## 예시과제집 미정

수록 대상·근거 검토 주체·공개 정보 범위·정답 검토 절차가 정해지지 않았다. 실제 업무 자료를 공개하거나 AI 출력으로 자동 출간할 수 없으며 사용자·기관의 별도 결정이 필요하다. 표시검수용 인위적 조건·합성 출력은 출간용 예시나 분류 정답을 대신하지 않는다.

## 실행 파일 숨김 자체 확인의 간헐적 초기화 실패 (2026-10-25)

재현 조건: 2026-10-25 재빌드 직후 실행 파일 `--self-check`를 숨김으로 7번 돌렸다. 1번째와 3번째가 '앱 초기화 실패…' 하나로 끝났고, 나머지 5번(2번째, 4~7번째)은 통과했다. 같은 시점 소스 자체 확인은 3번 모두 통과했다. 이번 보완은 호스트·화면·묶음 설정을 바꾸지 않았다.

영향: 동료 PC에서 첫 실행이 같은 안내로 끝날 수 있다. 다시 실행하면 되는 경우로 보인다.

못 푸는 이유: 실행 파일은 초기화 예외를 고정 안내로 바꾸고 원인을 남기지 않는다. 빌드 직후 보안 프로그램(이 PC의 안랩 제품)이 새 실행 파일이나 압축 해제 폴더를 검사한 것이 원인으로 추정되지만 확인하지 않았다.

가능한 처리: 초기화 예외 종류를 화면에 내지 않는 진단 기록(키·자료 없이)으로 남기는 기능을 검토한다. 배포 전 동료 PC에서 첫 실행을 확인한다.

## 일괄 검토 끝의 결과 엑셀 저장 대기와 취소 (2026-10-25)

결과 엑셀 교체가 거부되면 최대 120초까지 다시 시도한다(개인정보 검사 프로그램 대응). 이 대기 중에는 취소 요청에 바로 반응하지 않는다. 과제 결과·중간 저장·의견서는 이미 저장된 뒤이므로 결과 손실은 없다. 대기 중이라는 화면 안내를 넣을지는 이후 화면 개선 때 정한다.
