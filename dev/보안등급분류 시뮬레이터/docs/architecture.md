# 구성과 데이터 흐름

v15는 Windows의 단일 pywebview·Edge WebView2 창 안에서 HTML/CSS/JavaScript 화면과 Python 분류 기능을 연결한다. 별도 웹사이트·기관 서버·공유 데이터베이스·기관 로그인은 없다. 실제 운영 기준 v12와 v13·v14는 독립 실행 경로로 보존하며 v15 구현이 운영 전환을 뜻하지 않는다.

| 구성요소 | 책임과 연결 방향 |
| --- | --- |
| security_grade_classifier_v15.py | WebView2 실행 환경을 확인하고 고정 UI 자산 서버·숨김 자체 확인·네이티브 파일 선택·창 수명을 연결한다. |
| ui_v15/ | 입력·설정·진행·에이전트별 결과·현재/목표 고시 근거를 표시하고 9개 비동기 브리지 함수만 호출한다. 폰트는 로컬 자산이다. |
| desktop_bridge_v15.py | 경로 토큰·키 관리·불변 실행 옵션·단일 활성 작업·증분 진행 이벤트·저장 결과 내보내기를 연결한다. |
| v15_domain.py | 8항목·정의·조항·산식, 입력/옵션 정규화, schema2 결과와 고시 근거의 일치 검증을 제공한다. |
| notice_catalogue_v15.py | resources_v15/notices의 원문·정규화 조건·검수 기록을 manifest로 검증하고 불변 기준본을 반환한다. |
| notice_review_v15.py | 주입된 JSON 클라이언트와 공통 도메인으로 입력 사실 추출·전체 고시 색인 검토·후보 조건 및 참조 대조를 수행한다. |
| classification_v15.py | 고시 근거를 보존한 채 후보 식별·공통 항목 검토·독립 에이전트 평가·표준 종합 의견을 수행한다. |
| llm_client_v14.py | 두 외부 SDK 또는 requests 기반 로컬 서버 요청·안전한 오류·JSON 추출을 담당한다. |
| credential_store.py | 현재 Windows 계정의 제공자별 자격증명 접근과 입력·저장·환경변수 우선순위를 담당한다. |
| hwpx_writer_v15.py | 저장 결과와 templates/v15의 두 파생 템플릿만으로 편집 가능한 에이전트별·종합 의견서를 만든다. |
| batch_v15.py | openpyxl 입력·동시 처리, 조정자 단독 중간 저장·감사·5개 결과 시트, 문서 재생성과 기록 갱신을 담당한다. |
| v15 .spec | 새 진입점·WebView2 연결 구성요소·UI·고시 기준본·두 템플릿·아이콘·모델 SDK를 묶는다. |

단건은 화면 입력 → 브리지 검증·실행 옵션 및 기준본 고정 → 고시 사실/후보/조건 대조 → 선택한 한 분류 방식의 에이전트 검토 → 결과 검증 → 화면 표시·선택 HWPX 저장으로 흐른다. 화면에는 키 유무와 안전한 오류만 반환하며 키 원문·클라이언트·임의 파일 경로 접근 권한은 넘기지 않는다. 브리지는 한 번에 작업 하나를 실행하고 완료된 이전 결과를 세션 안에 보존한다.

화면 자산은 앱이 시작한 루프백 서버의 불변 스냅샷에서 제공한다. 이 서버는 분류 REST API가 아니다. JavaScript 요청은 네이티브 메시지 경계의 허용 함수 검사를 거쳐 Python 브리지로 전달되며 외부 URL·파일·새 창 탐색은 차단된다. 실제 모델 통신은 WebView가 아닌 Python 클라이언트에서 수행한다.

대량 처리는 실행 전체의 기준본·옵션을 고정한 뒤 과제별 독립 클라이언트로 처리하고 결과를 입력 순서로 정리한다. 조정자가 과제별 JSONL을 기록하고 결과 엑셀을 교체하며 문서 생성·감사 실패는 분류 상태와 별도로 반환한다. 서로 다른 체크포인트·엑셀·감사 파일을 하나의 원자적 저장으로 취급하지 않는다.

문서 재생성은 세션에 보존된 결과 또는 검증된 저장 결과만 소비하며 모델·키·현재 설치 고시를 조회하지 않는다. 대량 결과를 다시 내보내면 최신 체크포인트와 문서 상태까지 대조한 뒤 체크포인트 → 엑셀 → 감사 순서로 개별 갱신한다. 같은 배치의 연속 내보내기는 최신 보고서 상태를 공유한다.

외부 모델에는 선택한 과제 요약·추가 정보·부처 기준·현재/목표 사양·판단에 필요한 고시 근거가 전달된다. 입력 엑셀 파일이나 전체 가이드라인을 첨부하지 않는다. 로컬 모델도 설정 주소가 실제 전송 목적지다. reference_lists.py와 과거 앱 내부 목록은 새 고시 기준본과 자동 동기화되지 않으며 독립 excel_viewer.py의 PySide6·pandas는 v15 실행 의존성이 아니다.

## v16 실행 경로

v16은 v15 구성요소마다 같은 역할의 v16 파일(security_grade_classifier_v16 → desktop_bridge_v16 → classification_v16·batch_v16 → notice_review_v16 → notice_catalogue_v16, 공통 기준 v16_domain, 출력 hwpx_writer_v16)을 두고 v16 모듈끼리만 연결한다. llm_client_v14·credential_store는 v15와 같이 재사용한다. 화면 자산은 ui_v16, 기준본은 resources_v16/notices, 의견서 서식은 templates/v15 두 파생 서식을 그대로 쓴다. v15 경로는 독립적으로 보존되며 v16 실행 파일은 v15 실행 모듈을 묶지 않는다.

v16 화면은 11개 브리지 함수만 호출한다. 참고 고시 화면은 get_initial_state의 고시별 목록을 표시하고, 조항 목록은 search_notice_clauses, 펼친 원문은 get_notice_clause로 받는다. 두 함수는 Python 쪽에서 불러 둔 검증된 기준본만 읽고 작업 상태와 무관하게 응답한다. 검색 계산은 화면 스크립트가 하지 않는다. 결과 화면은 결과에 저장된 출처를 고시번호로 묶어 표시하며 고시명은 초기 상태의 고시명 표에서 찾는다.

단건·일괄 흐름과 AI 요청은 v15와 같다. 달라지는 것은 기준본(고시일·이름·지문)과 schema3, 엑셀 고시일 열, HWPX 고시일 줄, 일괄 검토 시작 전의 이전 버전 결과 보호뿐이다.
