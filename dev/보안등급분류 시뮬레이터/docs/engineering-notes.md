# 구현과 검증에서 주의할 동작

## 과거 버전과 실행 경로

v13_test는 실행 프로그램이며 테스트 모음이 아니다. v12~v14의 .spec·체크포인트·내부 참조 목록은 새 실행 경로와 자동 연결되지 않는다. 가장 큰 버전 번호나 열린 파일만 보고 운영 버전을 바꾸면 실제 활용 기준 v12와 어긋난다. 새 진입점·.spec·requirements를 함께 확인하고 과거 파일은 일괄 동기화하지 않는다.

## WebView 함수 노출과 초기화 순서

pywebview 6.2.1은 등록 함수가 없으면 js_api 객체의 중첩 속성을 찾는다. 비공개 밑줄 이름이 있는 객체를 js_api로 넘겨도 `_store.get` 같은 경로를 실제 디스패처가 호출할 수 있다. js_api=None과 9개 명시 노출을 사용해도 dunder 및 프레임워크 내장 메시지 경로까지 사라지는 것은 아니다. 실제 WebMessageReceived의 기존 delegate를 제거·교체해 발신 원본·패킷·9개 함수 허용 목록을 먼저 적용하고 정상 9개 비동기 호출과 금지 경로를 실제 WebView에서 함께 확인한다.

기본 공개 함수 예외 처리에는 예외 문자열·스택을 renderer로 직렬화하는 경로가 있다. 함수 본문 안의 try만으로는 인자 수 오류를 잡지 못한다. 호출 바인딩부터 안전한 공통 오류 경계로 감싸며 잘못된 인자에 키·경로·예외 원문이 포함되지 않는지 확인한다.

`gui='edgechromium'`만으로 구형 엔진 전환이 막히지 않는다. WebView2 초기화 실패 경로가 MSHTML import와 IE 모드 설정으로 이어질 수 있으므로 구형 엔진 초기화 이전에 거부하고 실제 엔진도 확인한다. before_show 시점에는 네이티브 창은 있지만 CoreWebView2가 아직 없을 수 있다. 초기화 완료 원래 처리기 이전에 필터를 설치해야 첫 로드부터 적용된다.

request_sent 이벤트에서 False를 반환하는 것만으로는 네트워크 요청을 취소하지 않는다. 네이티브 WebResourceRequested·NavigationStarting 차단을 사용하며 기본 새 창 처리기는 Handled만 추가한 후속 처리기로 무력화되지 않을 수 있어 실제 등록 흐름을 교체한다. UI의 CSP가 fetch·이미지를 먼저 막으면 네이티브 필터까지 요청이 도달하지 않으므로 CSP 차단과 네이티브 403 관찰을 구분해 시험한다. 보통 UI와 CSP를 제거한 시험 페이지의 결과를 같은 것으로 보고하지 않는다.

이 경계는 프레임워크 내부 연결 지점을 사용하므로 pywebview 버전 변경 때 source와 패키징 실행 파일에서 모두 자체 확인한다. WebView2 Runtime 자체와 로더 DLL은 역할이 다르므로 로더가 포함됐다는 이유로 Runtime 설치를 보장하지 않는다.

## 고시 원문과 분할 요청

공식 통합 원문과 ‘최종’이라는 이름의 예고 첨부가 다른 경우가 있었다. 전략물자 2026-101 시행본 대신 2026-496 예고안을 선택하지 않도록 발령·시행일·행정규칙 식별자·첨부 해시를 확인한다. 원문 공백을 정리하면 다운로드 파일과 manifest 해시가 달라지므로 원문은 바이트 그대로 보존한다.

PDF 추출만 보면 표·계층·각주가 잘못 붙을 수 있다. 항목과 참조를 HWPX 문단/표 및 PDF 페이지로 대조하고 조건식이 전이 참조를 빠뜨리지 않는지 확인한다. 예컨대 2E003.f의 코팅 표는 별개 후보가 아니라 관련 조건의 참조로 붙어야 한다. 전체 571개 기록 확보는 414개 미해석 실항목의 의미 판정 지원과 다르다.

요청 길이 제한 대응을 명목상 chunk 값만 바꾸거나 매번 전체 원문을 다시 넣는 방식으로 구현하면 실제 요청은 줄지 않는다. 긴 후보·조건식·참조·과제 문맥을 실제 별도 요청에 손실 없이 나누고 원래 JSON 경로·문자열 위치를 보존한다. 독립 호출 사이에 모델이 앞 패킷을 기억한다고 가정하지 않는다. 조각에 관련 내용이 없다는 응답은 전체 문맥을 본 음성 판단이 아니므로 부분 검토로 남겨야 한다.

사실의 인용에 숫자와 단위가 같이 있어도 다른 속성·대상·시점의 수치를 연결할 수 있다. 원문 속성·범위·단위 전체·시점을 확인하며 모델이 제안한 별칭이나 자기 자신 연결을 수치 근거의 증명으로 쓰지 않는다. ‘현재와 목표를 비교한다’는 문장은 양쪽에서 성능을 확보했다는 증거가 아니다.

## 재출력과 저장 일치

문서 재생성은 모델 응답 검사를 거치지 않으므로 저장 결과 경계에서도 공통 검증이 필요하다. 공통항목의 고시 연결은 관련 비교 ID 전체와 정확한 출처가 일치해야 하며 누락·없는 ID·중복 연결·추가 필드·중복 JSON 키를 문서 쓰기 전에 거부한다. 실제 초기 결과·후보 단계 종료·부처 기준 미제공 8번 항목의 정확한 미검토 형태만 빈 연결을 허용하며 상태 문자열 변경만으로는 예외가 되지 않는다. 합성 자료의 기준본이나 비교 ID를 바꿀 때도 관련 항목 관계를 보존하며 공통항목·에이전트 연결을 함께 갱신한다.

v14에서 과제 A를 재출력한 뒤 B를 예전 보고서로 재출력하면 A의 최신 문서 상태가 결과 엑셀에서 사라질 수 있음을 합성 재현했다. 분류 본문만 같다고 허용하면 문서 상태가 오래된 보고서의 덮어쓰기를 막지 못한다. v15는 보고서 전체 결과를 최신 체크포인트와 문서 상태까지 대조해 오래된 보고서를 쓰기 전에 거부한다. 과거 v14 원본은 수정하지 않았다.

화면에서도 배치 최초 작업만 갱신하면 재출력 작업의 새 job_id를 거친 A→B→A 저장에서 이전 상태가 재사용된다. 같은 배치의 내보내기 작업은 최신 보고서 문맥을 공유한다. 체크포인트 쓰기 실패 때는 메모리 문맥을 기록되지 않은 결과로 바꾸지 않으며 엑셀만 실패한 경우 성공한 체크포인트를 보존한다. 체크포인트·엑셀·감사는 별개 파일이므로 각 상태를 확인한다.

매 과제마다 전체 엑셀을 다시 구성하면 1,001건 처리에서 저장 비용이 급증한다. 과제별 JSONL은 계속 기록하되 전체 엑셀 스냅샷 횟수는 제한하고 열 너비·스타일 계산을 재사용한다. 성능 개선을 문서 생성 옵션의 임의 해제로 바꾸지 않는다.

Excel 셀 길이 한도는 비BMP 문자에서 Python 문자 수와 다를 수 있다. 긴 근거는 여유 있는 분할 길이로 이어쓰기하고 수식 모양 문자열을 명시적 텍스트로 쓴다. 한글·등호·플러스·골뱅이로 시작하는 값이 실제 파일에서 보존되는지 다시 읽어 확인한다.

## 문서와 시각 확인

HWPX ZIP/XML·스타일 참조·원문 보존 검사는 실제 한글 페이지 배치와 다르다. 긴 표·참조 부록이 구조상 온전해도 실제 표시를 별도 확인해야 한다. 한글 2024에서 실제 열기는 Alt+O이며 Ctrl+O는 현재 문서에 끼워 넣는 동작이다. 합성 출력은 새 문서의 정확한 열기로 확인하고 사용자 원본은 수정·저장하지 않는다.

headless Edge의 390/1366 화면과 숨긴 WebView의 실제 9개 브리지 확인은 사용자 전경 앱·실제 Windows 125%/150% 배율 검사와 다르다. 숨긴 자체 확인은 합성 자료·가짜 저장소를 사용하므로 실제 API·자격증명·법적 정확도를 검증하지 않는다. 사용자 중단 상태의 한글·데스크톱 제어는 재개 승인 전 수행하지 않는다.

Windows 원자 교체는 같은 경로 연속 갱신에서 일시적 PermissionError가 날 수 있다. 합성 검사에서는 열린 읽기 객체와 가비지 수집을 배제해도 발생했고 첫 재시도는 성공했다. 외부 원인이 확인되지 않았으므로 보안 프로그램이나 가비지 수집 문제로 단정하지 않는다. 교체 단계만 짧게 제한 재시도하고 지속 잠금은 기존 파일을 보존한 오류로 처리한다. 검증 도구는 파일 바이트를 먼저 읽어 BytesIO로 검사해 자기 읽기 핸들의 영향을 배제한다.

과거 v12·v13에는 누락 점수 대체·복제·범위 자르기와 과제명만으로 재개하는 한계가 남아 있다. 새 회귀시험 통과를 과거 파일의 수정이나 정확성으로 확대하지 않는다.

## v16 작업에서 확인한 함정

v16 모듈은 v15 파일을 복사해 만들었지만 v15 모듈을 가져다 쓰면 안 된다. v16_domain.validate_manifest는 출처 키 집합(고시일 포함)과 고시명 표·본문 출처를 정확히 검사하므로, v15 도메인이나 v15 로더가 v16 기준본·결과를 만나면 거부하고 반대도 같다. 시험 자료의 합성 manifest도 실제 고시번호, 고시마다 `-body` 본문 출처 하나, ISO 날짜를 써야 한다. 재사용할 합성 도우미는 tests/test_v16_domain.py(SYNTHETIC_NOTICES·synthetic_result)와 tests/test_v16_notice_review.py(임시 기준본·catalogue_mapping·substitute)에 있다.

v15와 v16 결과를 비교할 때는 기준본 지문에서 계산되는 값이 모두 달라진다. catalogue_id·지문 외에 comparison_id(지문+조항)와 options_fingerprint(옵션의 기준본 지문 포함)도 바뀌고, 결과 엑셀 `고시기준본`의 manifest JSON 이어쓰기 행 경계도 달라진다. 이어쓰기 행을 다시 합치고 v15 값→v16 값 대응표로 치환한 뒤 비교해야 '저장 문장 동일'을 판정할 수 있다. 날것으로 비교하면 정상 차이 때문에 실패한다.

화면 문구를 개조식으로 바꿀 때 저장되는 문장을 함께 바꾸면 엑셀·HWPX·중간 저장과 다음 단계 AI 입력이 v15와 달라진다. 미해결 사유·부족정보 질문·문서 오류 사유·`_error_result` 사유는 저장 문장이다. 분류·고시 대조의 진행 표시는 화면 전용이지만, v16 브리지는 그 문구 대신 자체 `_EVENTS` 문구를 화면에 보낸다. 예외 문자열(ValueError·CatalogueError·BatchError)은 브리지가 고정 문구로 바꾸므로 화면에 나오지 않아 v15 문장 그대로 둔다.

pywebview의 js_bridge_call은 js_api=None이어도 `__str__` 같은 dunder 이름에 응답한다. 디스패처 단위 시험으로는 비공개 밑줄 이름만 확인할 수 있고, dunder·내장 이름 거부는 호스트의 네이티브 메시지 허용 목록 시험과 숨긴 실제 WebView 자체 확인으로만 확인된다.

v16 일괄 검토의 이전 버전 결과 판정은 중간 저장 파일의 각 줄을 관대하게 해독한다. 같은 키가 두 번 있는 줄도 마지막 값으로 읽어 `schema_version` 2면 멈춘다. bool·문자열·실수 버전 값과 해독할 수 없는 줄은 이전 버전 근거로 보지 않고 v15처럼 경고 후 새로 처리한다. 결과 경로가 폴더나 바로가기면 결과 엑셀로 확인되지 않으므로 멈춘다.

git 작업 사본을 새로 만들 때 core.autocrlf=true가 소스 파일을 CRLF로 되돌린다. 고시 기준본 폴더는 `.gitattributes`의 `* -text`로 바이트를 보존하므로, resources_v16/notices를 옮기거나 새로 만들 때 이 파일을 함께 커밋하지 않으면 manifest 해시가 작업 사본에서 깨진다. 기존 v15 화면 시험(test_v15_frontend)은 프로젝트 `.dryforge/ui-v15-captures`에, v16 화면 시험은 `.dryforge/ui-v16-captures`에 캡처를 남긴다. 둘 다 커밋 제외 폴더다.

pywebview(winforms)는 create_window의 width·height·min_size에 화면 배율을 곱한다. 1366×900 창은 125%에서 1708×1125 물리 픽셀이 되어 1920×1080 화면 작업 영역보다 커지고 아래가 잘렸다. v16 호스트는 창 표시 전 이벤트(GUI 스레드, pywebview가 DPI 인식을 켠 뒤)에서 MonitorFromWindow·GetMonitorInfoW의 작업 영역(물리)과 GetDpiForWindow를 읽고, 논리 크기 = 물리 × 96 ÷ dpi(내림)로 계산한 뒤 WinForms 창의 MinimumSize → Size → Location을 직접 바꾼다. pywebview의 resize·move는 창이 보인 뒤를 기다리므로 표시 전 이벤트 안에서 부르면 20초 멈춘 뒤 실패하고, min_size는 창을 만들 때 한 번만 정해져 나중에 낮출 공개 방법이 없다. 측정이나 적용이 실패하면 원래 크기로 둔다. 창 위치는 예전처럼 마우스가 있는 모니터(GetCursorPos·MonitorFromPoint)의 작업 영역 가운데이고, 마우스 위치나 그 모니터를 읽지 못하면 창을 만든 모니터의 작업 영역 가운데로 둔다.

한글 줄바꿈은 `word-break: keep-all`로 낱말 단위로 바꾸고, 공백 없는 긴 값은 `overflow-wrap: anywhere`로 칸 안에서 나눈다. `overflow-wrap: break-word`는 표의 최소 폭 계산에 반영되지 않아 keep-all과 함께 쓰면 긴 낱말이 표를 넓혀 가로로 넘친다. 날짜 '2025-10-02'는 하이픈에서 끊길 수 있으므로 고시번호·고시일·시행일을 각각 줄바꿈 없는 단위로 묶는다. 낱말 끊김은 화면 시험에서 각 낱말 범위의 줄 사각형이 하나인지로 확인하며, 닫힌 details 안의 글자도 배치 상자를 보고하므로 checkVisibility로 보이는 요소만 검사한다.

시험 파일들은 같은 폴더의 다른 시험 모듈을 바로 가져다 쓰고 tests 폴더에 패키지 표시 파일이 없다. 그래서 `python -m unittest tests.test_v16_batch`처럼 모듈 이름으로 부르면 가져오기 오류가 난다. `-m unittest discover -s tests -p "파일이름"` 형태나 PYTHONPATH=tests로 실행한다.
