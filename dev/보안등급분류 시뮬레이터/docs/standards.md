# 변경과 검증 규칙

실제 운영 기준 v12의 전환은 별도 사용자 결정이다. v12~v14·과거 .spec·아이콘·양식·샘플을 보존하며 새 실행 경로만 명시적으로 변경한다. 과거 자격증명 포함 의심 변형은 작업 사본·배포에서 제외하되 사용자 원본을 임의 삭제하지 않는다.

Python은 4칸 들여쓰기·snake_case·PascalCase와 한국어 UTF-8을 유지한다. 무관한 전체 재서식화를 하지 않는다. 기능별 소스는 루트의 평면 모듈로 두며 자산·시험 폴더를 가상의 기능 패키지로 바꾸지 않는다. AGENTS.md와 CLAUDE.md는 바이트까지 동일하게 유지한다.

## 경계와 검증 경로

입력·옵션·계산·결과 검증은 v15_domain.py를 공통 기준으로 사용한다. 분류·화면·엑셀·HWPX에 각자 다른 수식·상태 enum을 만들지 않는다. 모델 SDK·HTTP는 llm_client_v14.py, 키는 credential_store.py, 파일 생성은 배치·출력기에 한정한다. 고시 해석 조건과 원문은 검증된 기준본에서 공급하며 모델 응답에 없는 조건·출처를 만들어 저장하지 않는다.

브리지는 시작 전에 입력·옵션·기준본을 검증하고 실행 중 변경하지 않는다. 화면에는 안전한 이벤트·검증 결과만 반환한다. 노출 함수 등록과 실제 네이티브 메시지 수신 허용 목록을 함께 검사하며 비공개 속성 이름만으로 보호된다고 가정하지 않는다. 실제 메시지의 발신 원본·패킷·함수 검사를 첫 페이지 로드 전에 설치한다. WebView2 부재 시 MSHTML 초기화 전에 거부해야 한다.

문서 재생성은 모델·키·현재 기준본에 의존하면 안 된다. 대량 기록 갱신은 저장 결과 검증과 최신 문서 상태 대조를 통과한 경우만 쓴다. 조정자만 체크포인트·엑셀·감사를 기록하고 작업 스레드는 renderer를 직접 조작하지 않는다.

합성 입력·모의 모델로 회귀검증한다. 실제 API·생산 서비스·실제 과제를 시험에 사용하지 않으며 실제 자격증명을 열거·읽기·변경하지 않는다. 실시한 명령·실제 종료 코드·조건·결과를 남기고 미실시를 통과로 추정하지 않는다. headless Edge, 숨긴 실제 WebView, 가짜 저장소, 실제 OS 저장소, 한글 실열람, 전경 UI와 실제 Windows 배율을 구분한다.

고시 자산 변경은 공식 개정본 확인 → 원문 고정 → 조건 및 참조 정규화 → 검수 기록 → 재현 가능한 manifest/지문 → 오프라인 회귀검증 → 새 배포 순서다. 런타임 자동 다운로드나 원문 한두 줄만 바꾼 배포를 하지 않는다. 원문 공백·줄바꿈을 일괄 정리하지 않으며 해시 대상 내부에 임의 파일을 추가하지 않는다.

확인한 실행·빌드 및 전이 의존성은 requirements_v15.txt로 고정하고 pywebview 6.2.1의 네이티브 연동을 버전 상승 때 재검증한다. 실행 환경과 개발용 Playwright·PDF 추출 의존성을 분리한다. 필수 SDK의 지연 모듈·메타데이터·WebView JS/관리 DLL/네이티브 loader를 누락하지 않는다. 다른 도구의 PySide6·pandas·모델 가중치를 분류 배포에 추가하지 않는다.

변경은 검증된 작업 브랜치와 소유 경로에 한정하고 스테이징에는 검토한 경로만 명시한다. 상위 저장소·원격 업로드·main 통합·운영 배포는 구현 완료와 별도 권한으로 취급한다. 실제 키·embedded_key.py·실제 과제의 입력/감사/결과/체크포인트·전체 가이드라인을 커밋하거나 배포하지 않는다. build/dist 자동 제외를 가정하지 않으며 실행 파일의 실제 포함 목록을 확인한다.

모든 HWPX의 한글 표시와 실제 Windows 125%/150% 검사는 자동 구조 검사로 대체하지 않는다. 사용자 중단 상태의 데스크톱 제어는 명시적 재개 전 다시 시작하지 않는다. 남은 검증·정책이 있는 상태를 전체 완료·법적 정확도·운영 전환으로 표시하지 않는다.
