# 국외지원사항 자동 통계산출 프로그램 v4.2

기존 엑셀 파일(v5)의 보조시트 + 통계분석 로직을 파이썬으로 재구현한 프로그램입니다.
raw 파일 2개만 지정하면 통계분석 리포트(xlsx)와 한글 보고서(hwpx)가 자동 생성되며,
**보조시트 행을 늘리거나 참조 범위(5000행)를 신경 쓸 필요가 전혀 없습니다.** 데이터가 몇 만 건이어도 그대로 처리됩니다.

**v4.2에서 exe 하나만 옮기면 됩니다.** 매핑테이블과 표준보고양식이 프로그램 안에 들어갔습니다.

## 화면 구성 (v4.2에서 전면 개편)

화면을 **「편집 계기(Editorial Instrument)」** 로 다시 짰습니다.

### 활자 — 맑은 고딕 하나를 뼈대로

서체를 섞지 않으므로 위계는 **크기 · 굵기 · 자간**으로만 만듭니다.
표제는 크고 굵게, 눈썹표제는 아주 작게 굵히고 자간을 벌리고, 수치는 굵기로 본문과 갈라 세웁니다.

등폭 활자는 **기계값 두 곳에만** 남겼습니다 — 파일 경로, 그리고 시각이 찍히는 처리 대장.
사람이 읽는 이름과 수치는 전부 맑은 고딕입니다.

### 색 — 먹빛 계조 + 주홍(朱) 하나

주홍은 뜻이 있는 곳에만 씁니다 — 필수 입력 · 오류 · 정합성 불일치 · 연구보안 우려.
통과는 조용히(먹빛 ✓), 실패는 크게 알립니다. 모서리는 각지고 그림자는 없으며,
창 맨 위 3px 주홍 띠가 판식 표기입니다.

### DPI 인식 (v4.2)

고해상도 화면에서 흐려지지 않도록 **DPI 인식을 켰습니다.** 이전에는 윈도우가 창 전체를
비트맵으로 확대해, 이 디자인의 근간인 1px 실선과 작은 활자가 뭉개졌습니다
(4K·150% 환경에서 특히).

이제 화면 배율을 읽어 활자는 포인트 기준으로 자동 확대되고, 여백·막대 두께·캔버스 좌표는
`theme.px()`가 배율을 곱해 맞춥니다. 실선은 **화면 픽셀 1개**로 유지해 가장 정확한 세선이
되게 하고, 배율이 175%를 넘을 때만 2픽셀로 올립니다.

창 크기도 배율에 맞춰 커지지만 **화면을 넘지 않게 잘라 맞춥니다.** 150% 배율의
1920×1080 노트북에서 세로가 화면을 넘어가는 것을 막기 위한 것입니다.

화면은 **두 판**으로 나뉩니다.

### ① 산출

- **표제부** — 책 표식, 제목, 오른쪽에 입력 진행 상황과 판 번호
- **입력** — 필수 두 칸(왼쪽 주홍 세로선)이 먼저 보이고, 매핑테이블·양식·저장폴더는
  `› 양식 · 매핑테이블 · 저장폴더`를 눌러 펼칩니다
- **실행 줄** — 실행 버튼 · 전처리 체크 · 진행 표시줄
- **처리 내역** — 시각이 찍히는 처리 대장. 경고는 주홍으로 구분됩니다

연구자 raw를 고르면 과제 raw 칸이 비어 있을 때 같은 파일로 자동 채워집니다
(두 시트가 한 파일에 있는 경우가 많기 때문입니다).

### ② 대시보드 (v4.2 신규)

산출을 마치면 자동으로 이 판으로 넘어갑니다. **파일을 열지 않고 결과를 읽는 자리**입니다.
막대는 0에서 자라며 왼쪽부터 차례로 나타납니다.

| 구획 | 내용 |
|---|---|
| 표제 | 국외지원사항 등록 건수를 크게 하나 |
| 주요 수치 | 연구자 · 국가 · 과제 · 과제매핑 미진행 · 보고의무 종료 · 연구보안 우려 |
| 검산 | 유형 합계 ≥ 등록 건수 / 관련성 판정 = 과제 건수 |
| 등록 추이 | 월별 세로 막대 (최근 24개월, 연도 구분선) |
| 상위 국가 · 유형별 | 가로 막대 Top 10 / 유형 전체 |
| 소속기관 유형 · 과제 연관성 | 100% 분할 막대 |
| 최다 소속기관 · 지원기관 | 가로 막대 Top 10 |
| 연구보안 우려 | 위험국가는 주홍. 수혜 국가 목록 포함 |
| 확인이 필요한 항목 | 번호 중복·미기재, 종료일 미상이 있을 때만 나타납니다 |

막대의 짙기는 **값의 순위**를 뜻합니다(1위가 가장 짙음). 색으로 항목을 구분하지 않으므로
표가 조용하고, 주홍이 나오면 그것만 눈에 들어옵니다.

차트는 tkinter Canvas에 직접 그립니다. matplotlib을 쓰면 exe가 40MB에서 100MB를 넘겨
'한 개만 옮기는 배포'라는 목적과 어긋나기 때문입니다.

창은 크기를 조절할 수 있고, 대시보드는 휠이나 오른쪽 손잡이로 스크롤합니다.

### 매핑테이블 별칭 충돌 경고 (v4.1)

같은 원본 기관명이 서로 다른 정규화명으로 적혀 있으면 **한 기관이 둘로 나뉘어 집계**됩니다.
실행할 때 자동으로 점검해 처리 내역에 알립니다. 현재 매핑테이블에서 6건이 검출됩니다
(예: `AFOSR` → `AFOSR(미 공군과학연구국)` / `AFOSR(미 공군과학연구실)`).
[기관별칭] 시트에서 한쪽으로 통일해 주세요.

## 사용 방법 (GUI)

1. 프로그램 실행 → 창이 뜸
2. 연구자 raw 파일 선택 (연구자raw 시트가 들어있는 파일, 또는 연구자 데이터만 있는 단독 파일)
3. ② 과제 raw 파일 선택 — 두 시트가 한 파일에 있으면 **같은 파일을 두 번 선택**하면 됩니다 (①을 고르면 ②에 자동 입력)
4. ④ 표준보고양식(.hwpx) 확인 — 프로그램 폴더의 `표준보고양식.hwpx`가 자동 지정됩니다
5. [raw 파일 전처리 실행] 체크 여부 확인 (기본 켜짐)
6. [통계 산출 실행] 클릭 → **엑셀 리포트와 한글 보고서가 함께 생성**됩니다
   - `통계분석결과_날짜_시간.xlsx`
   - `국외지원사항_등록보고현황_날짜_시간.hwpx`

명령행에서도 사용 가능합니다:
```
python 국외지원사항_통계산출.py 연구자raw.xlsx 과제raw.xlsx [출력파일.xlsx]
```


## v3 신규 — raw 파일 전처리

이전에는 raw 파일을 손으로 정제한 뒤 업로드해야 했지만, v3부터는 프로그램이 처리합니다.
실행 화면의 **[raw 파일 전처리 실행]** 체크박스로 켜고 끌 수 있습니다(기본 켜짐).
이미 정제된 파일을 넣어도 결과는 같으므로 그대로 두셔도 됩니다.

처리 순서 (연구자 raw · 과제 raw 동일):

1. **지원·지급출처 국가** 가 `대한민국 / 가나 / 가봉 / 가이아나` 인 행 전체 제거
2. **지원·지급 내용** 이 무효값(`0`, `0원`, `1`, `-`, `--`, `없음`, `해당사항 없음` 등 14종)인 행 전체 제거
3. **지원·지급 사유** 가 무효값(`없음`, `해당없음`, `연구과제 없음`, `글로벌협력사업 (지급 없음)` 등 7종)인 행 전체 제거
4. **NRI 등록일자 오름차순 정렬** (날짜 인식이 안 되는 값은 맨 뒤로)

처리 결과는 실행 화면의 처리 내역과 리포트의 **[전처리 내역]** 시트에 단계별 제거 건수와
해당 값까지 남으므로, 나중에 근거를 확인하거나 감사에 대응할 수 있습니다.

### 지원·지급 기간 (병합 머리글) 처리

실제 raw 파일에서 **지원·지급 기간은 시작일·종료일 두 칸**이고, 머리글만 병합되어 있습니다
(연구자 raw는 `F1:G1`, 과제 raw는 `J1:K1`). 이 상태로 그냥 읽으면 종료일 칸의 머리글이
비어 있어 **종료일이 통째로 버려지고 시작일만 남습니다.**

병합 머리글을 인식해 **`지원·지급 시작일`과 `지원·지급 종료일` 두 개의 열로 분리**해서 내보냅니다.
기간이 원래 한 칸(`2026-06-25 ~ 2027-06-05`)인 파일은 자동으로 쪼개서 채우므로 두 형식 모두 처리됩니다.

### 파일을 잘못 지정하면 알려줍니다

연구자 raw 파일을 과제 자리에 넣는 것처럼 종류를 바꿔 지정하면, 조용히 잘못된 결과를 내는 대신
어떤 열이 없는지 알려주고 중단합니다.

### 열은 이름으로 찾습니다

실제 raw 파일과 기존 정제본은 열이 한 칸씩 어긋나 있습니다
(실제 raw: 사유 H · 내용 I · 국가 J / 정제본: 사유 G · 내용 H · 국가 I).
그래서 열 위치가 아니라 **머리글 이름**으로 열을 찾도록 했고, 두 형식 모두 그대로 처리됩니다.
머리글을 인식하지 못하면 위치 기준으로 자동 전환하며, 어느 방식이 쓰였는지 처리 내역에 표시됩니다.

### 제거 기준값 추가/수정

`매핑테이블.xlsx`의 **[전처리규칙]** 시트에서 관리합니다. 열은 세 가지(`출처국가`,
`지원지급내용`, `지원지급사유`)만 쓰고, 값은 앞뒤 공백과 끝 마침표를 무시한 **완전 일치**로 비교합니다.

완전 일치를 쓰는 이유: `0`이나 `-` 같은 값을 "포함" 기준으로 지우면 `USD 50,000`,
`한-미 공동연구` 처럼 정상적인 행까지 삭제됩니다.

### 검토 후보

제거 목록에는 없지만 무효값으로 의심되는 표기(`없음`, `해당사항`, `N/A` 등을 포함하는 짧은 값)를
발견하면 **삭제하지 않고** [전처리 내역] 시트에 목록으로 남깁니다.
확인 후 정말 제거해야 할 값이면 [전처리규칙] 시트에 추가하세요.

## 산출기준일은 raw 파일명에서 읽습니다

통계의 기준 시점은 **프로그램을 돌린 날이 아니라 raw를 내려받은 날**입니다. 그래서
`연구자 raw` 파일명에 적힌 날짜를 산출기준일로 씁니다. 며칠 뒤에 다시 돌려도 같은 raw면
같은 보고서가 나옵니다.

인식하는 표기는 다음과 같습니다(연·월·일이 모두 있어야 합니다).

| 파일명 | 산출기준일 |
|---|---|
| `국외지원사항_20260727.xlsx` | 2026-07-27 |
| `국외지원사항(2026.07.27).xlsx` | 2026-07-27 |
| `국외지원 26-07-27 최종.xlsx` | 2026-07-27 |
| `2026년 7월 27일 기준.xlsx` | 2026-07-27 |

- 연구자 raw에서 못 찾으면 **과제 raw 파일명**을 봅니다
- 실제로 없는 날짜(`2026.13.01` 등)는 건너뜁니다
- 두 자리 연도(`26.07.27`)는 **구분자가 있을 때만** 인정합니다. `v4.2` 같은 판 번호가
  날짜로 읽히는 것을 막기 위한 것입니다

찾은 날짜는 처리 내역에 `산출기준일 2026-07-27 — 파일명.xlsx` 형식으로 남습니다.
**어느 파일명에서도 날짜를 찾지 못하면 오늘 날짜를 쓰고 주홍 경고를 남깁니다.**

이 날짜는 다음 세 곳에 함께 쓰입니다.

- 보고의무 종료 연구자 판정 기준
- 한글 보고서 본문 날짜
- 한글 보고서 월별 등록 수 표의 열 구성 (`산출월−1`까지)

### 예외 — 표제 아래 발행 표기는 오늘 날짜

`(KISTEP 연구윤리자산보호센터, ’yy.mm.dd.)` 한 줄만 **문서를 만든 날(오늘)** 로 채웁니다.
이 줄은 통계의 기준이 아니라 발행 시점을 적는 자리이기 때문입니다.

## 보고의무 종료 연구자 통계

[통계분석] 시트 기본 통계에 **보고의무 종료 연구자 수** 항목이 추가됩니다.
연구자 raw 전처리 데이터를 기준으로, **산출기준일**(raw 파일명에서 읽은 날짜) 시점에
지원·지급 기간이 끝난 연구자를 셉니다.

판정 기준:

- 한 연구자가 여러 건을 신고했을 수 있으므로, **신고한 모든 건의 종료일이 산출일보다 이전**인 경우에만 보고의무 종료로 봅니다. 한 건이라도 진행 중이면 제외됩니다.
- **종료일이 비어 있거나 날짜로 읽히지 않는 건**이 하나라도 있으면 종료로 보지 않습니다(과소 판정보다 과대 판정이 위험하므로 보수적으로 처리).
- 종료일이 산출일과 같은 날이면 아직 종료되지 않은 것으로 봅니다.

**연구책임자 / 일반연구자 구분**: 과제 raw의 `연구책임자` 열에 이름이 있는 사람을 연구책임자로 봅니다.
항목에는 `N명 (연구책임자 X명 · 일반연구자 Y명 · 신고 Z건)` 형식으로 표시되고, 바로 아래 주석에
산출 기준일·기간 종료 건수·종료일 미상 건수·판정 방식이 함께 기록됩니다.

**명단은 [보고의무 종료 연구자] 시트**에 성명·구분·소속기관·신고 건수·최종 종료일·경과일·
지원 국가·지원기관 순으로 수록되며, 최종 종료일 오름차순(오래된 순)으로 정렬됩니다.

건수는 두 가지가 구분되어 표기됩니다.
- **기간이 종료된 신고 전체**: 종료일이 지난 모든 신고 건 (일부만 종료된 연구자의 건도 포함)
- **신고 Z건**: 보고의무가 완전히 종료된 연구자들의 신고 건만 합산

### 연구자 식별 기준 (v3.5부터 국가연구자번호)

연구자 관련 통계는 모두 **국가연구자번호**로 사람을 식별합니다. 성명 기준일 때 생기던
동명이인 문제(다른 사람이 한 명으로 합쳐지거나, 연구책임자로 잘못 분류되는 일)가 없어집니다.
적용 대상: 고유 연구자 수, 고유 연구책임자 수, 소속기관별 연구자 수, 다수 수령 연구자 Top 10,
과제매핑 미진행 연구자, 보고의무 종료 연구자 및 연구책임자 판정.

번호 표기는 `10000001`, `1000-0001`, 엑셀에서 숫자로 읽혀 `10000001.0`이 되는 경우를
모두 같은 번호로 봅니다(앞자리 0은 보존).

예외 처리 두 가지가 들어 있습니다.

- **번호 미기재**: 성명으로 대체해 집계하므로 해당 인원이 누락되지 않습니다. 미기재 건수는 주석에 표기됩니다.
- **한 번호에 서로 다른 성명**: 번호가 마스킹되었거나 잘못 입력된 경우입니다. 그 번호는 식별자로
  쓸 수 없으므로 해당 건만 성명으로 분리 집계하고, [통계분석] 시트 상단에 경고를 표시합니다.
  (예: 샘플 파일처럼 모든 행의 번호가 `12345678`로 동일하면 3명이 1명으로 합쳐지는데, 이 처리로 3명이 유지됩니다.)

## 한글 표준보고서(.hwpx) 출력 (v3.6 신규)

KISTEP 표준보고양식에 통계를 자동으로 채워 한글 문서를 생성합니다.
**양식 파일을 그대로 두고 안의 값만 바꾸므로 글꼴·표 테두리·여백 등 서식이 원본 그대로 유지됩니다.**

자동으로 채워지는 항목:

| 위치 | 내용 |
|---|---|
| 본문 날짜 | 산출기준일 — raw 파일명에서 읽은 날짜 (`’26.07.27.` 형식) |
| 표제 아래 발행 표기 | `(KISTEP 연구윤리자산보호센터, ’yy.mm.dd.)` — 여기만 **오늘 날짜** |
| 국외지원사항 등록 수 | 연구자 수, 연구책임자 수, 등록 건수 |
| 오입력 제외 | 전처리 전 원본 건수, 제거 건수 |
| 보고된 과제 수 | 고유 과제 수 |
| 협약 시 보고 (※줄) | 연구책임자 수 / **총 신고 건수 − 과제매핑 미진행 신고 수** |
| 월별 등록 수 표 | **산출월에 맞춰 열을 직접 만들어** 채웁니다 (아래 참고) |
| 국가별 표 | 상위 10개국 국가명·건수·비중 |
| 지원·지급 유형별 표 | 6개 유형 + 기타 + 합계(중복 산출) |
| 소속기관 유형별 표 | 학·연·산·기타 |
| 과제와의 연관성 표 | 관련있음·관련없음·합계 |
| 상위 소속기관 표 | 20위까지 |
| 상위 지원기관 표 | 20위까지, 수혜국가·연구자 소속 포함 |

표는 순서가 아니라 **머리글 문구로 찾습니다.** 양식에서 표 순서가 바뀌거나 문단이 추가돼도 계속 동작합니다.

### 월별 표는 산출월에 맞춰 열이 자동으로 늘고 줍니다

양식에 적힌 `‘24년 / ‘25년 / ‘26년 1~6월`을 그대로 쓰지 않고, **통계 산출일을 기준으로 표를 다시 만듭니다.**
열 구성은 `구분 | 완료된 연도들 | 산출연도 1월~(산출월−1) | 소계 | 합계` 입니다.

| 산출 시점 | 만들어지는 열 |
|---|---|
| 2026.07 | ‘24년, ‘25년, ‘26년(1~6월, 소계), 합계 — 11열 |
| 2026.09 | ‘24년, ‘25년, ‘26년(1~8월, 소계), 합계 — 13열 |
| 2026.01 | ‘24년, ‘25년, 합계 — 4열 (월 열과 둘째 행이 사라짐) |
| 2027.03 | ‘24년, ‘25년, ‘26년, ‘27년(1~2월, 소계), 합계 — 8열 |

연도가 바뀌면 지난 연도는 연 단위 한 열로 접히고 새 연도가 1월부터 다시 시작합니다.
열을 새로 만들 때도 양식의 셀 서식을 복제해서 쓰므로 글꼴·테두리가 그대로 유지되고,
표 전체 너비도 원래 폭에 맞춰 열 너비를 자동 배분합니다.

**주의**: 산출월 당월에 등록된 건은 표에 들어가지 않습니다(‘7월이면 6월까지’ 규칙).
그래서 월별 표의 합계는 본문의 총 등록 건수보다 적을 수 있고, 그 차이는 처리 내역에 경고로 표시됩니다.

양식 파일이 없으면 엑셀 리포트만 생성하고 그 사실을 처리 내역에 남깁니다.

## 유형규칙 시트 (v4.0)

`매핑테이블.xlsx`의 **[유형규칙]** 시트에서 유형 분류 키워드를 관리합니다. `유형 / 구분 / 값` 세 열만 씁니다.

| 구분 | 뜻 |
|---|---|
| `포함` | 이 중 하나라도 있으면 후보 (그 자체로 유형을 확정할 수 있는 표현) |
| `필수` | 후보가 된 뒤 이 중 하나가 **더** 있어야 확정 |
| `제외` | 이 중 하나라도 있으면 탈락 |
| `정확일치` | 값 전체가 일치하면 후보 |
| `조건부` | **그 자체로는 유형을 확정할 수 없는 표현**(활동명·낱개 숫자 등). 같은 칸에 `근거`가 함께 있어야 확정 |
| `근거` | `조건부` 전용 확정 조건 |

값에는 특수 토큰 두 개를 쓸 수 있습니다.

| 토큰 | 뜻 |
|---|---|
| `{수량}` | `숫자+명/인` 패턴 (예: `박사급 1명`) |
| `{금액}` | `숫자+통화·금액단위` 패턴 (예: `50,000달러` · `USD 3,000` · `3천만원` · `15백만원` · `$2,500`) |

행을 추가·삭제하고 저장하면 다음 실행부터 반영됩니다. 시트가 없으면 프로그램 내장 기본 규칙을 씁니다.

### 기타는 잔여 유형입니다 — 시트의 [기타] 행은 판정에 쓰이지 않습니다

기타는 다른 여섯 유형과 나란히 판정하지 않고 **맨 마지막에 남는 것만 받습니다.**

- 여섯 유형 중 **하나라도** 걸리면 기타를 붙이지 않습니다
- **아무 유형에도 걸리지 않은 건**만 기타가 됩니다
- 그 건이 `기술교류` · `인력양성` · `단순논의`(띄어쓴 표기 포함)에 해당하면 판정 근거로 남고,
  아니면 `어떤 유형에도 미해당`으로 남습니다

이전에는 기타의 포함 키워드가 `연구지원` · `교육` · `창업` · `양성` · `지원사업` · `award`처럼
넓어서, **이미 금전이나 연구인력으로 분류된 건에 기타가 중복으로 따라붙었습니다.** [유형 분류 내역]
시트에서 기타가 과다하게 잡히던 원인입니다.

그래서 판정 표현은 `stat_engine.py`의 `OTHER_KW`에 고정했고, **매핑테이블 [유형규칙] 시트의
`기타` 행은 무시합니다.** 표현을 늘리거나 줄이려면 `OTHER_KW` 목록을 고치세요.

### 금전은 '돈을 받은 근거'가 있어야 합니다

금전 판정 키워드를 두 층으로 나눴습니다.

- **그 자체로 금전**: `인건비` · `급여` · `연구비` · `장학` · `강의료` · `용역비` 등, 그리고 `{금액}`
- **조건부**: `공동연구` · `수탁연구` · `연구과제` · `연구지원` · `기술교류` · `컨설팅` · `료` · `/` ·
  낱개 숫자 `0`~`9` · 통화 낱말(`원` · `달러` · `USD` …)

조건부 표현은 **같은 칸에 `{금액}`이나 위 '그 자체로 금전' 표현이 함께 있을 때만** 금전으로 봅니다.
그래서 이렇게 갈립니다.

| 지원·지급 내용 | 판정 |
|---|---|
| `국제공동연구 수행` | 금전 아님 |
| `공동연구 (GPU 서버 및 실험장비 제공)` | 연구장비 및 시설만 |
| `단순 기술 교류 2회` | 금전 아님 → 기타 |
| `공동연구 USD 50,000` | 금전 (`공동연구+usd 50,000`) |
| `공동연구 인건비 지원` | 금전 (`공동연구+인건비`) |

**이전에는 `원` · `료` · 낱개 숫자 `0`~`9`가 금전의 포함 키워드였습니다.** `원`은 `지원` · `연구원` ·
`원자력`에, `료`는 `재료` · `자료`에, 숫자는 연도·횟수·수량에 걸립니다. 그래서 돈이 전혀 없는
공동연구나 장비만 받은 건까지 금전으로 집계됐습니다.

#### 기타로 떨어지기 전 금액 재판정

위 판정은 **숫자와 통화가 붙어 있는** 표기만 금액으로 봅니다. 그런데 실제 데이터에는
둘이 떨어져 있거나 통화가 아예 없는 금액 표기가 많습니다.

| 지원·지급 내용 | 왜 안 걸렸나 |
|---|---|
| `1050 미국 달러 연구 자문` | 숫자와 통화 사이에 낱말이 끼어 있음 |
| `5년간 총 200,000 (이십만) 유로` | 괄호가 끼어 있음 |
| `1,500,000/월 *12 = (총계) 18,000,000/년` | 통화 표기가 아예 없음 |
| `68000 $ per year` | 통화 기호가 숫자 뒤에 있음 |

그래서 **어떤 유형에도 걸리지 않아 기타로 떨어지기 직전에 한 번 더 진단합니다.**
아래 중 하나에 해당하면 기타가 아니라 금전으로 되돌립니다.

1. **자릿점이 찍힌 수** — `1,500,000` · `200,000`. 통화 표기가 없어도 금액으로 봅니다
   (뒤가 `명` · `인` · `건` · `개`면 수량이므로 제외)
2. **통화 표기와 수가 같은 칸에 함께 있음** — 서로 떨어져 있어도 인정 (`1050 … 달러`)
3. 엄격한 금액 패턴 (`3천만원` 등)

**이미 다른 유형이 붙은 건은 손대지 않습니다.** 아무 유형에도 걸리지 않은 건만 대상이므로
느슨한 기준을 써도 오탐이 번지지 않습니다. 되돌려진 건은 [유형 분류 내역] 시트의 판정 근거에
`내용:금액재판정 1,500,000` 형식으로 남으므로, 이 문구로 필터하면 재판정된 건만 볼 수 있습니다.

이 두 층 구분은 **매핑테이블 [유형규칙] 시트에 예전 금전 키워드가 남아 있어도 적용됩니다.**
프로그램이 시트를 읽을 때 위 조건부 표현을 자동으로 `조건부`로 내리고 `근거`를 붙입니다
(`stat_engine.py`의 `harden_money`). 시트에서 금전에 `조건부` · `근거` 행을 직접 적으면 그 값이
우선합니다.

### 연구인력 규칙 (v4.0에서 변경)

양식의 표 구조상 연구인력은 **행정적 지원**(사람을 받은 경우)이고, 인건비·급여만 받은 경우는
**재정적 지원**(금전)입니다. 원본 수식은 이 구분을 '금액·숫자가 있으면 제외'로 구현해서
`박사급 1명`처럼 인원수만 적어도 탈락했습니다(실측 21건만 집계).

v4.0부터는 소극적 배제를 없애고 **인원수 표현(`{수량}`) 또는 제공성 표현(파견·배정·채용·고용·
인력활용 등)을 필수 조건**으로 둡니다. 그 결과 `연구인력 박사급 1명`, `석박사급 3명`은 잡히고,
`포닥 월급`, `박사후 연구원 인건비`는 금전으로만 남습니다. `연구원 간 단순 논의` 같은 오탐도 사라집니다.

## 유형 분류 내역 시트 (v4.0)

어떤 건이 왜 그 유형으로 분류됐는지 건별로 확인할 수 있습니다.
한 건이 여러 유형에 해당하면 **유형마다 한 행**씩 나오므로, [유형] 열로 필터하면
해당 유형으로 분류된 건만 볼 수 있습니다.

| 열 | 내용 |
|---|---|
| 유형 | 분류된 유형 (미분류로 기타에 들어간 건은 주황색) |
| 판정 열 | 사유 / 내용 중 어디서 걸렸는지 |
| 판정 근거 | `판정열:걸린키워드` 형식. `내용:박사급+1명`의 `+`뒤는 필수조건을 만족시킨 표현 |
| 분류된 유형 수 | 그 건이 몇 개 유형에 집계됐는지 |

판정이 잘못됐으면 [유형규칙] 시트에서 해당 키워드를 고치면 됩니다.

## 배포 — exe 한 개만 옮기면 됩니다 (v4.2)

매핑테이블·표준보고양식·아이콘이 **실행파일 안에 들어갔습니다.** 이전에는 exe와 함께
네 개 파일을 같이 옮겨야 했고, 하나라도 빠지면 한글 보고서가 만들어지지 않았습니다.

```bat
pip install pandas openpyxl lxml pillow pyinstaller
pyinstaller 국외지원사항_통계산출.spec
```

- 빌드가 끝나면 `dist\국외지원사항_통계산출.exe` 하나가 생성됩니다 (약 37MB).
- **그 exe 파일만 복사하면 됩니다.** 빈 폴더에 exe만 두고 실행해도 엑셀·한글 보고서가
  모두 정상 생성됩니다.
- `pillow`는 아이콘을 다시 만들 때만 필요합니다(`python make_icon.py`). 프로그램 실행에는
  쓰이지 않고 exe에도 포함되지 않습니다.
- 사내 보안 프로그램이 exe를 차단하면, 파이썬 설치 후 `.py`를 직접 실행하는 방식도 동일하게 동작합니다.

### 양식·매핑테이블을 고쳐 쓰려면 — 내려받기

내장본은 고칠 수 없으므로 **꺼내서 고치는 방식**을 씁니다.

1. 선택 입력을 펼쳐 **[양식·테이블 내려받기]** 를 누릅니다
2. 폴더를 고르면 `매핑테이블.xlsx`와 `표준보고양식.hwpx`가 그 폴더에 나옵니다
3. 파일을 고쳐 **exe와 같은 폴더에 둡니다**
4. 다음 실행부터 내장본 대신 그 파일을 씁니다

찾는 순서는 다음과 같고, 화면의 경로 앞에 어느 쪽을 쓰는지 `[내장]` · `[수정본]` · `[지정]`
으로 표시됩니다.

| 순서 | 위치 | 표기 |
|---|---|---|
| 1 | exe와 같은 폴더에 있는 파일 | `[수정본]` |
| 2 | exe 안에 들어 있는 기본값 | `[내장]` |

- **이미 있는 파일은 덮어쓰지 않습니다.** 같은 이름이 있으면 먼저 물어보고, 아니오를
  고르면 없는 파일만 내려받습니다. 손으로 채운 별칭·규칙이 조용히 사라지는 일을 막기 위한 것입니다.
- 잘못 고쳤을 때는 **수정본 파일을 지우면** 내장본으로 돌아갑니다. 또는 내려받기에서
  덮어쓰기를 골라 공장 출하값으로 되돌릴 수 있습니다.
- `[바꾸기]`로 다른 위치의 파일을 직접 지정할 수도 있습니다(`[지정]`으로 표시).

## 아이콘 (v4.2에서 교체)

`國` 한자를 얹은 먹빛 판에서 **책**으로 바꿨습니다. 통계가 아니라 기록을 다루는 도구이고,
산출물이 보고서 두 권이라는 점에서 책이 맞는 표식입니다.

세 요소만 씁니다 — 종이빛 표지, 먹빛 등(spine), 주홍 표제띠. 등이 세로축이라 강조는
가로축으로 두어, 16px 작업표시줄에서도 두 요소가 뭉치지 않습니다.
크기마다 디테일을 덜어내며(64px 이상은 표제 활자까지, 32px 이하는 등과 띠만),
세로선은 최종 픽셀 격자에 맞춰 흐려지지 않게 했습니다.

```bat
python make_icon.py
```

`app_icon.ico`(16·24·32·48·64·128·256px 7종), `app_icon.png`, 그리고 크기 대조판인
`app_icon_preview.png`가 만들어집니다. 표제부의 책 표식은 같은 도형을 코드로 그리므로
아이콘과 항상 일치합니다.

## 기존 엑셀과의 차이점 (개선 사항)

- 참조 범위 제한 없음: 5000행 하드코딩이 사라져 데이터 건수 무제한
- 연도/월별 통계가 고정값(2024~2028, 2026-01~12)이 아니라 **데이터에 있는 기간을 자동 인식**
- 지원·지급 유형 분류는 원본 대시보드(B67~B73)와 동일한 **다중 카운트 방식**: 한 건에 여러 유형이 포함되면 각 유형에 모두 집계되고, 아래에 중복건수가 표시됩니다
- **유형 판정 키워드를 `매핑테이블.xlsx`의 [유형규칙] 시트로 옮겼습니다 (v4.0)**. 코드를 고치지 않고 엑셀에서 조정할 수 있습니다. 아래 [유형규칙 시트] 항목 참고
- **판정 대상은 지원·지급 사유 + 내용 두 열입니다 (v3.9)**. 원본 엑셀은 사유만 봤지만, 실제 데이터의 사유 열에는 연구 주제·과제명이 들어 있고 무엇을 받았는지는 내용 열에 적혀 있어 사유만으로는 절반 가까이가 분류되지 않았습니다(실측 44.9% 미분류 → 4.4%). 두 열을 이어붙이지 않고 **각각 판정한 뒤 합집합**을 취합니다. 이어붙이면 '연구인력' 규칙의 제외 조건(금액·숫자)이 내용의 금액 때문에 항상 발동해 연구인력이 사라집니다
- **과제 관련성 판정을 어구 단위로 보정했습니다 (v3.9)**. 원본 수식은 `"부"`, `"n"` 같은 한 글자를 부분일치로 찾아 `1세부 공동연구기관`, `Stipend 충족을 위한 인건비 지원`, `자격 부여`, `일부 관련` 등을 관련 없음으로 잘못 판정했습니다. 이제 한 글자 응답(`무`, `부`, `N`, `x` 등)은 완전일치로만 보고, 서술문은 `관련 없음`·`무관`·`상이`·`별개` 같은 어구로 판정합니다. 명확한 긍정 어구(`관련이 있음` 등)가 약한 부정 어구보다 우선합니다
- **정부연구비는 과제번호 기준으로 중복을 제거해 합산합니다 (v3.9)**. 같은 과제가 여러 행에 나오면 예산이 여러 번 더해져 실측 1.8배까지 부풀려졌습니다. 참고용으로 행 단위 단순 합계도 주석에 함께 표기합니다
- 원본에서는 7개 유형 어느 키워드에도 해당하지 않는 사유(예: "해외 저널 심사 참여")가 아무 유형에도 집계되지 않아 유형 합계가 총 건수보다 작아질 수 있었습니다. 프로그램에서는 이런 미분류 건(빈 사유 포함)을 **'기타'로 집계**하여 모든 신고 건이 최소 한 유형에 속하고, 중복건수가 항상 0 이상이 되도록 했습니다
- **기타는 다른 유형과 겹쳐 붙지 않습니다.** 여섯 유형 중 하나라도 걸리면 기타를 달지 않고, 하나도 걸리지 않은 건만 기타로 봅니다. 위 [기타는 잔여 유형입니다] 항목 참고
- **금전은 금액 표현이나 명시적 금전 표현이 있어야 집계합니다.** 돈이 없는 공동연구·단순 기술교류·장비만 받은 건이 금전으로 잡히던 문제를 고쳤습니다. 위 [금전은 '돈을 받은 근거'가 있어야 합니다] 항목 참고
- 단, 원본의 '금전'(B70) 수식에는 다른 6개 유형과 달리 행 단위 판정(`>0`)이 누락되어 건수가 아닌 키워드 등장 횟수를 세는 버그가 있었습니다(금전 건수가 총 건수보다 커짐). 파이썬에서는 다른 유형과 동일하게 "금전 키워드가 하나라도 포함된 건수"로 집계하도록 바로잡았습니다
- 연구보안 세부 리스트와 미매핑 연구자 리스트가 잘리지 않고 전체 출력됩니다
