# 회의록 자동정리 프로그램 v2.0.0

회의 녹음파일을 올리면 전사(轉寫) → 발언자 매칭 → 기관별 요약을 거쳐
KISTEP 표준 회의록 양식(`.hwpx`)을 자동으로 채워 주는 프로그램.

```
녹음파일  ──[ OpenAI Whisper API ]──────────────▶  전사문
          ──[ OpenAI GPT : 발언자 매칭 ]────────▶  참석자별 발언
          ──[ OpenAI GPT : 기관별 요약 ]────────▶  요약 초안
          ──────────────────────────────────▶  회의록.hwpx
```

---

## 구성

전사와 요약을 나눠 처리하지만 **둘 다 OpenAI 이고, API 키도 하나만 쓴다.**

| 단계 | 하는 일 | 모델 |
|---|---|---|
| ① 전사 | 음성 → 글자 | `whisper-1` |
| ② 정리 | 글자 → 발언자 매칭 · 기관별 요약 · 시사점 | `gpt-5.6-luna` |

두 모델 모두 `config.py` 의 `STT_MODEL` / `SUMMARY_MODEL` 에 **고정**되어 있다.
화면에서는 바꿀 수 없고, 바꿔야 하면 그 한 줄을 고치고 다시 빌드한다.

* `whisper-1` 을 쓰는 이유 — 구간별 시각(`verbose_json` 의 `segments`)을 주는 모델이라야
  발언을 토막으로 나눌 수 있다. 다른 전사 모델은 전체 텍스트만 줘서 발언자 매칭이 안 된다.
* 녹음파일은 ①에서만 쓰이고, ②에는 **텍스트만** 전달된다.

## 설치

```bash
cd "c:\dev\회의록 자동정리 프로그램\회의록정리v2"
pip install -r requirements.txt
```

| 패키지 | 필수 | 용도 |
|---|---|---|
| `lxml` | ✅ | hwpx(zip + XML) 편집 |
| `pywebview` | 권장 | 네이티브 창. 없으면 기본 브라우저로 열림 |
| `av` | 선택 | 25MB 넘는 녹음파일 분할 (아래 참조) |

전사·요약 모두 HTTP API 라서 `openai` · `requests` 같은 패키지를 쓰지 않는다.
표준 라이브러리 `urllib` 만으로 대용량 스트리밍 업로드까지 처리한다.
덕분에 exe 가 작고, API 오류 본문을 그대로 보여 줄 수 있어 원인 파악이 쉽다.

## API 키

키를 찾는 순서는 이렇다. 위쪽이 이긴다.

| 순서 | 어디에서 | 쓰는 상황 |
|---|---|---|
| 1 | `embedded_key.py` 의 `OPENAI_API_KEY` | **배포용.** exe 에 함께 묶인다 |
| 2 | 환경변수 `OPENAI_API_KEY` | 개발 중 편의 |
| 3 | 프로그램 [설정] 탭에서 입력 | 키를 각자 넣어 쓰는 경우 |

### 키를 내장해서 배포하기

`embedded_key.py` 를 열어 한 줄만 채우고 빌드하면 된다.

```python
OPENAI_API_KEY = "sk-proj-..."
```

내장된 exe 는 [설정] 탭에 키 입력란이 아예 나타나지 않고
"API 키가 프로그램에 내장되어 있습니다" 라고만 표시된다. 받는 사람은 키를 준비할 필요가 없다.

> **주의**
> exe 안의 문자열은 마음먹으면 꺼내 볼 수 있다. 내장용으로는 이 프로그램 전용 키를
> 따로 발급해 **사용량 한도(usage limit)를 걸어 두고**, 유출이 의심되면 바로 폐기한다.
> 그리고 키를 적은 `embedded_key.py` 는 **git 에 커밋하지 않는다.**

### 각자 키를 넣어 쓰는 경우

[설정] 탭에서 입력하며, **Windows DPAPI 로 현재 사용자 계정에 묶어 암호화**해
`%APPDATA%\KISTEP회의록정리\config.json` 에 저장한다. 파일을 복사해 가도 다른 계정·다른
PC 에서는 복호화되지 않는다. 키는 platform.openai.com → API keys 에서 발급한다.

## 25MB 초과 파일

OpenAI Whisper API 는 요청당 25MB 제한이 있다. 1시간 회의 mp3 는 보통 30~60MB 라 그냥은
못 올린다. 프로그램이 16kHz 모노 WAV 로 바꾸면서 10분씩 잘라 여러 번 올리는데,
여기에 변환기가 하나 필요하다.

* `pip install av` — 권장. FFmpeg 라이브러리가 wheel 에 들어 있어 별도 설치가 없고 exe 로도 잘 묶인다.
* 또는 `ffmpeg.exe` 를 `app.py`(배포 시 exe)와 같은 폴더에 두거나 PATH 에 둔다.

25MB 이하 파일은 변환 없이 원본을 그대로 올리므로 **짧은 회의는 추가 설치 없이 바로 동작한다.**
변환기가 없는 상태에서 큰 파일을 고르면 1단계 화면이 미리 경고한다.

## 화면 흐름

| 단계 | 내용 |
|---|---|
| 설정 | API 키(내장이면 표시만) · 작성 부서. 전사/요약 연결 테스트 버튼 있음 |
| 1. 녹음파일 전사 | 파일 선택(드래그앤드롭 가능) → 전사 실행 → 결과 요약 |
| 2. 참석자 · 발언자 | 참석자 표 입력(이름/기관/직위) → AI 매칭 → **전사문에서 직접 수정** |
| 3. 기관별 요약 | 회의 정보 입력 → 요약 생성 → **기관·항목·발언내용 직접 수정** |
| 4. 한글 문서 만들기 | 저장 폴더 선택 → hwpx 생성 |

AI 결과는 전부 화면에서 고칠 수 있고, 고친 내용이 문서에 반영된다.

**[요약 모델 연결 테스트]** 는 키·모델 이름·구조화 출력(JSON 스키마)까지 한 번에 확인한다.
모델을 실제로 한 번 호출하므로 소액의 비용이 든다.

### 발언자 매칭

Whisper 는 화자를 구분해 주지 않는다. 그래서 요약 모델이 자기소개·호칭("○○ 팀장님")·
논의 흐름을 근거로 구간별 발언자를 추정하고, 사람이 2단계 화면에서 고치는 방식이다.
짧은 맞장구("네", "그렇죠")가 많으면 추정이 자주 틀리므로
**"발언자 미상만 보기"로 걸러 고치는 것을 전제로 만들었다.**

### 세션 저장

전사는 돈이 드는 단계라, 4단계에서 문서를 만들 때 `..._세션.json` 도 함께 저장한다.
상단 [세션 불러오기]로 다시 열면 전사를 다시 하지 않고 요약부터 이어서 작업할 수 있다.

## 양식 채우기 방식 (`hwpx_writer.py`)

`template.hwpx` 는 zip + XML 구조(docx 와 비슷)이고, 내용은 `Contents/section0.xml` 에 있다.

**고정 문구는 자리표시자로 보고 문자열 치환한다.** 위치(인덱스)로 찾지 않기 때문에
양식에서 문단이 조금 늘거나 줄어도 계속 동작한다.

| 양식의 자리표시자 | 채워지는 값 |
|---|---|
| `ㅇㅇㅇㅇ 회의록` | 회의 제목 + " 회의록" |
| `’yy.mm.dd.` | 회의 날짜 (`’26. 9. 4.` 형식) |
| `., KISTEP 연구윤리자산보호센터)` | 설정의 작성 부서 |
| `’yy. mm. dd. / “장소”` | 일시·장소 |
| `참석자1 기관 참석자1 직위, …` | `기관 직위 이름, …` |
| `희의록 기록 키워드 2줄` | 안건 |
| `회의결과에 따른 시사점` | 시사점 |
| `향후 조치계획, 환류계획 등` | 환류계획 |
| `   -  (참석자1) 내용` | 회의록 원문 (발언자별로 문단 복제) |

**기관별 요약 표**는 구조를 새로 만든다. 양식은 11행 3열이고,

* row 0 — 머리행 (`기 관` / `항 목` / `발언 내용`)
* row 1~5 — 기관1 블록 (col 0이 `rowSpan=5`로 병합)
* row 6~10 — 기관2 블록

행 높이가 3363으로 균일하고 블록 시작행만 3열·나머지는 2열이라 규칙이 단순하다.
이 세 가지를 원형(prototype)으로 삼아 복제한다.

* `trs[1]` — 첫 블록 시작행 (머리행 바로 아래라 테두리 `borderFillIDRef` 가 다름)
* `trs[2]` — 블록 안쪽 연속행 (2열)
* `trs[6]` — 두 번째 이후 블록 시작행 (3열)

기관 수 × 항목 수만큼 행을 만든 뒤 `rowAddr` / `rowCnt` / `cellSpan@rowSpan` /
`cellSz@height` / 표 전체 `sz@height` 를 다시 계산한다. 셀 안의 줄바꿈은 첫 문단을 본떠
문단을 복제하는 식으로 처리하므로 여러 줄짜리 발언 내용도 들어간다.

표 재구성이 맞게 되는지는 `selftest.py` 가 API 키 없이 검증한다
(기관 3곳 / 항목 3·2·1개 → `rowSpan` 3·2·1, 7행).

## 파일 구성

| 파일 | 역할 |
|---|---|
| `app.py` | 진입점. 127.0.0.1 로컬 HTTP 서버 + pywebview 창, 파이프라인 조율, CLI |
| `ui/index.html` | 화면 전체 (HTML/CSS/JS 한 파일) |
| `embedded_key.py` | **내장 API 키를 적는 곳.** 비어 있으면 환경변수·설정에서 찾는다 |
| `config.py` | 설정 저장·불러오기, 키 우선순위, 모델 고정값(`STT_MODEL`/`SUMMARY_MODEL`) |
| `audio.py` | 녹음파일 → 16kHz 모노 WAV 변환·분할 (PyAV / ffmpeg) |
| `stt.py` | OpenAI Whisper API 호출, 스트리밍 multipart 업로드 |
| `summarizer.py` | OpenAI Chat Completions 호출. 발언자 매칭 + 기관별 요약 (structured outputs) |
| `hwpx_writer.py` | 양식 채우기 |
| `selftest.py` | API 키 없이 하는 자체 점검 |
| `template.hwpx` | KISTEP 표준 회의록 양식 |

## 확인이 필요한 부분

* **요약 모델 이름** — `config.py` 의 `SUMMARY_MODEL = "gpt-5.6-luna"` 가 실제 API 모델 ID 와
  같은지 **처음 쓸 때 [요약 모델 연결 테스트]로 한 번 확인**한다.
  이름이 다르면 "모델을 쓸 수 없습니다(HTTP 404)" 안내가 나오고, 그때 그 한 줄만 고치면 된다.
* **긴 회의의 응답 길이** — 요약은 최대 32,000 토큰까지 받는다. 기관이 아주 많은
  장시간 회의에서 "응답이 최대 길이에 걸려 끊겼습니다" 가 나오면 녹음을 나눠 처리한다.
* **표 높이** — hwpx 의 셀 높이는 계산해서 넣지만, 한글이 파일을 열 때 다시 계산하므로
  내용이 길어도 문제되지 않는다.
