# 관련어 파일 작성 지침

이 폴더의 `*.json`은 고시 검색(03 고시 검색)이 검색어를 넓힐 때 쓰는 **관련어 사전의 원본**이다. 고시 원문을 읽고
손(또는 AI)으로 쓴다. `tools/build_search_dictionary.py`가 이 파일들을 합치고 원문과 대조해
`resources/search_dictionary.json`(관련어 사전, 지문 포함)과 `tools/output/관련어_검수.xlsx`(검수 엑셀)를 만든다.
사전은 실행 중 바뀌지 않는다. 고치려면 이 폴더의 파일을 고치고 도구를 다시 돌린 뒤 다시 빌드한다(spec 4.2).

사전에는 두 가지가 들어 있다.

- **같은 말 묶음(groups)**: 한글·영문·음차·약어·띄어쓰기만 다른 같은 말. 예: `D램`·`DRAM`·`디램`·`D-RAM`.
- **위·아래 관계(relations)**: 묶음 사이의 하위 → 상위 분야. 예: `D램` → `메모리` → `반도체`.

검색은 검색어를 같은 말 → 바로 위·아래(한 단계) → 그 다음 위·아래(두 단계)로 넓힌다(spec 4.3). 관계 하나를 더하면
그 위·아래 두 단계 안의 모든 묶음이 함께 검색되므로, **확실한 관계만** 넣는다.

## 파일 하나의 형식

```json
{
    "scope": "이 파일이 맡은 범위 설명(예: 이중용도 0~3군)",
    "groups": [
        {"id": "dram", "terms": ["D램", "DRAM", "디램", "D-RAM"], "note": "원문 표기는 'D램'(첨단 001·002, 핵심 001·002)"}
    ],
    "relations": [
        {"narrow": "dram", "broad": "memory", "note": "선택"}
    ]
}
```

| 필드 | 필수 | 뜻 |
|---|---|---|
| `scope` | 예 | 이 파일이 맡은 범위 설명(비어 있지 않은 글). 도구는 내용 검사에 쓰지 않는다. |
| `groups[]` | 예(빈 목록 가능) | 같은 말 묶음 목록. |
| `groups[].id` | 예 | 묶음 id. 영문 소문자로 시작하고 영문 소문자·숫자·밑줄만(`[a-z][a-z0-9_]*`). 뜻이 드러나게 짓는다(`dram`, `secondary_battery`). |
| `groups[].terms` | 예 | 같은 말 낱말 목록(1개 이상). 원문 표기를 **맨 앞**에 둔다. |
| `groups[].note` | 아니오 | 원문 근거(어느 항목에 어떤 표기로 나오는지)를 짧게. 검수 엑셀에 보인다. |
| `relations[]` | 아니오(없으면 빈 목록) | 위·아래 관계 목록. |
| `relations[].narrow` | 예 | 아래(하위 분야) 묶음 id. |
| `relations[].broad` | 예 | 위(상위 분야) 묶음 id. |
| `relations[].note` | 아니오 | 관계의 원문 근거. |

다른 필드는 쓰지 않는다(도구가 형식 오류로 멈춘다). 파일은 UTF-8, 4칸 들여쓰기. 도구가 검수를 반영해 파일을 다시
쓸 때는 묶음·관계 하나를 한 줄로 쓴다(`core.json`과 같은 꼴).

## 작성 규칙

1. **원문에 근거한다.** 묶음마다 낱말 **하나 이상**이 고시 원문(실제 검토 항목 507개의 원문 국문·영문·제목·분야)에
   실제로 나와야 한다. 하나도 없으면 도구가 오류로 멈춘다. 원문에 근거 없는 관련 분야를 지어내지 않는다.
2. **원문에 없는 낱말은 원문 낱말의 같은 말일 때만** 넣는다(음차·약어·영문·흔한 다른 표기. 예: 원문 `D램`의 같은 말
   `DRAM`·`디램`, 원문 `무인항공기`의 같은 말 `드론`). 도구는 허용하되 검수 엑셀에 `원문에 없음`으로 표시한다.
   사용자가 검색창에 칠 만한 말만 넣고, 원문에도 없고 아무도 치지 않을 영문 풀이는 넣지 않는다.
3. **위·아래 관계의 중간 단계 낱말도 원문에 있어야 한다.** 예: `D램` → `메모리 반도체` → `반도체`는 안 된다
   ('메모리 반도체'는 원문에 없다). `D램` → `메모리` → `반도체`처럼 원문 낱말로 잇는다.
4. **같은 말과 위·아래를 섞지 않는다.** `OLED`와 `디스플레이`는 같은 말이 아니다(OLED가 아래). 뜻이 더 좁으면 다른
   묶음으로 두고 관계로 잇는다(`AMOLED` → `OLED` → `디스플레이`). 한 묶음이 위 묶음을 여럿 가져도 된다.
5. **한 낱말은 한 묶음에만.** 공백·대소문자만 다른 낱말은 같은 낱말이다(`마이크로 LED` = `마이크로LED`). 서로 다른
   묶음에 같은 낱말이 있으면 오류다(다른 파일끼리도). 한 묶음 안에서 공백·대소문자만 다른 낱말을 함께 적어도 오류다
   (검색이 공백·대소문자를 무시하므로 하나만 두면 된다).
6. **관계에 순환이 없어야 한다.** `a → b`와 `b → a`, `a → b → c → a` 모두 오류. 자기 자신을 가리키는 관계도 오류.
7. **관계의 양쪽 묶음은 어느 파일에든 있어야 한다.** 다른 파일의 묶음을 가리켜도 된다.
8. **같은 id를 여러 파일에 둘 수 있다.** 도구가 낱말을 합집합으로 합친다(공백·대소문자만 다른 낱말은 먼저 나온 표기를
   남기고 알린다). 같은 관계가 여러 파일에 있어도 하나로 합친다. 한 파일 안에서는 같은 id·같은 관계를 두 번 쓰지 않는다.
9. **범위별로 파일을 나눈다.** `core.json`(spec 5장 질의에 필요한 핵심 관계)은 지우지 않는다. 다음 범위 파일을 더한다:
   `advanced_core.json`(국가첨단전략기술·국가핵심기술), `dual_use_0-3.json`, `dual_use_4-9.json`, `military.json`.
   파일 이름 순서대로 합친다.
10. 원문 확인은 `notice_catalogue.clause_index(load_catalogue())`(507개)와 `clause_record(catalogue, clause_id)["text"]`로
    한다. 낱말이 원문에 몇 번 나오는지는 `--check`가 알려 준다.

### 원문에서 낱말을 맞추는 규칙(도구·검수 엑셀의 건수 기준)

- 공백·줄바꿈 무시(`마이크로LED`가 `마이크로 LED`와, `리튬 이차전지`가 `리튬이차전지`와 맞는다), 대소문자 무시.
- 영문·숫자로 시작하는 낱말은 앞 글자가 영문·숫자가 아니어야 맞는다(`OLED`는 `cooled` 안에서 맞지 않는다).
- 영문으로 끝나는 낱말은 복수형 `s`·`es`(y로 끝나면 `ies`)까지 받고 그 뒤가 영문이 아니어야 맞는다
  (`UAV` = `UAVs`, `memory` = `memories`, `memory`는 `memoryless`와 맞지 않는다).
- 한글은 경계를 보지 않는다(`전지`는 `이차전지` 안에서도 맞는다).
- 한 항목의 글 = 원문(국문·영문) + 제목 + 분야. 제목·분야가 원문에 이미 그대로 들어 있으면 한 번만 센다.
- 건수 = 507개 항목 전체에서 맞은 횟수, 항목 수 = 한 번 이상 맞은 항목 수.

## 도구 명령 (프로그램 폴더 `고시판정v1`에서)

```text
python tools/build_search_dictionary.py --check tools/synonyms/<파일>.json
```

그 파일을 검증한다. 관계의 상대 묶음과 낱말 중복은 같은 폴더의 다른 파일을 맥락으로 함께 본다(같은 이름의 파일은
검증 대상이 대신한다). 원문에 없는 낱말 목록·오류를 출력하고 **아무 파일도 쓰지 않는다**. 그 파일이 관련된 오류가
있으면 종료 코드 1, 형식 오류면 2.

```text
python tools/build_search_dictionary.py
```

전체 생성. 폴더의 모든 `*.json`을 이름 순서로 합쳐 `resources/search_dictionary.json`과
`tools/output/관련어_검수.xlsx`를 쓴다. 오류가 있으면 사전은 쓰지 않고 검수 엑셀(오류 시트 포함)만 쓰며 종료 코드 1.
사전을 새로 만들면 지문이 바뀌므로 다시 빌드한다.

```text
python tools/build_search_dictionary.py --apply-review <검수 엑셀> [--reviewed-on YYYY-MM-DD]
```

검수 엑셀의 `검수 결과` 칸을 관련어 파일에 반영하고 다시 생성한다. 반영 내역(지운 낱말·고친 낱말·지운 관계·고친 관계,
낱말이 모두 지워져 없어진 묶음과 그 묶음을 가리키던 관계)을 출력한다. 엑셀의 줄이 관련어 파일에 없거나, 반영한 결과가
검증(원문 근거·중복·순환 등)을 통과하지 못하면 **아무 파일도 고치지 않고** 종료 코드 1.

`--reviewed-on YYYY-MM-DD`: 사전의 `reviewed_on`에 검수 일자를 적는다(전체 생성에도 쓸 수 있다). 주지 않으면 묶음
id·낱말·관계가 이전 사전과 같을 때만 이전 검수 일자를 이어 쓰고, 내용이 바뀌었으면 `null`(검수 전)로 둔다.

그 밖의 옵션: `--synonyms-dir`(관련어 폴더), `--notices-root`(고시 기준본 폴더), `--output`(사전 경로),
`--review-xlsx`(검수 엑셀 경로). 시험은 이 옵션으로 임시 폴더에만 쓴다.

## 검수 엑셀 `tools/output/관련어_검수.xlsx`

| 시트 | 열 |
|---|---|
| 같은 말 묶음 | 묶음 id · 낱말 · 원문 등장 건수 · 등장 항목 수 · 원문 확인(`원문에 있음`/`원문에 없음`) · 묶음 메모 · 출처 파일 · **검수 결과** |
| 위·아래 관계 | 아래 묶음 · 아래 낱말 · 위 묶음 · 위 낱말 · 메모 · 출처 파일 · **검수 결과** |
| 요약 | 생성 일시 · 검수 일자 · 사전 지문 · 고시 기준본·지문 · 항목 수 · 파일 · 묶음 수 · 낱말 수 · 원문에 없는 낱말 수 · 관계 수 · 오류 수 · 검수 방법 |
| 오류 | 오류가 있을 때만. 오류 · 관련 파일 |

`검수 결과` 칸만 채운다.

- 빈칸 = 그대로 둔다.
- `삭제` = 그 낱말(같은 말 묶음 시트) 또는 그 관계(위·아래 관계 시트)를 지운다. 묶음의 낱말이 모두 지워지면 묶음과
  그 묶음을 가리키는 관계도 지운다.
- 고친 값
  - 같은 말 묶음: 바꿀 낱말(예: `디램` 줄에 `디-램`).
  - 위·아래 관계: 위 묶음 id 하나(예: `memory`)를 적으면 위 묶음을 바꾸고, `아래 id → 위 id`(또는 `->`)로 적으면
    관계를 그것으로 바꾼다.

## 사전 파일 `resources/search_dictionary.json` (실행용 모듈이 읽는 형식)

```json
{
    "format": "search_dictionary/1",
    "catalogue_id": "kr-notices-v16-1",
    "catalogue_fingerprint": "<고시 기준본 지문>",
    "generated_at": "2026-11-06T12:00:00+09:00",
    "reviewed_on": null,
    "sources": ["core.json"],
    "groups": [
        {"id": "dram",
         "terms": [{"term": "D램", "count": 4, "clauses": 4}, {"term": "DRAM", "count": 0, "clauses": 0}],
         "note": "…", "sources": ["core.json"]}
    ],
    "relations": [
        {"narrow": "dram", "broad": "memory", "note": "", "sources": ["core.json"]}
    ],
    "fingerprint": "<SHA256>"
}
```

- `groups[].terms[]`: `term` 낱말, `count` 원문 등장 건수, `clauses` 등장 항목 수(위 맞추기 규칙). `count`가 0이면
  원문에 없는 같은 말이다.
- `relations[]`: `narrow`(아래) → `broad`(위).
- `reviewed_on`: 검수 일자(`YYYY-MM-DD`) 또는 `null`(검수 전).
- `fingerprint`: **`fingerprint`를 뺀 나머지 전부**의 canonical SHA256 — 키 정렬·구분자 `(",", ":")`·`ensure_ascii=False`
  JSON을 UTF-8로 인코딩한 SHA256(`notice_catalogue.canonical_hash`와 같은 방식). 지문은 이 파일 안에만 있고 코드 상수로
  두지 않는다.
- 도구 안의 함수(실행용 모듈이 같은 규칙을 쓴다):
  - `dictionary_fingerprint(data)` — 위 지문 계산.
  - `validate_dictionary(data, catalogue=None)` — 필드 구성·id 모양·낱말 유일·건수·원문 근거(묶음마다 `count` > 0인 낱말)
    ·관계 양끝 존재·순환 없음·지문 일치를 검사한다. `catalogue`를 주면 기준본 지문도 대조한다.
    틀리면 `SearchDictionaryError`.
  - `load_dictionary(path, catalogue=None)` — 파일을 읽어(키 중복·NaN 거부) `validate_dictionary`.
  - `normalize_term(term)`·`count_term(term, text)`·`term_pattern(term)` — 위 맞추기 규칙.

## 예시: 범위 파일 하나

```json
{
    "scope": "이중용도 6군(센서·레이저)",
    "groups": [
        {"id": "laser", "terms": ["레이저", "laser"], "note": "core.json에도 있는 묶음 — 낱말이 합쳐진다"},
        {"id": "fiber_laser", "terms": ["광섬유 레이저", "파이버 레이저", "fiber laser"], "note": "6A005 원문 확인 뒤 표기를 맞춘다"}
    ],
    "relations": [
        {"narrow": "fiber_laser", "broad": "laser"}
    ]
}
```

(예시의 `fiber_laser` 낱말은 형식을 보이기 위한 것이며 실제 원문 표기와 다를 수 있다. 실제로 쓸 때는 `--check`로
원문 등장 건수를 확인한다.)
