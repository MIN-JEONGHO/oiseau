# 국가R&D 제재통계 프로그램

NTIS 제재정보 rawdata(xlsx) **하나로 두 가지 통계**를 만듭니다.
각각 엑셀 집계표와 hwpx 표준양식이 채워진 파일이 나옵니다.

| 통계 | 기준연도 | 세는 단위 | 산출물 | 원본 |
|---|---|---|---|---|
| **원인과제 집계** | 총연구기간 | 과제 | 부처 × 7항목 표 1개 | `제재정보분석.workflow` |
| **월별 통계** | 처분연도 | 제재 레코드 | 통계 9종 (제재유형 3 × 분류축 3) | `월별통계 제재통계 자동 분석.xlsx` |

> 두 통계의 **기준연도가 다릅니다.** 원인과제 집계는 과제가 수행된 기간을,
> 월별 통계는 제재가 처분된 연도를 축으로 씁니다. 같은 rawdata에서 나온 숫자라도
> 서로 맞지 않는 것이 정상입니다. 화면의 탭 아래에 기준연도를 항상 적어 두었습니다.

## 설치

```
pip install pandas openpyxl lxml xlsxwriter python-calamine pywebview
```

| 패키지 | 역할 | 없으면 |
|---|---|---|
| pandas, openpyxl, lxml | 필수 | 동작 안 함 |
| xlsxwriter | 엑셀 쓰기 | 동작 안 함 |
| python-calamine | 빠른 엑셀 읽기 | openpyxl로 대체 (10만 행에서 수 배 느려짐) |
| pywebview | 네이티브 창 | 기본 브라우저로 열림 |

가져다 씁니다. 두 통계가 같은 rawdata를 같은 방식으로 읽게 하려는 것입니다.

# GUI 실행

```
python app.py
```

`pywebview`가 있으면 네이티브 창으로, 없으면 기본 브라우저로 같은 화면이 열립니다.
화면은 `127.0.0.1` 임의 포트에서만 제공되고 외부로 열리지 않습니다.

## 화면 구성

```
┌──────────────────────────────────────────────────────────┐
│ ※ 제재통계                     rawdata 제재정보_….xlsx  │
├──────────────────────────────────────────────────────────┤
│  원인과제 집계 ✓      월별 통계 ✓                        │  ← 탭
│  총연구기간 기준      처분연도 기준                       │
├──────────────────────────────────────────────────────────┤
│  입력  ─ rawdata (두 탭이 공유)                          │
│        ▸ 양식 · 참조데이터 바꾸기 (접혀 있음)            │
│  ─────────────────────────────────────────────────       │
│  집계 조건 ▸        [집계 실행] ─── 진행                 │
│  검산 / 결과 표                                          │
├──────────────────────────────────────────────────────────┤
│  [엑셀 저장] [한글 서식 채우기]      저장 위치 …         │
└──────────────────────────────────────────────────────────┘
```

**입력은 탭 밖에 있습니다.** 한 파일로 두 분석을 하기 때문입니다. rawdata를 한 번 넣으면
두 탭 모두에서 쓰고, 각 탭에서 실행한 결과는 서로 지우지 않고 따로 남습니다.
양식 두 개와 참조데이터는 내장되어 있어 평소에는 접어 두었습니다.

**탭 부제에 기준연도를 적었습니다.** 두 통계의 가장 위험한 차이라서 상시 표시합니다.
탭 이름 옆 `✓` / `✕`는 그 통계의 검산 상태입니다.

> 찾아보기는 브라우저 기본 파일 선택 창(`<input type="file">`)을 씁니다.
> 처음에는 네이티브 대화상자를 썼는데, pywebview가 없는 환경에서 tkinter 창을
> 워커 스레드에서 띄우려다 아무것도 안 뜨는 문제가 있었습니다. 지금 방식은
> 네이티브 창·브라우저 양쪽에서 모두 동작합니다.
> 고른 파일은 임시 폴더로 복사되므로 **결과 저장 위치의 기본값은 문서 폴더의 `제재통계`** 입니다.

### 원인과제 집계 탭

**검산** — 집계 직후 네 가지를 서버에서 직접 다시 계산해 대조합니다.

| 검산 항목 | 확인 내용 |
|---|---|
| 연도별 소계 = 연도 전개 건수 합 | 연도 전개 누락 없음 |
| 부처별 합 = 합 계 행 | 부처 배분 누락·중복 없음 |
| ① + ② + ③ = 소계 | 판정 분류 누락 없음 |
| 합 계 열 = 연도별 열의 합 | 합계가 연도별 열과 어긋나지 않음 |

**집계 결과** — 상단에 고정되는 **연도 레일**이 열 머리 역할을 하면서 연도별 소계와
가장 많았던 연도를 함께 보여줍니다. 부처가 많아 아래로 스크롤해도 열 위치를 잃지 않습니다.
부처명·항목 열도 좌측에 고정됩니다. 부처 이름으로 찾기, 부처명순 ↔ 소계 많은순 정렬을 지원합니다.

참조데이터를 넣지 않으면 국가R&D연구비·과제수·비율 행은 표에서 숨겨지고,
안내에서 바로 **입력 양식 만들기**를 누를 수 있습니다.

### 월별 통계 탭

**통계판** — 통계를 격자로 놓습니다. 행은 제재유형, 열은 분류축이고, 축을 더 고르면
열이 늘어납니다.

```
              제재사유별   기관유형별   부처별
  참여제한       1 ✓         2 ✓        3 ✓      ← 건수
  환수금         4 ✓         5 ✓        6 ✓      ← 부과액(억원)
  제재부가금     7 ✓         8 ✓        9 ✓
```

각 칸에 통계 번호·대표값(합계)·검산 결과가 있습니다. 칸을 누르면 그 표가 아래에 열립니다.
표 하나만 보면서 나머지가 맞는지 모르는 상태를 없애려는 구조입니다.
원본 워크북의 `리스트` 시트가 실제로 이 격자로 조직되어 있습니다.

**출력** — 하단 바는 **현재 탭의 통계**를 저장합니다. 파일명 접두어가 각각
`원인과제집계_` / `월별통계_` 로 달라 섞이지 않습니다.

### 그림 (두 탭 공통)

검산과 표 사이에 그림을 둡니다. 네 가지를 오갈 수 있습니다.

| 그림 | 답하는 질문 | 형식 |
|---|---|---|
| 연도별 추이 | 늘고 있나 줄고 있나 | 선. 계열이 5개 이상이면 **소형 다중표**로 폅니다 |
| 순위 | 어디가 많나 | 가로 막대(내림차순) |
| 구성비 | 무엇으로 이뤄졌나 | 누적 막대 |
| 분류×연도 | 언제 어디서 터졌나 | 히트맵 |

`지표`·`상위 N`을 바꿔 축을 갈아 끼울 수 있고, **그림 저장**으로 PNG를 받습니다.
표에 쓰는 수를 그대로 그리며 다시 계산하지 않습니다.

**저장한 PNG는 화면과 다릅니다 — 보고서에 그대로 실으라고 만든 것입니다.**
화면 그림을 캡처하는 것이 아니라 저장용으로 다시 그리며, 화면에는 없는 세 가지가 들어갑니다.

| 들어가는 것 | 왜 |
|---|---|
| **x·y 축 이름** | 무엇을 무엇으로 세었는지. 원인과제 집계는 `연도 (총연구기간 기준)` × `제재처분 과제 수 (건)`, 월별 통계는 `처분연도` × `참여제한 건수 (건)` 처럼 고른 지표와 단위를 그대로 적습니다. **두 통계의 기준연도가 다르다는 사실이 그림 안에 남습니다.** |
| **범례** | 화면 범례는 SVG 밖 HTML 이라 지금까지 PNG 에 담기지 않았습니다. 색만 예닐곱 개 찍힌 그림이 보고서에 실리면 어느 색이 무엇인지 알 길이 없었습니다. |
| **각주** | 화면 아래 설명(`3. 부처별 참여제한 · 건수 · 연도 추이 · 상위 8개만 …`)을 그림 안에 굽습니다. 그림 하나만 떨어져 나가도 무엇을 센 것인지 남습니다. |

순위 그림에는 값 눈금이, 소형 다중표에는 칸마다 양 끝 연도와 `칸마다 같은 눈금 · 최대 N`이
저장본에만 추가로 붙습니다. 화면에서는 머리글의 지표 선택과 각주가 같은 말을 하고 있어
축 이름을 또 두면 그림 자리만 좁아지기 때문입니다.
화면에도 축 이름을 넣고 싶으면 `ui/index.html` 의 `AXIS_ON_SCREEN` 을 `true` 로 바꾸면 됩니다.

해상도는 **가로 2400px 이상**입니다(A4 본문 폭 300dpi 기준). 그림 종류에 따라
2400~2530 × 770~1030px 로 나옵니다.

> 이전에는 저장본이 화면 캡처와 다를 바 없이 흐렸습니다. SVG 를 `<img>` 로 태울 때
> `width`·`height` 를 적지 않아 크로미움이 제 기본 크기(300px)로 한 번 래스터한 뒤
> 캔버스에서 늘렸기 때문입니다. 최종 화소 수를 SVG 에 직접 적어 그 크기로 굽게 고쳤습니다.

**그림 코드를 고칠 때 주의 — `data:image/svg+xml` 은 HTML 이 아니라 XML 로 읽힙니다.**
XML 은 속성값 안의 `<` 를 문법 오류로 보고, 하나만 있어도 그림이 통째로 안 그려집니다
(`img.onerror` → `그림을 PNG로 바꾸지 못했습니다`). 화면용 툴팁 `data-tip` 에는 `<u>`·`<b>` 가
날것으로 들어 있어 이 조건에 걸립니다. 예전 코드는 화면 SVG 를 `outerHTML` 로 긁어왔고
그 과정에서 브라우저가 `<` 를 `&lt;` 로 바꿔 줘서 우연히 통과했지만, 지금은 문자열로 직접
짜므로 그 손질이 없습니다. `vizPng()` 가 굽기 직전에 `data-tip`·`data-x`·히트존·십자선을
걷어내는 것이 이 때문입니다. **새 속성에 마크업을 담게 되면 같은 자리에서 함께 걷어내야 합니다.**

## 디자인 노트

- 3단 색 램프는 **제재 수단**을 뜻합니다 — 참여제한 자적 `#7D334A`, 제재부가금 구리 `#A85F40`, 환수금 올리브 금 `#999530`. 두 탭에서 같은 색이 같은 것을 가리키므로 탭을 옮겨도 읽는 법이 바뀌지 않습니다. 원인과제 집계의 ①은 참여제한+제재부가금이라 좌측 괘선을 자적/구리로 위아래 반씩 나눴습니다.
- 이 세 값은 눈으로 고른 것이 아니라 **검증기를 돌려 잡았습니다**. 원래 쓰던 장부색(자적 `#6B2C39`, 구리 `#9E6B3D`, 황동 `#C6A96B`)은 띠와 글자로는 좋지만 차트 채움색으로는 세 항목이 어긋났습니다 — 자적이 명도 밴드 아래, 셋 다 채도 바닥 미만(회색으로 읽힘), 황동은 종이 대비 2.17:1. 게다가 구리와 황동은 색상각이 24°밖에 안 떨어져 정상 시력으로도 구별이 어려웠습니다(ΔE 9.5, 기준 15). 원색에서 최소로 벗어나면서 전 항목을 통과하는 값으로 다시 잡았고, 황동만 크게 움직였습니다.
- 히트맵은 **단일 색상 램프**(먹빛 남청 5단)를 씁니다. 크기 비교는 정체성이 아니므로 색을 여러 개 쓰지 않습니다. 같은 이유로 순위 막대도 단일 색입니다.
- 분류가 많아도 **색을 새로 만들지 않습니다.** 상위 N + `그 외`로 접거나 소형 다중표로 폅니다.
- 색면은 쓰지 않고 표 좌측 3px 괘선과 원문자에만 씁니다.
- 한글은 고딕(맑은 고딕), 숫자는 모노(Cascadia Mono / Consolas). 숫자 열이 `tabular-nums`로 정렬됩니다. 둘 다 Windows 기본 내장이라 오프라인 exe에서도 그대로 나옵니다.
- 웹폰트·CDN·브라우저 저장소를 쓰지 않습니다. 사내망·오프라인 환경에서 그대로 동작합니다.
- `※`, `*`, `**`, `(단위 : 건, 억원, %)` 등 양식의 각주 어휘를 화면에서도 그대로 씁니다.

## exe 빌드

```bat
build_exe.bat
```

`dist\제재통계.exe` 하나가 나옵니다. `ui/index.html`과 양식 두 개, 참조데이터가
모두 exe 안에 들어갑니다.

배포 대상 PC에 **Microsoft Edge WebView2 런타임**이 필요합니다. Windows 10 21H2 이상과
Windows 11에는 기본 포함되어 있고, 없으면 기본 브라우저로 열립니다.

빌드가 실패하거나 실행 시 창이 뜨지 않으면 `app.spec`의 `console=False`를 `True`로 바꿔
다시 빌드하면 콘솔에서 원인을 볼 수 있습니다.

# 통계 1 · 원인과제 집계

과제 단위 / 총연구기간 기준. `제재정보분석.workflow` 의 노드 로직을 구현한 것입니다.

## CLI 실행

```bat
:: 1) 가장 기본 (엑셀만) — 인자 없이 실행하면 파일 선택창이 열립니다
python run_report.py
python run_report.py 제재정보_rawdata_20260301.xlsx

:: 2) hwpx 표준양식까지 채우기
python run_report.py 제재정보_rawdata.xlsx ^
    --template "(표준양식) 부처별 예산 과제수 제재처분 집계(유형별)(원인과제수행연도기준).hwpx" ^
    --ref 조사분석_참조데이터.xlsx ^
    --outdir 결과

:: 3) 참조데이터 입력 양식 먼저 만들기 (부처 목록/연도가 자동으로 들어감)
python run_report.py 제재정보_rawdata.xlsx --make-ref-template

:: 4) 연도 축을 양식대로 2017~2025 로 고정
python run_report.py 제재정보_rawdata.xlsx --year-start 2017 --year-end 2025
```

`--template` 을 생략하면 rawdata 폴더와 현재 폴더에서 `*.hwpx` 를 자동으로 찾습니다.

## 처리 로직

### 0) 읽기 — 헤더 행 자동 탐지
실제 NTIS 제재정보 rawdata는 **1행이 그룹 머리(문제과제정보 / 제재정보 / 등록정보), 2행이 실제 컬럼명**입니다.
프로그램은 파일 앞 15행만 미리 훑어 알려진 컬럼명이 가장 많이 나오는 행을 헤더로 잡습니다.
94개 열 중 필요한 14개만 읽어 메모리와 시간을 줄입니다.

### 1) 데이터 변환
- 필요한 컬럼만 선택: 과제수행연도, **과제번호**, 과제명, 총연구기간시작/종료일, 처분연도, 제재유형구분, 소관부처, 부처명, 제재ID, 제재대상, 사업명
  (컬럼명이 조금 달라도 `sanction_pipeline.REQUIRED_COLUMNS` / `OPTIONAL_COLUMNS` 의 별칭으로 자동 인식)
- `과제수행연도 >= 2017` 필터 (`--min-task-year`)
- 과제명·과제번호 공백 제거
- 날짜 컬럼 → 4자리 연도 추출 (문자열/날짜/엑셀 시리얼 모두 처리)

### 2) 데이터 전처리
- **부처 기준 컬럼**: 기본은 `소관부처`(현재 명칭으로 이미 정리된 값). 비어 있으면 `부처명`으로 보완하고,
  둘 다 비면 `(부처 미지정)`으로 분류합니다. `--ministry-column 부처명` 으로 바꿀 수 있습니다.
- 구칭 표기 통일. 표는 두 그룹으로 나눠 뒀습니다.

  | 상수 | 내용 |
  |---|---|
  | `MINISTRY_RENAME_CONFIRMED` | 확인된 매핑 — 미래창조과학부→과학기술정보통신부, 환경부→기후에너지환경부, 산업통상자원부→산업통상부 |
  | `MINISTRY_RENAME_INFERRED` | 정부조직 개편 이력에서 유추한 매핑 — 검토 후 사용 |

  표에 적는 것은 **실제 개편 한 단계씩**이면 됩니다. `지식경제부→산업통상자원부` 와
  `산업통상자원부→산업통상부` 가 함께 있으면 `resolve_rename_chains()` 가 연쇄를 풀어
  지식경제부까지 최종 이름(산업통상부)으로 보냅니다. pandas 의 `replace` 는 한 번만
  치환하므로 이 처리가 없으면 같은 부처가 중간 이름에 남아 **두 줄로 갈라집니다**.

  같은 치환은 참조데이터의 부처명에도 적용됩니다. 그러지 않으면 rawdata 쪽만 새 이름이 되어
  연구비·과제수·비율 조회가 빗나가 공란이 됩니다. 치환으로 두 부처가 한 이름이 되면 값은 합산합니다.

  부처가 둘로 쪼개진 경우는 R&D 소관을 이어받은 쪽으로 보냈습니다. 이 세 건은 데이터에 따라 틀릴 수 있습니다.

  | 구칭 | 이 프로그램의 선택 | 다른 후보 |
  |---|---|---|
  | 교육과학기술부 | 과학기술정보통신부 | 교육부 |
  | 국토해양부 | 국토교통부 | 해양수산부 |
  | 농림수산식품부 | 농림축산식품부 | 해양수산부 |

  실행하면 **실제로 적용된 치환만** 건수와 함께 콘솔과 화면 각주에 표시됩니다.
  예: `부처명 치환: 환경부 → 기후에너지환경부 (3건)`. 아무것도 안 뜨면 치환이 없었다는 뜻입니다.

  `소관부처` 열은 NTIS가 이미 현재 명칭으로 정리해 주므로, 이 표는 대부분 `--ministry-column 부처명` 을
  쓸 때만 작동합니다.
- 과제 그룹 내 연구기간 시작/종료일 결측 보완
- 시작일이 끝까지 비어 있는 행 제거 / 종료일 결측은 시작일로 대체 / 종료<시작 이상치는 시작연도로 맞춤

### 3) 기간 분석 · 제재유형 판정
**과제명** 기준으로 묶어 그 과제의 제재유형 집합을 만들고 판정합니다.
`--id-strategy` / 화면의 「과제 동일성 판정 키」로 바꿀 수 있습니다.

| 값 | 묶는 방식 |
|---|---|
| `과제명` (기본) | 과제명이 같으면 한 과제 |
| `번호우선` | 과제번호가 있으면 그것, 없으면 과제명 |
| `번호` | 과제번호 (없으면 과제명) |
| `번호+명` | 과제번호와 과제명을 함께 (양식 각주 `**`의 "과제번호 및 과제명 기준"의 직역) |

> 기본을 과제명으로 두는 이유는 같은 과제가 세부과제번호마다 다른 번호로 들어와
> 번호로 묶으면 한 과제가 여러 건으로 갈라지기 때문입니다.
> 다만 과제명 칸에 회사명이 들어간 행(예: "에코마이스터")이 섞여 있어 서로 다른
> 과제가 한 줄로 합쳐질 수 있습니다. 대조할 기준에 따라 위 값으로 바꿔 쓰십시오.

#### 과제유형 기준 (`--task-type`)

rawdata 에는 한 과제에 대해 주관 기관의 행과 공동·위탁 기관의 행이 함께 들어옵니다.
양식 각주가 준용하는 NTIS 조사·분석은 총괄주관과제 기준이므로, 공동·위탁까지 원인과제로
세면 부처별 수치가 전반적으로 커집니다. 어느 기준이 맞는지는 대조할 원본 통계에 따라
다르므로 옵션으로 열어 두었고, **기본값은 `전체`** 입니다(기존 산출물이 바뀌지 않도록).

| 값 | 세는 범위 | 유형 미상 행 |
|---|---|---|
| `전체` (기본) | 공동·위탁 포함 모든 과제유형 | 포함 |
| `공동위탁제외` | `공동`·`위탁` 을 뺀 나머지 | 포함 |
| `세부만` | `세부(주관/협동)` 만 | 제외 |

필터는 **그룹 결측 보완 뒤, 과제 그룹핑 앞**에서 걸립니다. 보완보다 먼저 걸면 공동·위탁
행이 갖고 있던 연구기간까지 사라져 같은 과제의 주관 행이 시작일 결측으로 탈락합니다.

기준을 `전체` 가 아닌 값으로 지정했는데 원자료에 `과제유형` 열이 없으면 조용히 넘어가지
않고 멈춥니다. 필터가 걸린 줄 알고 잘못된 수치를 보고하는 쪽이 더 위험하기 때문입니다.

rawdata_20260101 기준 실측(연도축 2017~2025, 소계):
`전체` 2,980 · `공동위탁제외` 2,829 · `세부만` 2,826

| 판정 | 조건 |
|---|---|
| ① 참여제한 및 제재부가금 | 참여제한 **과** 제재부가금 모두 있음 |
| ② 참여제한만 처분 | 참여제한만 |
| ③ 제재부가금만 처분 | 제재부가금만 |
| 제외 | 환수금만 (양식 각주대로 환수금은 집계 제외) |

이후 총연구기간 시작~종료 연도를 연도 축에 전개합니다.

### 4) 집계
- **연도별 열**: 해당 연도에 수행 중이던 과제를 1건으로 셈 (계속과제는 각 연도에 중복 계상)
- **합계 열**: 연도별 열의 **단순 합**. 계속과제는 수행한 연도 수만큼 반영됩니다.
  예전에는 과제 중복을 제거해 계속과제를 1건으로 셌고 양식 각주 `*` 가 그 사실을
  설명했는데, 그 방식과 각주를 함께 걷어냈습니다(`template.hwpx` 의 `합계*` → `합계`).
- **소계** = ① + ② + ③
- **제재처분 비율** = 소계 ÷ 국가R&D과제수 × 100 (참조데이터가 있을 때만)

### 연도 축
기본은 자동입니다. `max(2017, 최소 시작연도)` ~ `최대 종료연도`이며, **종료연도는 올해로 제한**합니다.
연구기간이 2028년까지인 과제가 있어도 아직 수행되지 않은 연도이므로 열을 만들지 않습니다.
- `--year-start` / `--year-end` 로 고정 (양식에 맞추려면 `--year-end 2025`)
- `--year-end-cap` 으로 자동 결정 시 상한만 지정

## 참조데이터 (국가R&D연구비 / 국가R&D과제수)

이 두 항목은 NTIS 조사·분석 결과이므로 제재정보 rawdata 로는 계산할 수 없습니다.
`--make-ref-template` 로 양식을 만들어 값을 채운 뒤 `--ref` 로 넘기면 해당 행과 비율이 채워집니다.
넘기지 않으면 그 행은 공란으로 남습니다(한글에서 직접 입력).

**wide 형식** (`--make-ref-template` 이 만드는 형식)

| 부처 | 항목 | 2017 | … | 2025 | 합계 |
|---|---|---|---|---|---|
| 과학기술정보통신부 | 국가R&D연구비 | 12345.6 | | | |
| 과학기술정보통신부 | 국가R&D과제수 | 8901 | | | |

**long 형식**도 인식합니다.

| 부처 | 연도 | 국가R&D연구비 | 국가R&D과제수 |
|---|---|---|---|

`합계` 행이 없으면 부처 값을 더해서 자동 생성합니다.

참조데이터는 조사·분석 결과가 나오는 시점이 늦어 최근 연도가 비어 있을 수 있습니다.
빈 칸은 `0`이 아니라 **공란**으로 나가고, 그 연도의 제재처분 비율도 계산하지 않습니다.

rawdata에는 있는데 참조데이터에는 없는 부처가 있으면 실행 중에 짚어 줍니다.
예: `'신설과학부' 부처는 참조데이터에 없어 국가R&D연구비·과제수·비율이 공란입니다`.
이 경고가 없다면 표에서 어떤 부처만 비어 있는 것이 참조데이터 누락인지 프로그램 오류인지
구분할 수 없습니다. 참조데이터 갱신이 늦으면 신설·개편 부처에서 실제로 발생합니다.

`다부처`는 rawdata의 `소관부처`에 나올 수 있는 값이라 참조데이터에도 같은 이름으로 들어 있고,
치환 표에 없으므로 그대로 매칭됩니다.

## 출력물

### 엑셀 (`원인과제집계_YYYYMMDD_HHMM.xlsx`)

| 시트 | 내용 |
|---|---|
| `집계표(양식)` | hwpx 양식과 동일한 레이아웃 (부처 × 7항목 × 연도) |
| `부처별_판정별` | 부처 × 판정 × 연도 피벗 (workflow 피벗 노드 재현) |
| `과제단위_판정` | 과제 1건 = 1행. 판정 근거 추적용 (과제번호, 제재유형, 제재ID, 집계반영연도). 자동 필터 걸려 있음 |
| `연도전개` | 과제 × 연도 long 포맷. **항상 포함** |

상세 시트(`연도전개` / 월별 통계의 `전처리`)는 선택지 없이 항상 넣습니다. 판정 근거를 되짚을 때
필요하고, 빠뜨리면 나중에 다시 만들어야 하기 때문입니다. 과제 3만 건 규모에서 `연도전개`는
16만 행이 되어 엑셀 저장이 4초 → 12초로 늘어납니다. CLI 에서는 `--no-long` 으로 뺄 수 있습니다.

### hwpx (`원인과제집계_YYYYMMDD_HHMM.hwpx`)
표준양식의 7행 블록을 부처 수만큼 복제하고 값을 넣습니다.
연도 열 개수가 데이터와 다르면 열을 자동으로 늘리거나 줄이고 너비를 재분배합니다.
표 서식·각주·글꼴은 원본 양식 그대로 유지됩니다.

# 통계 2 · 월별 통계

제재 레코드 단위 / **처분연도** 기준. `월별통계 제재통계 자동 분석.xlsx` 의 수식을 구현한 것입니다.
과제 단위로 묶지 않고 제재 레코드를 그대로 셉니다.

## 처리 로직

### 1) 전처리 — 원본 `원자료(전처리)` 시트의 11열

| 열 | 규칙 |
|---|---|
| 처분연도 | 숫자로 변환, 0은 결측. 없으면 `처분일`에서 연도 추출 |
| 제재유형구분 | 그대로 |
| 연구수행주체(정제) | 아래 **연구수행주체 정제** 참고 |
| 제재사유(기본법) / (혁신법) | 그대로 |
| 미납금액 / 대상금액(원) / 납부금액(원) | 아래 **금액 정제** 참고. 0은 결측 |
| 소관부처 | 원인과제 집계와 같은 규칙(비면 `부처명` 보완 + 구칭 치환) |
| 제재ID | 그대로 |
| 건수 | 제재ID가 있으면 1 |

#### 연구수행주체 정제

두 열의 **출처가 다릅니다.**

| 열 | 출처 |
|---|---|
| `연구수행주체` (L열) | 문제과제정보 — 조사·분석 데이터 |
| `연구수행주체(정제)` (AG열) | 제재정보 — 전문기관이 입력 |

원본 워크북의 `=IF(제재정보="", 문제과제, 제재정보)` 규칙을 씁니다.

1. `연구수행주체(정제)`가 비면 `연구수행주체`(L열) 값을 가져옵니다
2. 둘 다 있고 **다르면 `연구수행주체(정제)`(AG열)** 를 씁니다

실행하면 어느 쪽을 몇 건 썼는지 알립니다. 샘플에서는 `정제 공란 → L열 보완 29건`,
`두 열이 달라 정제 채택 5건 (대학→중소기업, 출연연구소→중소기업)` 이 나옵니다.
두 열이 모두 빈 행은 **기관유형별 표에서만 빠지므로** 표 간 검산이 어긋나는 원인이 됩니다.
그 건수도 함께 알립니다.

#### 금액 정제

NTIS 내보내기에 따라 금액 3열이 **텍스트로 저장되어** 오는 경우가 있습니다. 원본 워크북에서
열을 선택해 `Alt+A → E → F`(텍스트 나누기)로 속성을 바꿔야 했던 것이 이 문제입니다.
프로그램은 다음을 직접 걷어내고 숫자로 바꿉니다.

| 들어오는 값 | 결과 |
|---|---|
| `18,873,603` | 18873603 — 쉼표 |
| `1 234 567`, `12　345` | 1234567 / 12345 — 공백·전각공백 |
| `295000000원`, `₩12,000` | 295000000 / 12000 — 통화 표기 |
| `１２３４` | 1234 — 전각 숫자 |
| `(1,000)` | −1000 — 괄호 음수 |
| `해당없음` | **변환 실패 → 건수를 알림** |

`pandas.to_numeric` 만 쓰면 `18,873,603` 이 그대로 `NaN` 이 되어 **그 금액이 조용히 0으로
집계됩니다.** 합계만 보면 알아챌 수 없으므로, 변환하지 못한 값은 열별 건수와 실제 값 예시를
화면 각주·콘솔·엑셀 `검산` 시트에 남깁니다.

```
! '대상금액(원)' 을 숫자로 바꾸지 못한 값 3건 (집계에서 0 처리): '해당없음'
! 금액이 텍스트로 저장된 파일일 수 있습니다. 합계가 실제보다 작게 나오니 원자료를 확인해 주세요
```

### 2) 통계 — 제재유형 × 분류축

기본은 **9종**(제재유형 3 × 표준 분류축 3)입니다.

| 번호 | 제재유형 | 분류축 | 값 |
|---|---|---|---|
| 1 · 2 · 3 | 참여제한 | 제재사유 · 기관유형 · 부처 | 건수 |
| 4 · 5 · 6 | 환수금 | 같음 | 부과액 · 납부액 · 미납액 · 미납률 · 건수 |
| 7 · 8 · 9 | 제재부가금 | 같음 | 같음 |

#### 분류축 늘리기

「집계 조건」에서 축을 더 고르면 표가 그만큼 늘어납니다(6축이면 18종).
**표준 3축이 먼저 1~9번을 차지하고 추가 축이 10번부터** 붙으므로, 축을 더 골라도
1~9번의 뜻은 변하지 않습니다.

| 축 | 표준 목록 | 값이 빈 행 |
|---|---|---|
| 제재사유 | 9분류 | **이 표에서 빠짐** (검산이 알려 줍니다) |
| 기관유형 | 7분류 | `기타` |
| 부처 | 23개 | `(부처 미지정)` |
| 제재대상 | 기관 · 인물 | `(대상 미상)` |
| 과제유형 | 세부(주관/협동) · 공동 · 위탁 · 기타 | `(유형 미상)` |
| 사업명 | 건수 상위 N개 + `기타` | `(사업명 미상)` |

값이 빈 행을 대체 라벨로 남기는 이유는 검산 때문입니다. 같은 제재유형의 여러 표는
모집단이 같아 건수 합계가 같아야 하는데, 축 값이 비어 행이 빠지면 그 표만 합계가
갈라집니다. **제재사유만 예외**로 두는데, 9분류에 없는 행이 빠지는 것은 결함이 아니라
드러내야 할 사실이기 때문입니다.

- **사업명**은 값이 2천 종이 넘어 상위 N개(기본 20)만 행으로 두고 나머지를 `기타`로 묶습니다.
  순위는 제재유형별이 아니라 **모집단 전체에서 한 번만** 매깁니다 — 제재유형마다 다른
  목록을 쓰면 표를 나란히 놓고 읽을 수 없습니다. 동수는 이름순으로 끊어 실행할 때마다
  목록이 바뀌지 않게 합니다. 꼬리가 길어 `기타` 비중이 절반을 넘습니다(N=20 기준 약 54%).
- **기관유형 별칭 치환**을 끄면 `출연연구소`·`정부부처`가 원자료 표기 그대로 갈라집니다.
- 고른 축의 원천 열이 통째로 비어 있으면 **멈춥니다**. 그냥 두면 한 줄짜리 표가 나오는데
  그 합계는 모집단과 같아서 어떤 검산도 잡지 못합니다.

> **한글 양식은 표 9개로 고정**입니다. 축을 더 골라도 한글에는 표준 9표만 담기고 각주로
> 알립니다. 표준 3축 중 하나라도 빼면 한글 저장이 막힙니다(엑셀에는 전부 들어갑니다).

- **부과액** = 대상금액(원) ÷ 1억 (억원)
- **납부액** = 납부금액(원) ÷ 1억
- **미납액** = 부과액 − 납부액. **0원 이하는 `완납`으로 간주해 0으로 둡니다**(양식 각주).
  납부액이 부과액보다 큰 칸이 있으면 건수를 알립니다.
- **미납률** = 미납액 ÷ 부과액 × 100. 부과액이 0이면 산출하지 않습니다.

원본의 `미납금액` 열은 쓰지 않습니다. 원본 수식도 부과액−납부액으로 계산합니다.

#### `-` 와 `0` 의 구별

양식 각주가 규칙을 못박아 두었습니다.

> ※ 미납률(%) = 미납액/부과액. 따라서 **미납률 0%가 전액 납부를 의미**함
> (당해 연도 미발생한 경우, "-"으로 표기)

그래서 `-` 는 **그 연도에 부과가 없었다**는 뜻만 씁니다. 0을 `-`로 찍으면
전액 납부한 것과 부과가 없던 것이 구별되지 않습니다.

| 상황 | 부과액 | 납부액 | 미납액 | 미납률 |
|---|---|---|---|---|
| 부과 없음 (당해 연도 미발생) | `-` | `-` | `-` | `-` |
| 전액 납부 | `10.0` | `10.0` | `0.0` | `0.0%` |
| 전혀 납부 안 함 | `10.0` | `0.0` | `10.0` | `100.0%` |
| 초과 납부 → 완납 처리 | `10.0` | `12.0` | `0.0` | `0.0%` |

건수는 부과액과 별개로 0이면 `-`입니다(금액 정보만 없는 제재 레코드가 있을 수 있음).
hwpx·엑셀·화면 표가 모두 같은 규칙을 씁니다.

|---|---|---|
| 연구결과 불량 | 01 | 12 |
| 연구개발결과 누설‧유출 | 02 | — |
| 연구개발과제 수행포기 | 03 | 27 |

### 4) 분류 목록

| 분류축 | 표준 목록 | 상수 | 0인 행 | 목록 밖 값 |
|---|---|---|---|---|
| 제재사유 | 9개 | `REASON_LABELS` | 남김 | 집계 제외 + 경고 |
| 기관유형 | 대학 · 대기업 · 중견기업 · 중소기업 · 출연연 · 국공립연구소 · 기타 | `ORG_LABELS` | 남김 | **`기타`로 편입** |
| 부처 | 23개 | `MINISTRY_LABELS` | **뺌** | 별도 행 추가 + 경고 |

**기관유형은 표준 7개 밖으로 나가지 않습니다.** 양식의 기관유형이 7개로 고정이고,
목록 밖 값을 별도 행으로 남기면 기관유형별 표만 합계가 갈라지기 때문입니다.

| 들어오는 값 | 처리 |
|---|---|
| `정부부처` | → `국공립연구소` (`ORG_ALIAS`) |
| `출연연구소`, `정부출연연구소`, `출연(연)` | → `출연연` |
| `대학교`, `산학협력단` | → `대학` |
| `무분류`, `병원` 등 목록 밖 값 | → `기타` |
| 두 열 모두 공란 | → `기타` |

목록 밖 값과 공란이 `기타`로 들어간 건수는 **값별로 항상 알립니다.** 정보가 없는 건을
`기타`로 간주하는 것이므로 얼마나 그렇게 됐는지는 보여야 합니다.

```
! 표준 목록에 없는 기관유형 6건을 '기타'로 편입: 무분류 3건, 병원 3건
! 연구수행주체가 두 열 모두 빈 행 4건도 '기타'로 편입
```

**부처는 전 연도가 0인 행을 뺍니다.** 23개 중 대부분이 0이어서 표가 불필요하게 길어집니다.
제재사유·기관유형은 목록이 짧아 0이어도 남깁니다(양식과 대조하기 쉽도록).
`MonthlyConfig.drop_empty_axes` 로 조정합니다.

**표준 목록에도 치환 규칙을 적용합니다.** `MINISTRY_LABELS` 에는 구칭이 섞여 있어서,
이 처리를 빼면 rawdata 쪽만 새 이름(`산업통상부`)이 되고 표준 목록의 구칭 행(`산업통상자원부`)은
0으로 남은 채 새 이름이 '미등록 값'으로 맨 아래 따로 붙습니다 — **같은 부처가 두 줄로 갈라집니다.**
참조데이터에서 겪은 것과 같은 종류의 실수입니다. 치환으로 두 부처가 한 이름이 되면 순서를 지키며 합칩니다.

**표준 목록에 없는 값**은 맨 아래에 실제 이름으로 행을 추가하고 화면·콘솔에 알립니다.
엑셀에서는 붉은 기울임으로 표시합니다. 원본 워크북의 SUMIFS는 정확히 일치하는 값만 세기 때문에
목록 밖 값이 조용히 사라졌는데, 그러면 합계가 맞지 않는 것을 알아채기 어렵습니다.

기관유형에는 별칭 표(`ORG_ALIAS`)가 있습니다. 실제 데이터의 `출연연구소`는 표준 목록의 `출연연`과
같은 것이라 치환하고, 적용되면 `기관유형 치환: 출연연구소 → 출연연 (1건)` 처럼 알립니다.

### 5) 연도 축

`처분연도` 기준으로 **2017 ~ 올해**가 기본입니다. 범위 밖 처분은 집계에서 빠지고 건수를 알립니다.
양식대로 뽑으려면 종료연도를 2025로 지정하세요.

## 출력물

### 엑셀 (`월별통계_YYYYMMDD_HHMM.xlsx`)

| 시트 | 내용 |
|---|---|
| `1` ~ `9` | 통계 9종. 분류 × 항목 × 연도. 부과가 없던 칸만 공란 |
| `검산` | 표 간 검산 + 표 안쪽 검산 + **전처리 내역** + 연도축 · 제외 건수 |
| `전처리` | 11열 전처리 결과. 자동 필터 걸려 있음. **항상 포함** |

`검산` 시트의 전처리 내역에는 연구수행주체를 어느 열에서 가져왔는지(정제 사용 / L열 보완 /
두 열 불일치 / 둘 다 공란)와 금액 변환 실패 건수가 들어갑니다.

### hwpx (`월별통계_YYYYMMDD_HHMM.hwpx`)

양식의 표 9개를 통계 1~9 순서로 채웁니다. 각 표에서

1. 연도 열 개수를 데이터에 맞춰 늘리거나 줄이고 너비를 재분배
2. 분류 블록(참여제한 1행 / 금액 5행)을 표준 목록 + 추가 분류 + 합 계 만큼 복제
3. 값 주입 후 `rowAddr` / `colAddr` / `rowCnt` / `colCnt` 재계산

### 각주의 기준일

각 표 아래 각주에 자리표시자가 있습니다.

```
※ 기준연도는 처분연도 기준, NTIS 제재정보에 전문기관이 현재(’yy.mm.dd일까지 입력) 기준으로 …
```

`’yy.mm.dd` 9곳을 **rawdata 파일명의 연월일**로 바꿉니다.

| 파일명 | 기준일 |
|---|---|
| `제재정보_rawdata_20260101_샘플.xlsx` | `’26.01.01` |
| `제재정보_rawdata_20260301 (1).xlsx` | `’26.03.01` |
| `제재정보_2026-01-31.xlsx` | `’26.01.31` |
| `제재정보_rawdata.xlsx` | 못 찾음 → 자리표시자 유지 + 경고 |

`YYYYMMDD` / `YYYY-MM-DD` / `YYYY.MM.DD` 를 인식하고, 월·일 범위를 검사하므로
`20261301` 같은 값은 날짜로 보지 않습니다. 파일명에 여러 개 있으면 마지막 것을 씁니다
(`2026년 제재통계` 같은 접두어보다 뒤에 붙은 추출일자가 기준일이므로).

**못 찾으면 자리표시자를 그대로 둡니다.** 잘못된 날짜를 적는 것보다 비어 있는 것이 눈에 띕니다.
`fill_monthly_hwpx(..., asof="’26.01.01")` 로 직접 지정할 수도 있습니다.

> 양식에 적힌 분류 행은 **이전 산출물의 스냅샷**이어서 표마다 목록이 달랐습니다.
> 환수금(제재사유) 표에는 `기술료 미납`·`환수금 미납`·`연구개발 성과의 소유 위반`이 없고,
> 제재부가금(부처별) 표에는 `기후에너지환경부`가 `환경부`로, 환수금(부처별) 표에는
> `보건복지부`가 `복지부`로 적혀 있었습니다. 그래서 행은 양식을 따르지 않고 표준 목록으로
> 다시 만듭니다. 표 서식·각주·글꼴은 원본 양식 그대로 유지됩니다.

표기는 금액 소수 1자리, 미납률 소수 1자리 `%`, 건수 정수이고 0이거나 산출 불가면 `-`입니다.

## 검산

### 표 간 — 같은 제재유형의 세 표는 건수 합계가 같아야 합니다

1·2·3(참여제한), 4·5·6(환수금), 7·8·9(제재부가금)은 **같은 모집단을 세 방식으로 나눈 것**이므로
건수 합계가 같아야 합니다. 다르면 틀린 것입니다.

실제로 갈라지는 원인은 두 가지입니다.

| 원인 | 어느 표에서 빠지나 |
|---|---|
| 제재사유가 9분류 어디에도 없음 | 제재사유별 표에서만 |

기관유형은 목록 밖 값과 공란을 `기타`로 편입하므로 빠지지 않습니다.
부처도 비어 있으면 `(부처 미지정)` 으로 남습니다. **남은 원인은 제재사유 하나뿐입니다.**

어긋나면 화면과 엑셀 `검산` 시트에 **모집단 · 표별 합계 · 어느 표에서 몇 건이 빠졌는지**를
함께 보여줍니다.

```
✕ 참여제한   모집단 37 / 제재사유 33 · 기관유형 34 · 부처 37
             (빠진 건수: 제재사유 −4 · 기관유형 −3)
```

원자료의 제재사유·연구수행주체를 채우거나, `REASON_GROUPS` 에 빠진 원문값을 추가해야 합니다.

### 표 안쪽

- 분류별 합 = `합 계` 행 (건수 · 부과액 · 납부액 각각)
- 연도별 합 = `합계` 열

둘 중 하나라도, 또는 표 간 검산이 어긋나면 통계판의 해당 칸이 `✕`가 되고 탭 이름 옆도 `✕`가 됩니다.

# 성능

10만 행 × 94열 (46MB xlsx), 과제 3만 건 기준 측정값입니다.

**원인과제 집계**

| 단계 | 시간 |
|---|---|
| 엑셀 읽기 (필요한 14열만) | 12~14초 |
| 변환 · 전처리 | 1초 |
| 기간분석 · 판정 | 1.4초 |
| 집계 | 0.1초 |
| 엑셀 저장 (연도전개 포함 · 기본) | 12초 |
| hwpx 저장 | 0.2초 |
| **합계** | **약 28초 / 최대 730MB** |

**월별 통계**

| 단계 | 시간 |
|---|---|
| 엑셀 읽기 (필요한 13열만) | 6~7초 |
| 전처리 (11열) | 1.1초 (금액이 전부 텍스트면 +0.8초) |
| 통계 9종 집계 | 0.6초 |
| 엑셀 저장 (전처리 포함 · 기본) | 5초 |
| hwpx 저장 (표 9개) | 0.3초 |
| **합계** | **약 19초 / 최대 730MB** |

두 통계를 다 돌리면 rawdata를 두 번 읽습니다(각자 필요한 열이 달라서).
합쳐 47초쯤이고, 엑셀 읽기와 상세 시트 쓰기가 대부분입니다.

최적화 이력 — 처음 구현은 10만 행에서 훨씬 느렸습니다.

| 고친 것 | 전 | 후 |
|---|---|---|
| 엑셀 읽기: pandas가 94열 전체를 올린 뒤 걸러냄 → calamine으로 흘려 읽으며 14열만 담기 | 22초 / 1.29GB | 12초 / 0.73GB |
| 기간분석: `groupby.unique()` 6회 (30만 회 그룹 슬라이싱) → 불리언 max·first·min/max로 벡터화 | 13.2초 | 1.4초 |
| 집계: `iterrows()` → 과제×연도 불리언 행렬 + groupby.sum | (수십 초) | 0.1초 |
| 엑셀 쓰기: `pandas.to_excel` 셀 단위 → xlsxwriter `write_row` | 23초 | 4초 |

## 검증 결과

**실제 샘플 데이터** (`제재정보_rawdata_20260101_샘플.xlsx`, 48행 / 94열 / 29과제)

원인과제 집계 — 헤더 2행 자동 탐지, 과제번호 22건으로 묶임, 판정 20건 / 환수금만 2건 제외,
부처 5개, ① 1건 · ② 18건 · ③ 1건, 소계 20건 ✔

월별 통계 — 통계 9종 모두 산출. 참여제한 3표의 합계가 37건으로 동일,
환수금 부과액 16.3억 = 납부액 4.8억 + 미납액 11.5억, 미납률 70.6% ✔
`산업통상부`가 정식 행으로 들어가고 구칭 0 행이 남지 않는지, 부처별 표에서 0건 행이
빠지는지(참여제한 23 → 6행) 확인 ✔

**표 간 검산은 일부러 틀린 데이터로도 시험했습니다.** 제재사유를 9분류 밖 값으로 4건,
연구수행주체를 공란으로 3건 만들었을 때 `제재사유 33 · 기관유형 34 · 부처 37` 로 어긋나는 것과
`빠진 건수: 제재사유 −4 · 기관유형 −3` 이라는 원인 표시가 맞는지 확인했습니다.
부처를 공란으로 만든 경우는 `(부처 미지정)` 으로 남아 합계가 유지되는 것까지 확인 ✔

**금액 정제도 텍스트 파일로 시험했습니다.** 금액 3열을 `18,873,603` 형태의 쉼표 문자열로 바꾼
파일이 숫자 파일과 **동일한 합계**(환수금 16.34억, 제재부가금 0.61억)를 내는지, `해당없음` 을
섞었을 때 변환 실패 3건이 화면과 엑셀에 뜨는지 확인했습니다.
`parse_money()` 는 쉼표·전각숫자·전각공백·통화표기·괄호음수를 단독으로도 시험했습니다 ✔

**기관유형 편입** — `정부부처`·`무분류`·`병원`·공란을 섞어 넣고 전처리 결과가 표준 7개
안에만 있는지, 값별 편입 건수가 맞는지, 그 결과 **기관유형별 표 합계가 모집단과 같아지는지**
확인했습니다 ✔

**hwpx 기준일** — 파일명 6종으로 추출을 시험하고, `’26.01.01` 이 9곳 모두 치환되는지,
날짜가 없는 파일명에서는 자리표시자가 그대로 남는지, GUI 출력에도 반영되는지 확인했습니다 ✔

**정합성** — 원인과제 집계 4항목은 더미 2,311행 / 실제 샘플 / 합성 10만 행(과제 3만) 모두 통과.
월별 통계 9표의 분류합·연도합, 세 표 합계 일치도 모두 통과 ✔

**hwpx** — 두 양식 모두 rowCnt/colCnt/rowAddr/colAddr 정합, 셀 병합 유지, 열 너비 합 = 원본 표 너비.
원인과제 집계는 연도 10개일 때 colCnt 13으로 자동 확장, 월별 통계는 표 9개가 모두 12열 유지 ✔

**GUI** — 서버 API 전 과정 26개 + 검산 확장 25개 + 전처리 정제 20개 + 기관유형·기준일 17개 + 표기규칙 23개 항목 헤드리스 검증: 화면 서빙, 탭 2개, 통계판,
rawdata 한 번 업로드로 두 통계 실행, **탭별 결과가 서로 지워지지 않는지**, 내장 양식·참조데이터 인식,
탭별 출력 4종, 월별 엑셀 시트 구성(1~9 + 검산 + 전처리), 월별 hwpx 표 9개,
그리고 오류 경로(없는 파일 / 헤더 행 잘못 지정)에서 사람이 읽을 수 있는 메시지가 나오는지까지 확인 ✔
