# 0001. 새 버전은 폴더를 통째로 복사해 만든다

- 상태: 확정(사용자 확인 2026-10-23)
- 적용: 저장소 전체

## 맥락
도구 여러 개를 혼자 고쳐 가며 쓴다. 고친 버전에 문제가 생기면 이전 exe와 소스로 바로 돌아가거나 결과를 비교해야 한다. 사용자는 git의 브랜치·태그에 익숙하지 않다.

## 결정
- 새 버전은 현재 버전 폴더를 통째로 복사하고 접미사를 붙여 만든다(`v4.2` → `v4.3`, `통계v5` → `통계v6`, `회의록정리v3` → `회의록정리v3.1`).
- 가장 높은 번호가 현재 버전이다.
- 이전 폴더는 소스와 exe를 그대로 보존하고 고치지 않는다.
- git은 버전 관리 수단이 아니라 보관용이다.

## 고려한 대안
- **git 브랜치·태그로 버전 관리**: 사용자가 익숙하지 않아 되돌리거나 비교하기 어렵다.

## 결과
- 같은 코드가 여러 폴더에 중복된다. 수정은 현재 폴더에만 하므로 이전 버전의 결함은 그대로 남는다. 이전 버전을 고치는 일은 하지 않는다.
- 현재 버전을 폴더로 판단해야 한다. 폴더 번호와 프로그램 안의 버전 표기가 다를 수 있다.
- 검색 결과에 이전 버전 코드가 섞인다. 수정 대상을 찾을 때는 현재 버전 폴더로 범위를 좁힌다.
- 새 버전을 만들지, 현재 폴더를 고칠지는 사용자가 정한다.
- 일부 버전 폴더(회의록 v3.1)는 사용자의 지시로 자체 git 저장소가 되었다. 그런 폴더는 상위 저장소 추적에서 뺀다.
