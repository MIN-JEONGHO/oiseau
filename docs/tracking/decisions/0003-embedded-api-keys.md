# 0003. API 키를 exe에 넣어 배포한다

- 상태: 확정(사용자 확인 2026-10-23)
- 적용: 회의록 자동정리(내장 키는 v1.1.0부터, 키 입력 화면 제거는 v3.0.0부터), 연구보안·연구윤리 동향 리포트(v3부터)

## 맥락
exe를 받은 동료가 API 키를 발급하거나 입력하지 않고 바로 쓰게 하고 싶었다.
- 회의록 v1.1.0·v2.0.0은 내장 키 → 환경변수 → 설정 화면에서 입력해 Windows DPAPI로 암호화 저장한 키 순서로 키를 찾았다.
- 리포트는 v2까지 설정 화면에서 키를 입력받아 `config.json`에 평문으로 두었다.

## 결정
- **회의록**: `embedded_key.py`의 `OPENAI_API_KEY`를 빌드할 때 exe에 묶는다. 내장 키를 먼저 쓰고, 없을 때만 환경변수 `OPENAI_API_KEY`를 쓴다. v3.0.0에서 입력란을 없애면서 쓰이지 않게 된 DPAPI 저장 기능도 지웠다.
- **리포트**: `rmonitor/_secrets.py`의 `ANTHROPIC_API_KEY`를 exe에 묶는다. 환경변수 `RM_LLM_API_KEY`가 있으면 그것을 먼저 쓴다. 키 입력 화면과 설정 항목은 없다.
- 키는 화면(브라우저)과 설정 파일로 내보내지 않는다.
- 배포는 같은 센터·부서 동료까지로 한다.

## 고려한 대안
- **받는 사람이 각자 키를 입력·보관**: 받는 사람이 키를 준비해야 해서 기각했다. 회의록의 DPAPI 암호화 저장은 입력란과 함께 없앴다.
- **설정 화면에서 입력해 설정 파일에 평문 저장(리포트 v1·v2 방식)**: 받는 사람이 키를 넣어야 했다. 설치 후 바로 리포트를 만들 수 있도록 v3에서 바꿨다.

## 결과
- exe를 가진 사람은 문자열을 추출해 키를 꺼낼 수 있다. 배포 범위를 넓히려면 이 결정부터 다시 해야 한다.
- 키 파일과 exe·dist·배포 zip은 커밋하지 않는다.
- 키를 바꾸려면 다시 빌드해 재배포해야 한다. 리포트는 환경변수로 바로 바꿀 수 있다. 회의록은 내장 키가 있으면 환경변수가 무시된다.
- 노출이 의심되면 제공자 콘솔에서 폐기하고, 새 키로 다시 빌드하고, 이전 exe를 회수한다.
