# 시스템 구성

## 전체 구성

저장소 `oiseau/`의 코드는 모두 `dev/` 아래에 있고, `dev/<프로그램 폴더>/<버전 폴더>/` 두 단계로 놓인다. 버전 폴더 하나가 독립된 실행·빌드 단위다. 프로그램끼리, 버전 폴더끼리 공유하는 코드·패키지·빌드 설정은 없다. 여러 프로그램에 같은 이름의 모듈(`hwpx_writer.py` 등)이 있어도 서로 다른 구현이다. 각 프로그램은 PyInstaller로 exe 하나가 되어 센터·부서 동료의 PC로 복사된다.

| 프로그램 | 현재 버전 폴더 (`dev/` 기준) | 진입점 | 화면 방식 | 외부 연결 |
|---|---|---|---|---|
| 공공데이터 등록 사전검토 | `공공데이터 DB검증 프로그램/공공데이터 DB검증v4/` | `main.py` — 인수가 없으면 화면, 있으면 명령줄 | pywebview 창이 파이썬 객체를 직접 호출 | 실호출을 켰을 때만 등록 API 주소 |
| 국외지원사항 통계 | `국외지원사항 프로그램/국외지원 자동산출 프로그램v4.3/` | `국외지원사항_통계산출.py` — 파일 인수가 2개 이상이면 명령줄 | tkinter 창, 대시보드는 Canvas에 직접 그림 | 없음 |
| 제재통계 | `제재통계 프로그램/통계v6/` | `app.py`(화면), `run_report.py`(연구수행 기준 명령줄) | 127.0.0.1 HTTP 서버 + pywebview | 없음 |
| 연구보안·연구윤리 동향 리포트 | `연구보안연구윤리 월간메일링/v4/` | `run_gui.py`(화면), `run_cli.py`(명령줄·예약 실행) | 127.0.0.1 HTTP 서버 + pywebview | Anthropic Messages API + 웹 검색 도구 |
| 회의록 자동정리 | `회의록 자동정리 프로그램/회의록정리v3.1/` (자체 git 저장소) | `app.py` — `--cli`면 명령줄 | 127.0.0.1 HTTP 서버 + pywebview | OpenAI 전사 API·Chat Completions API |

보안등급분류 시뮬레이터(`dev/보안등급분류 시뮬레이터/`)는 자체 작업 지침과 문서를 가진 별도 단위이며, 다른 도구와 코드·빌드를 공유하지 않는다.

## 공통 처리 흐름

통계 도구 두 개(국외지원·제재통계)의 흐름은 이렇다.

원자료 파일 → 읽기(열은 위치가 아니라 머리글 이름과 별칭으로 찾음) → 전처리(제거·정규화, 근거 기록) → 집계 엔진 → 검산 → 엑셀 리포트와 한글(hwpx) 보고서

공공데이터 도구도 읽기 → 판정 흐름은 같지만, 결과는 엑셀 리포트와 자동수정 사본이다. hwpx와 검산은 없다.

- 의존 방향은 진입점(화면·명령줄) → 엔진 → 출력기 한쪽뿐이다. 엔진은 화면 모듈을 가져오지 않으므로 화면과 명령줄이 같은 계산을 쓴다.
- hwpx 출력은 한컴 양식 파일(zip) 안의 `Contents/section0.xml`을 열어 XML을 직접 고친 뒤 다시 압축한다. 양식 안에서 채울 곳을 찾는 방법은 도구마다 다르다.
  - 국외지원·회의록: 표는 표 안의 머리글 문구로, 값 자리는 양식의 자리표시자 문구로 찾는다.
  - 제재통계: 위치로 찾는다. 연구수행 기준은 양식의 첫 표를 고정된 행 배치(머리 행 다음에 부처별 7행 블록)로 다루고, 처분연도 기준은 문서에 나오는 순서대로 표 9개를 통계 1~9번에 대응시킨다.

AI 도구 두 개(리포트·회의록)는 외부 API 호출 → 응답(JSON) 검증 → 사람이 확인·수정 → HTML 또는 hwpx 생성 순서다.

## 화면 구조 세 가지

1. **파이썬 객체 직접 호출 (공공데이터)**: `checker/gui.py`가 `checker/ui.py`에 문자열로 들어 있는 HTML을 pywebview 창에 띄우고, JS가 파이썬 객체의 메서드를 직접 부른다. HTTP 서버가 없다. 구분(파일데이터·OPEN API)별 결과를 따로 들고 있어서 탭을 오가도 지워지지 않고, 엑셀 리포트에는 양쪽이 함께 들어간다.
2. **로컬 HTTP 서버 (제재통계·리포트·회의록)**: 127.0.0.1의 빈 포트에 HTTP 서버를 띄워 `ui/index.html`과 `/api/*` JSON 엔드포인트를 제공하고, pywebview가 그 주소를 창으로 연다. 오래 걸리는 작업은 백그라운드 스레드에서 돌고, 화면은 상태 엔드포인트를 주기적으로 읽는다. 요청에 토큰이나 출처 확인은 없다. 소스로 실행할 때 pywebview가 설치되어 있지 않으면 같은 주소를 기본 브라우저로 연다.
3. **tkinter (국외지원)**: 산출 판과 대시보드 판 두 개로 나뉜다. 산출을 마치면 대시보드로 넘어가, 같은 통계를 다시 계산하지 않고 그린다. 창을 만들기 전에 DPI 인식을 켜고, 픽셀 값에는 화면 배율을 곱한다.

## 프로그램별 흐름

### 공공데이터 등록 사전검토
- **파일데이터**: `engine` → `rules_file`(확장자·용량·ZIP·비정형) → `readers`(형식별 판독: CSV·TSV·TXT, XLSX 첫 시트, JSON 객체 배열, ZIP 안의 CSV·TSV) → `rules_csv`(10·12·13·17번 표 전수 검사) → `rules_meta`(등록 정보 1~4·7·11·14~16번) → 자동 판정이 안 되는 5·6번 안내 → 결과.
- **OPEN API**: `api_reader`(Swagger·OpenAPI JSON 또는 오퍼레이션 명세표를 같은 명세 구조로 정규화) → `api_probe`(실호출을 켰을 때만) → `rules_api`(1~23번) → 결과.
- **출력**: `report`(두 구분을 한 엑셀에), `fixer`(파일데이터 수정 사본), `api_fixer`(등록 정보 대조표 JSON). 수정본을 다시 검토한 결과를 목록에 덧붙인다.

### 국외지원사항 통계
진입점(화면·명령줄) → `resources`로 매핑테이블·양식 결정(exe 옆 파일이 있으면 그것, 없으면 exe 내장본) → `stat_engine`이 매핑을 읽고 별칭 충돌을 점검 → `preprocessor`가 연구자 raw·과제 raw를 읽고 전처리(시트 선택, 머리글 인식, 병합 머리글 분리, 파일 종류 확인) → 파일명에서 산출기준일 결정 → `stat_engine` 통계 산출 → `report_builder`(엑셀 9시트) → 양식이 있으면 `hwpx_writer`(한글 보고서가 실패해도 엑셀은 남긴다) → `dashboard`가 같은 통계를 표시.

### 제재통계
- **연구수행 기준**: 화면 또는 `run_report.py` → `sanction_pipeline`: 헤더 행 탐지 → 필요한 열만 읽기 → 변환 → 전처리 → 기간 분석·판정 → 연도별 집계 → 참조데이터 결합 → `excel_writer`, `hwpx_writer`. 검산 4종은 화면(`app.py`)에서만 계산한다.
- **처분연도 기준**: `monthly_pipeline`: 헤더 탐지·연도 추출·부처명 치환은 `sanction_pipeline`에서 가져다 씀 → 11열 전처리 → 제재유형 × 분류축 표 → 표 안·표 간 검산 → `monthly_excel`, `monthly_hwpx`.
- 두 통계는 필요한 열이 달라 rawdata를 각자 읽는다. 화면에서 고른 파일은 임시 폴더로 복사되고, 결과 저장 기본 위치는 문서 폴더의 `제재통계`다. 두 탭의 결과는 서로 지우지 않고 따로 남는다.

### 연구보안·연구윤리 동향 리포트
`rmonitor/pipeline` → 기간 계산(월간은 직전 달, 주간은 직전 주 월~일) → `collector`가 `prompts/*.txt`의 자리표시자를 채운 지시문 작성 → `llm`이 Anthropic Messages API 호출(웹 검색 도구) → 응답 원문 저장 → `collector`가 JSON 추출·검증 → `renderer`(HTML) → `excel_log`(누적 엑셀) → `history`(실행 이력). 프롬프트·양식은 exe 안의 읽기 전용 자원이고, 설정·출력·로그·이력·누적 엑셀은 exe가 있는 폴더에 쓴다.

### 회의록 자동정리
화면의 전사 → `audio`(업로드 한도를 넘거나 OpenAI가 그대로 받지 않는 형식이면 WAV로 바꿔 나눔) → `stt`(whisper-1, 구간 시각 포함) → 발언자 매칭 → `summarizer`(구간을 나눠 요청) → 기관별 요약 → `summarizer` → 화면에서 사람이 수정 → 문서 만들기 → `hwpx_writer`(양식 자리표시자 치환과 기관별 요약 표 재구성) + 전사문 + 세션 JSON.

## 경계 — 밖으로 나가는 것

| 프로그램 | 밖으로 나가는 것 | 나가지 않는 것 |
|---|---|---|
| 공공데이터 | 실호출을 켰을 때만, 등록 URL에 인증키를 붙인 GET 요청 | 검토 대상 파일 내용, 리포트 |
| 국외지원 | 없음 | 원자료·결과 전부 |
| 제재통계 | 없음 | 원자료·결과 전부 |
| 리포트 | Anthropic으로 기간·카테고리를 채운 수집 지시문 | 업무 자료 |
| 회의록 | OpenAI로 녹음 파일(전사 단계만), 전사문·참석자 명단·회의 정보(매칭·요약 단계) | API 키(화면으로도 보내지 않음) |

화면 서버는 모두 127.0.0.1에만 묶여 있어 다른 PC에서 접근할 수 없다. 화면은 외부 CDN·웹폰트·원격 자원을 부르지 않는다.
