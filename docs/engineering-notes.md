# 실무 주의사항

## 공통

### 폴더 번호와 프로그램 안의 버전이 다르다
- **증상**: 최신으로 보이는 폴더를 고쳤는데 현재 버전이 아니었다. 또는 README·화면의 버전 표기가 폴더와 맞지 않는다.
- **원인**: 폴더를 복사할 때 내부 표기를 함께 올리지 않은 경우가 있다.
  - `공공데이터 DB검증v4` 폴더의 프로그램 표기는 `3.0.0`이다.
  - `공공데이터 DB검증 프로그램/v4` 폴더는 이름과 달리 `DB검증v3`의 백업이다.
  - 제재통계 `통계v6`의 화면 버전은 `v1.1.1`이다.
  - 리포트 `v4/dist`의 exe 이름은 `…모니터링v5.exe`다(프로그램 표기는 4.0.0).
  - 국외지원 v4.3 사용설명서의 '별칭 충돌 6건'은 v4.1 때 이야기이고, 현재 v4.3 매핑테이블의 충돌은 0건이다.
  - 공공데이터 README의 OPEN API 테스트 수(44)도 실제 시험 함수 수(46)와 다르다.
- **대응**: 현재 버전은 폴더로 판단한다. 공공데이터 `공공데이터 DB검증v4`, 국외지원 `국외지원 자동산출 프로그램v4.3`, 제재통계 `통계v6`, 리포트 `v4`, 회의록 `회의록정리v3.1`이다. 내부 표기와 README 숫자는 참고만 한다.

### 자체 git 저장소가 있는 하위 폴더
- **증상**: 상위 저장소에서 `git add dev/`를 하면 "embedded git repository" 경고가 뜨고, 내용 대신 빈 연결(gitlink)만 올라간다. 하위 폴더에서 `git log`를 하면 "detected dubious ownership"으로 거부된다.
- **원인**: `회의록정리v3.1` 등 일부 폴더는 자체 `.git`을 가진 별도 저장소다. 하위 저장소 일부는 다른 Windows 계정(Codex 샌드박스)으로 만들어져 소유자가 다르다.
- **대응**: 이런 폴더는 상위 `.gitignore`에 등록되어 있으므로 상위에서 추가하지 않는다. 하위 저장소 작업은 그 폴더 안에서 한다. 소유자 경고는 그 명령에만 `git -c safe.directory="<폴더 경로>" …`를 붙여 넘긴다. 전역 설정을 바꿀지는 사용자가 정한다.

### PyInstaller 결과물이 엉뚱한 폴더에 생긴다
- **증상**: 저장소 맨 위에 `build/app`·`dist` 폴더가 생겼다(2026-08-03에 생긴 빈 폴더가 남아 있다).
- **원인**: PyInstaller는 build·dist를 **현재 작업 폴더**에 만든다. 제재통계·리포트의 `build_exe.bat`에는 `cd /d "%~dp0"`가 없어서, 다른 폴더에서 실행하면 그 자리에 결과물이 생긴다. 공공데이터·회의록 `build_exe.bat`은 자기 폴더로 이동한 뒤 빌드한다.
- **대응**: 빌드는 해당 버전 폴더에서 실행한다(탐색기에서 더블클릭하면 그 폴더가 작업 폴더가 된다). `.spec`을 직접 돌릴 때도 먼저 그 폴더로 이동한다.

### WebView2가 없는 PC에서는 화면이 제대로 뜨지 않는다
- **증상**: 받는 PC에서 exe 창은 뜨는데 화면이 비거나 깨지고 버튼이 동작하지 않는다.
- **원인**: exe에는 pywebview가 들어 있다. pywebview는 WebView2 런타임이 없으면 구형 IE(MSHTML) 엔진으로 창을 연다. 이 엔진은 지금의 화면 스크립트를 처리하지 못한다. '기본 브라우저로 연다'는 동작은 **소스로 실행할 때 pywebview가 설치되어 있지 않은 경우**에만 일어난다. 제재통계·리포트의 `build_exe.bat`과 README에 있는 "없으면 기본 브라우저로 열립니다" 안내는 exe에는 맞지 않는다.
- **대응**: 배포 전에 받는 PC에 Microsoft Edge WebView2 런타임이 있는지 확인한다(Windows 10 21H2 이상·Windows 11은 기본 포함). 없으면 런타임을 설치한다.

### 이 PC의 Python
- **증상**: `python -I -c "import openpyxl"`나 `py -3.13`으로 돌리면 `ModuleNotFoundError`가 난다.
- **원인**: 프로젝트 의존성은 Python 3.14의 사용자 site-packages(`%APPDATA%\Python\Python314\site-packages`)에 설치되어 있다. `-I`·`-s`는 사용자 site-packages를 건너뛴다. `py -3.13`은 시스템 설치본이 아니라 다른 폴더에 들어 있는 휴대용 런타임을 가리킨다.
- **대응**: `python`(3.14.2, WindowsApps 별칭)이나 `py -3.14`로, `-I`·`-s` 없이 실행한다. 외부에서 받은 파일만 읽을 때는 그 파일을 둔 폴더가 아닌 곳에서 실행한다.

### 한국어가 든 .bat 파일
- **증상**: 콘솔에 한글 메시지가 깨지거나, 배치 파일 안의 한글 경로·이름이 잘못 해석된다.
- **원인**: 콘솔 코드페이지가 UTF-8이 아니면(기본 CP949) UTF-8로 저장한 배치 파일의 한글을 잘못 읽는다.
- **대응**: 제재통계·리포트·회의록의 `.bat`처럼 `@echo off` 바로 다음 줄에 `chcp 65001`을 두고 UTF-8로 저장한다. 공공데이터 `build_exe.bat`은 주석과 안내를 ASCII로 쓰지만 exe 이름(`--name "공공데이터_사전검토"`)과 마지막 안내에 한글이 있고 `chcp`가 없다. 그래서 콘솔 코드페이지에 따라 이 부분이 깨질 수 있으니 본보기로 삼지 않는다.

### hwpx 양식 편집
- **증상**: 보고서를 만들었는데 특정 표나 숫자가 비어 있다. 또는 엉뚱한 표에 값이 들어갔다. 또는 한글에서 표가 깨져 보인다.
- **원인**
  - 국외지원·회의록은 표를 표 안의 머리글 문구로, 값 자리를 자리표시자 문구로 찾는다. 양식에서 그 문구를 바꾸면 그 표·자리를 찾지 못한다. 국외지원은 이때 처리 내역에 "표를 찾지 못해 건너뛰었습니다"를 남긴다.
  - 제재통계는 표를 **위치**로 찾는다. 연구수행 기준은 첫 번째 표의 고정 행 배치를 쓰고, 처분연도 기준은 문서 순서대로 표 9개를 통계 1~9번에 대응시킨다. 표를 끼워 넣거나 순서·행 구조를 바꾸면 경고 없이 다른 표에 값이 들어간다(처분연도 기준은 표가 9개보다 적을 때만 멈춘다).
  - 행·열을 복제하거나 추가하면서 `rowAddr`·`colAddr`·`rowCnt`·`colCnt`·`rowSpan`·`cellSz`·표 `sz`를 다시 계산하지 않으면 한글이 표를 잘못 그린다.
  - 다시 압축할 때는 `mimetype` 항목을 첫 항목, 무압축으로 넣는다.
- **대응**
  - 국외지원·회의록 양식은 출력기가 찾는 머리글 문구와 자리표시자를 유지한다.
  - 제재통계 양식은 표의 개수·순서·행 구조를 바꾸지 않는다. 고쳤으면 합성 자료로 hwpx를 만들어, 한글에서 표마다 제목과 값이 맞는지 대조한다.
  - 출력기를 고친 뒤에는 결과 hwpx를 한글로 직접 열어 본다. XML 구조 검사만으로는 표시 결과를 보증할 수 없다.

## 국외지원사항 통계

### 매핑테이블을 고쳤는데 exe에 반영되지 않는다
- **증상**: 소스 폴더의 `매핑테이블.xlsx`를 고친 뒤에도 배포한 exe는 예전 규칙으로 집계한다.
- **원인**: 자원은 'exe(또는 스크립트) 옆 파일 → exe 내장본' 순서로 찾는다. 내장본은 **빌드할 때** 소스 폴더에 있던 파일이다. 소스에서 실행하면 소스 폴더의 파일이 곧 '수정본'이면서 '내장본'이다.
- **대응**
  - 받는 사람의 exe에 반영하려면 다시 빌드하거나, [양식·테이블 내려받기]로 꺼내 고친 파일을 exe 옆에 둔다.
  - 내려받을 폴더에 같은 이름의 파일이 있으면 덮어쓸지 먼저 묻는다. '아니오'면 없는 파일만 내려받는다.
  - 잘못 고쳤으면 옆 파일을 지우면 내장본으로 돌아간다.
  - 화면 경로 앞의 `[내장]`·`[수정본]`·`[지정]`으로 어느 쪽을 쓰는지 확인한다.

### 시트를 고쳐도 판정이 그대로인 규칙
- **증상**: [유형규칙] 시트의 `기타` 행을 고쳐도 기타 판정이 바뀌지 않는다. 금전 `포함`에 `원`·`공동연구`를 넣어도 그 표현만으로는 금전이 되지 않는다.
- **원인**: 기타는 잔여 유형이라 시트의 기타 행을 무시하고, 근거 표현은 코드의 `OTHER_KW`에 있다. 금전 규칙은 읽을 때 `harden_money`가 활동명·낱개 숫자·통화 낱말을 '조건부'로 내리고, '지급 없음' 제외 문구를 채워 넣는다. 시트에 금전 `근거`를 직접 적으면 기본 근거 대신 그 값이 쓰인다.
- **대응**: 기타 근거 표현은 `stat_engine.py`의 `OTHER_KW`를 고친다. 금전은 시트의 `조건부`·`근거`·`제외` 행으로 조정한다.

### 지원·지급 기간 종료일이 사라진다
- **증상**: 보고의무 종료 연구자가 0명이거나 종료일 미상이 많다.
- **원인**: 실제 raw는 지원·지급 기간이 시작·종료 두 칸이고 머리글만 병합되어 있다(연구자 raw `F1:G1`, 과제 raw `J1:K1`). 그냥 읽으면 종료일 칸의 머리글이 비어 종료일이 통째로 버려진다.
- **대응**: 병합 머리글을 인식해 시작일·종료일 두 열로 나누는 처리를 유지한다. 한 칸에 `2026-06-25 ~ 2027-06-05`처럼 적힌 형식도 쪼갠다. 머리글 처리를 고친 뒤에는 두 형식의 합성 파일로 모두 확인한다.

### raw와 정제본의 열 위치가 한 칸 어긋난다
- **증상**: 위치 기준으로 읽으면 사유·내용·국가가 한 칸씩 밀린다.
- **원인**: 실제 raw는 사유 H·내용 I·국가 J이고, 예전 정제본은 사유 G·내용 H·국가 I다.
- **대응**: 열은 머리글 이름(공백·가운뎃점·괄호·기호를 무시한 비교)으로 찾는다. 실패하면 위치로 대체하고 처리 내역에 표시한다. 연구자 파일과 과제 파일을 바꿔 넣으면 멈추는 확인도 유지한다.

### 화면 배율
- **증상**: 4K·150% 화면에서 1px 선과 작은 글자가 뭉개진다. 150% 배율 1920×1080 노트북에서 창 아래가 화면 밖으로 나간다.
- **원인**: DPI 인식이 꺼져 있으면 Windows가 창을 비트맵으로 확대한다.
- **대응**: `Tk()`를 만들기 **전에** DPI 인식을 켠다. 픽셀 상수는 `theme.px()`로 배율을 곱한다. 창 크기는 화면을 넘지 않게 자른다.

### 기본 저장 위치가 프로그램 폴더다
- **증상**: 결과 엑셀·hwpx가 exe 폴더나 소스 버전 폴더에 쌓인다(v3·v3.7·v3.8 폴더와 v4.x `dist`에 남은 결과물이 그 예다).
- **원인**: 저장폴더 기본값이 exe 또는 스크립트 폴더다.
- **대응**: 실행 전 [저장폴더]를 저장소 밖으로 바꾼다. 결과 파일 이름 패턴은 `.gitignore`에 등록되어 있다.

## 제재통계

### 같은 부처가 두 줄로 갈라진다
- **증상**: 부처별 표에 `산업통상자원부`(0)와 `산업통상부`(미등록 값)가 따로 나온다. 또는 참조데이터 비율이 공란이 된다.
- **원인**: pandas `Series.replace(dict)`는 한 번만 치환해서 연쇄 개편(A→B→C)이 중간 이름 B에 멈춘다. 표준 부처 목록이나 참조데이터에 치환을 적용하지 않아도 같은 일이 생긴다.
- **대응**: 개편 표에는 실제 개편 한 단계씩만 적고, `resolve_rename_chains()`가 최종 이름을 계산하게 한다. 새 매핑을 넣을 때 rawdata·표준 목록·참조데이터 세 곳에 모두 적용되는지 확인한다.

### 두 통계의 열 별칭 사전이 따로 있다
- **증상**: 같은 rawdata인데 한 통계는 부처 열을 찾고 다른 통계는 못 찾는다.
- **원인**: 헤더 탐지·연도 추출·부처명 치환은 공유하지만, 열 별칭 사전은 `sanction_pipeline.py`와 `monthly_pipeline.py`에 따로 있다. 지금도 '부처명'의 별칭 `소관기관`은 연구수행 기준에만 있다.
- **대응**: 열 별칭을 더하거나 고칠 때 두 사전을 함께 고친다.

### 명령줄이 엉뚱한 hwpx를 양식으로 쓴다
- **증상**: `run_report.py`를 두 번째 돌리자 보고서 모양이 이상하거나 값이 겹쳐 나온다.
- **원인**: `--template`을 주지 않으면 rawdata 폴더·현재 폴더·출력 폴더에서 `*표준양식*제재처분*.hwpx`를 찾고, 없으면 아무 `*.hwpx`나 양식으로 쓴다. 세 폴더 모두에 hwpx가 없을 때만 내장 `template.hwpx`를 쓴다. 기본 출력 폴더가 rawdata 폴더라서, 이전 실행이 만든 `제재처분집계_*.hwpx`가 다음 실행의 양식이 된다.
- **대응**: 명령줄에서는 항상 `--template`으로 양식을 지정한다.

### 명령줄로 돌리면 연구수행 기준 검산이 없다
- **증상**: 명령줄 결과에는 검산 표시가 없고, 연구수행 기준 엑셀에도 `검산` 시트가 없다.
- **원인**: 연구수행 기준의 검산 4종은 화면(`app.py`)에서만 계산한다. `run_report.py`는 참조데이터에 없는 부처만 경고한다. `검산` 시트는 처분연도 기준 엑셀에만 있다.
- **대응**: 연구수행 기준을 바꿨으면 화면으로 실행해 검산 ✓를 확인한다.

### 내장 파일을 내려받으면 고쳐 둔 파일이 덮어써진다
- **증상**: 손으로 채운 참조데이터나 양식이 다시 내장본으로 돌아갔다.
- **원인**: 화면의 내장 파일 내려받기는 저장 폴더(기본: 문서 폴더의 `제재통계`)에 `참조데이터_기본값.xlsx`·`연구수행기준_표준양식.hwpx`·`처분연도기준_표준양식.hwpx`를 묻지 않고 덮어쓴다(국외지원의 내려받기와 다르다).
- **대응**: 고친 참조데이터·양식은 다른 이름으로 저장해 두고, 화면에서 그 파일을 지정한다.

### 금액 합계가 실제보다 작다
- **증상**: 환수금·제재부가금 합계가 원본 워크북보다 작다.
- **원인**: NTIS 내보내기에서 금액 열이 텍스트(`18,873,603`)로 올 때가 있다. `pandas.to_numeric`만 쓰면 이 값이 NaN이 되어 조용히 0으로 집계된다.
- **대응**: `parse_money()`로 쉼표·공백·전각·통화 표기·괄호 음수를 정리하고, 실패 건수와 값을 화면 각주·콘솔·엑셀 `검산` 시트에 남긴다. 금액 열을 새로 다룰 때도 이 함수를 거친다.

### rawdata 헤더가 2행이다
- **증상**: 열을 하나도 찾지 못하거나 1행 그룹 이름(문제과제정보·제재정보·등록정보)을 열 이름으로 읽는다.
- **원인**: NTIS 제재정보 rawdata는 1행이 그룹 머리이고 2행이 실제 열 이름이다.
- **대응**: 앞 15행에서 알려진 열 이름이 가장 많이 나오는 행을 헤더로 잡는다. 헤더 행을 잘못 지정하면 사람이 읽을 수 있는 오류로 멈춰야 한다.

### 과제유형 필터를 너무 일찍 걸면 과제가 빠진다
- **증상**: `공동위탁제외`·`세부만`으로 돌렸더니 주관 과제까지 시작일 결측으로 빠진다.
- **원인**: 공동·위탁 행이 갖고 있던 연구기간이 필터로 먼저 사라지면, 같은 과제의 주관 행이 기간을 보완받지 못한다.
- **대응**: 필터는 그룹 결측 보완 **뒤**, 과제 묶기 **앞**에서 건다. 순서를 바꾸지 않는다.

### 저장한 PNG가 안 만들어지거나 흐리다
- **증상**: 그림 저장에서 "그림을 PNG로 바꾸지 못했습니다"가 뜬다. 또는 저장본이 화면 캡처처럼 흐리다.
- **원인**: `data:image/svg+xml`은 HTML이 아니라 XML로 읽혀서, 속성값 안의 `<`(툴팁 `data-tip`에 든 `<u>`·`<b>`) 하나만 있어도 그림 전체가 실패한다. SVG에 `width`·`height`를 적지 않으면 크로미움이 300px로 한 번 래스터한 뒤 늘린다.
- **대응**: `vizPng()`가 PNG로 바꾸기 직전에 `data-tip`·`data-x`·히트존·십자선을 걷어내는 처리를 유지한다. 새 속성에 마크업을 담으면 같은 자리에서 함께 걷어낸다. 최종 화소 수를 SVG에 직접 적는다.

### 화면의 파일 선택과 저장 위치
- **증상**: 결과가 입력 파일 옆이 아니라 문서 폴더의 `제재통계`에 저장된다.
- **원인**: 찾아보기는 브라우저 기본 `<input type="file">`이라 고른 파일이 `%TEMP%\sanction_ui`로 복사된다. 처음에는 네이티브 대화상자를 썼지만, pywebview가 없는 환경에서 tkinter 창을 워커 스레드에서 띄우려다 아무것도 뜨지 않는 문제가 있어 바꿨다.
- **대응**: 저장 위치는 화면에서 따로 고른다. 파일 선택을 네이티브 대화상자로 되돌리지 않는다.

### 10만 행에서 느려진다
- **증상**: 10만 행 rawdata에서 읽기·집계에 수십 초 이상 걸린다.
- **원인**: 열 전체를 pandas로 올리거나, `groupby.unique()` 반복, `iterrows()`, 셀 단위 `to_excel`을 쓰면 느려진다.
- **대응**: python-calamine으로 한 행씩 읽으며 필요한 열만 담는다. 집계는 불리언 행렬과 벡터화 연산으로, 엑셀 쓰기는 xlsxwriter `write_row`로 한다. 기준값(10만 행 × 94열, 과제 3만 건)은 연구수행 기준 약 28초·최대 730MB, 처분연도 기준 약 19초다. python-calamine이 없으면 읽기가 수 배 느려진다.

## 공공데이터 등록 사전검토

### 명세표 응답 항목이 통째로 사라진다
- **증상**: 오퍼레이션 명세표에서 응답 파라메터 일부가 판독 결과에 없다.
- **원인**: 머리글 별칭을 영문까지 부분일치로 찾으면 `code`가 `resultCode`에 걸린다. 그러면 응답 파라메터 줄이 에러코드 머리글로 오인되어, 그 아래 항목이 모두 에러코드 표로 넘어간다.
- **대응**: 별칭 부분일치는 한글 낱말에만 쓴다. 영문 별칭은 정확히 일치할 때만 인정한다.

### 인코딩 판정
- **증상**: CP949 파일이 UTF-8로, 또는 그 반대로 읽힌다.
- **원인**: exe 크기를 줄이려고 인코딩 추정 패키지 없이 BOM 확인 후 `utf-8 → cp949 → euc-kr → utf-16` 순서로 디코딩을 시도한다. 먼저 성공한 쪽을 쓴다.
- **대응**: 인코딩 관련 규칙을 고치면 BOM 있는 UTF-8, BOM 없는 UTF-8, CP949 합성 파일로 회귀 시험을 한다. 인코딩 추정 패키지를 새로 들이지 않는다.

## 연구보안·연구윤리 동향 리포트

### Claude 요청 매개변수
- **증상**: HTTP 400으로 수집이 실패한다. 또는 응답이 잘린다.
- **원인**
  - Sonnet 5.5는 `temperature`·`top_p`·`top_k`를 받지 않는다.
  - thinking은 `{"type": "adaptive"}`만 받는다(`budget_tokens` 방식은 400).
  - 사고 과정도 `max_tokens`를 함께 쓴다.
  - 400 오류 문구에서 거부된 매개변수를 읽어 빼고 다시 보내는 처리(`_post_pruning`)는 `thinking`에만 적용된다. 다른 매개변수가 거부되면 다시 시도하지 않고 실패한다.
- **대응**: 요청에 그 세 매개변수를 넣지 않는다. 출력 상한 하한 32,000을 유지한다. 모델이나 요청 형식을 바꾸면 공식 전환 안내로 매개변수 정책을 다시 확인하고, 새로 거부될 수 있는 매개변수는 직접 뺀다.

### 예전 설정 파일을 옮기면 키가 화면에 다시 나온다
- **증상**: v4 설정 화면이나 `config.json`에 예전 LLM 키·SMTP 비밀번호 항목이 보인다.
- **원인**: v3·v4의 설정 읽기는 모르는 항목도 버리지 않고 기본값에 합친다. 설정 화면은 설정 전체를 화면으로 보내고, 저장할 때 그대로 다시 쓴다. 그래서 v1·v2의 `config.json`(키·비밀번호 평문)을 v3·v4 폴더나 exe 옆에 두면 그 값이 화면에 나오고 계속 저장된다.
- **대응**: v1·v2의 `config.json`을 새 버전으로 옮기지 않는다. 새 설정은 `config.example.json`에서 시작한다.

### 같은 이슈가 누적되지 않는다
- **증상**: 로그에 "수집 N건 중 M건만 추가"가 남는다.
- **원인**: 누적 엑셀에 같은 출처 URL이 이미 있으면 건너뛴다. 대소문자와 끝 슬래시 차이는 같은 URL로 본다.
- **대응**: 누락이 아니라 이전 실행에서 이미 쌓인 이슈인지 누적 파일에서 먼저 확인한다. 중복 건너뛰기는 `config.json`의 `excel.skip_duplicate_url`로 끌 수 있다.

### 예약 실행이 아무 기록 없이 실패한다
- **증상**: 작업 스케줄러에 등록했는데 리포트도 `logs\schedule.log`도 생기지 않는다.
- **원인**: `실행_자동발송.bat`·`실행_자동발송_주간.bat`은 출력을 `logs\schedule.log`로 넘긴다. 그런데 cmd는 넘길 곳의 폴더를 만들지 않는다. 소스 폴더(`v4/`)에는 `logs` 폴더가 없어서 첫 예약 실행이 Python을 띄우기도 전에 실패한다.
- **대응**: 예약을 등록하기 전에 그 폴더에 `logs` 폴더를 만들거나, 화면·명령줄로 한 번 실행해 둔다.

### '자동발송' 배치 파일은 메일을 보내지 않는다
- **증상**: `실행_자동발송.bat`을 예약했는데 메일이 오지 않는다.
- **원인**: v3부터 메일 발송 기능이 없다. 배치 파일 이름만 예전 그대로이고, 실제로는 `run_cli.py`로 리포트를 생성해 `logs\schedule.log`에 기록할 뿐이다. exe가 아니라 Python으로 실행하므로 예약 PC에 Python이 있어야 한다.
- **대응**: 예약 실행 결과는 `logs\schedule.log`와 [이력] 화면에서 확인하고, 생성된 HTML은 사람이 전달한다.

## 회의록 자동정리

### 전사 모델을 바꾸면 발언자 매칭이 안 된다
- **증상**: 다른 전사 모델로 바꾼 뒤 발언자 매칭 단계가 실패하거나 구간이 하나뿐이다.
- **원인**: 구간별 시각(`verbose_json`의 `segments`)을 주는 모델이 `whisper-1`뿐이다. 다른 모델은 전체 텍스트만 준다.
- **대응**: `STT_MODEL`은 `whisper-1`로 고정한다.

### 모델 이름을 바꿨는데 exe가 그대로다
- **증상**: `config.py`의 `SUMMARY_MODEL`을 바꿨는데 배포된 exe는 예전 모델을 부른다.
- **원인**: 모델은 빌드할 때 exe에 묶인다.
- **대응**: 바꾼 뒤 다시 빌드한다. 처음 쓸 때 [요약 모델 연결 테스트]로 모델 ID를 확인한다(없는 모델이면 HTTP 404 안내). 되돌릴 때는 이전 값으로 고쳐 다시 빌드하거나, 이전 버전 폴더의 exe를 쓴다.

### 녹음 파일 변환이 필요한 경우
- **증상**: 녹음 파일에서 전사가 실패하거나 1단계 화면에 변환기 경고가 뜬다.
- **원인**: Whisper API는 요청당 25MB 한도가 있다. 프로그램은 여유를 두어 **24MiB 이하이면서** 확장자가 flac·mp3·mp4·mpeg·mpga·m4a·ogg·wav·webm인 파일만 그대로 올린다. 그 밖의 파일(크기가 크거나 aac·wma·amr·opus·avi·mkv·mov·3gp 형식)은 16kHz 모노 WAV로 바꿔 10분씩 잘라 올려야 하고, 여기에 PyAV(`av`)나 `ffmpeg.exe`가 필요하다.
- **대응**: 빌드 전에 `pip install av`를 하거나 `ffmpeg.exe`를 `app.py` 옆에 둬야 exe에 함께 묶인다.

### 명령줄 세션 이어 하기도 유료 호출이 생긴다
- **증상**: `--session`으로 이어 했는데 요약이 바뀌고 API 사용량이 늘었다.
- **원인**: 명령줄 `--session`은 전사만 건너뛴다. 참석자(명령줄 값, 없으면 세션의 명단)가 있으면 발언자 매칭을 다시 하고, 요약은 항상 다시 한다. 세션에 저장된 회의 정보는 명령줄의 `--title`·`--date`·`--place`보다 우선한다.
- **대응**: 요약을 다시 만들 필요가 없으면 화면에서 세션을 불러와 문서만 만든다.

## 반복 작업 점검표

### 새 버전 폴더 만들기 (사용자가 요청했을 때)
1. 현재 버전 폴더를 통째로 복사해 다음 번호를 붙인다.
2. 복사본에서 `build`·`dist`·`__pycache__`·실행 산출물·실제 자료를 지운다. 키 파일(`embedded_key.py`·`_secrets.py`)은 빌드에 필요하므로 남기되 커밋하지 않는다.
3. 프로그램 안의 버전 표기, README·사용설명서의 현재 버전, `.spec`의 exe 이름을 올릴지 사용자에게 확인한다. 지금까지 폴더마다 관행이 달랐다.
4. 변경 → 검증 → 빌드 → 빈 폴더에서 exe 단독 실행 순서로 진행한다.
5. 확인: `diff -rq <이전 폴더> <새 폴더> -x build -x dist -x __pycache__` 결과에 의도한 파일만 나와야 한다. 이전 폴더의 수정 시각이 바뀌지 않았어야 한다.
6. 현재 버전 폴더 이름은 저장소의 작업 지침과 설명 문서 여러 곳에 적혀 있다. 한 곳만 고치면 다음 작업이 이전 폴더를 고치게 되므로, 저장소 전체에서 이전 폴더 이름을 검색해 모두 함께 고친다.

### 커밋 전
1. `git status`로 스테이징 목록을 본다.
2. `git diff --cached --name-only`에 `embedded_key.py`·`_secrets.py`·`config.json`·`_claude.py`·`.exe`·`.zip`·`build/`·`dist/`·결과 파일 이름(`통계분석결과_`·`국외지원사항_등록보고현황_`·`연구수행기준_`·`처분연도기준_`·`제재처분집계_`·`세션.json`)이 없어야 한다.
3. 새로 스테이징하는 소스에 키 형태 문자열이 없는지 확인한다: `git diff --cached | grep -E "sk-(ant|proj)-|AIza"`의 결과가 0줄이어야 한다. `.gitignore`는 이미 알려진 파일 이름만 막는다.
4. 자체 git 저장소 폴더의 파일이 상위 스테이징에 없어야 한다.

### exe 배포 전
1. 빌드 종료 코드 0, 빈 폴더에서 단독 실행, 화면 표시를 확인한다.
2. 회의록·리포트 exe에는 키가 들어 있다. 받는 사람이 같은 센터·부서 동료인지 확인한다.
3. 받는 PC에 Edge WebView2 런타임이 있는지 확인한다. 없으면 창이 구형 IE 엔진으로 떠서 화면이 동작하지 않는다.
