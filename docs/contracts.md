# 입력·출력 약속

명령줄 옵션, 입력 파일 형식, 매핑테이블 형식, hwpx 양식 문구, 산출물 이름은 배치 파일, 결과를 받아 쓰는 사람, NRI·NTIS 내보내기, 매핑테이블 담당자, 양식 편집자가 그대로 기대는 약속이다.

## 공통 약속

- **산출 파일 이름**은 `접두어_YYYYMMDD_HHMM.확장자`다. 예외는 각 프로그램 항목에 적었다.
- **입력 열**은 위치가 아니라 머리글 이름(별칭 포함)으로 찾는다. 머리글을 못 찾았을 때의 처리는 도구마다 다르다.
  - 제재통계: 필수 열이 없으면 무엇이 없는지 알리고 멈춘다.
  - 국외지원: 열 위치로 대신 읽고, 그 사실을 처리 내역에 남긴다.
  - 공공데이터 기술문서: 명세 없이 등록 정보만으로 검토를 계속하고, 무엇을 못 찾았는지 보완필요 지적으로 남긴다.
- **입력 파일명 날짜**: 국외지원 raw와 제재통계 rawdata는 파일명에 내려받은 날짜를 넣는다. 그 날짜가 보고서의 기준일이 된다.
- **hwpx 양식**: 글꼴·테두리·여백 같은 서식은 양식 그대로 유지된다. 채울 곳을 찾는 방법은 도구마다 다르다.
  - 국외지원·회의록: 표는 표 안의 머리글 문구로, 값 자리는 자리표시자 문구로 찾는다. 아래에 적은 문구를 지우거나 바꾸면 그 표나 자리는 채워지지 않는다(경고가 남거나 자리표시자가 그대로 남는다).
  - 제재통계: 표를 위치로 찾는다. 표의 개수·순서·행 구조를 바꾸면 경고 없이 다른 표에 값이 들어간다.

## 공공데이터 등록 사전검토

### 명령줄
```
python main.py [파일·폴더·와일드카드 ...] [-m 등록정보] [-x 리포트.xlsx] [--json 결과.json]
               [--fix 대상] [--fix-suffix _수정] [-q]
python main.py --api -m 등록정보 [--spec 기술문서] [--probe --key 인증키]
               [--fix 대상 --fix-out 등록정보_수정.json] [-x 리포트.xlsx]
```

| 옵션 | 뜻 |
|---|---|
| (인수 없음) 또는 `--gui`·`-g` | 화면 실행 |
| `-m`, `--meta` | 등록 정보 JSON 파일 경로 또는 JSON 문자열 |
| `--api` | OPEN API 검토. 없으면 파일데이터 |
| `--spec` | 기술문서(Swagger·OpenAPI JSON, 오퍼레이션 명세표 xlsx·xlsm·csv) |
| `--probe`, `--key` | endPoint 실호출과 그때 쓸 인증키 |
| `--fix` | `서식` · `내용` · `all` · `반려`·`보완필요`·`확인권장`(그 등급 지적 중 고칠 수 있는 것) · 조항 목록(`10-타,10-하`). OPEN API는 `5-가`처럼 적어도 `api:` 접두어를 붙여 다시 찾는다 |
| `--fix-suffix` | 파일데이터 수정본 접미사(기본 `_수정`). 확장자는 원본 그대로 |
| `--fix-out` | OPEN API 수정 등록 정보 저장 경로(기본 `등록정보_수정.json`) |
| `-x`, `--json`, `-q`, `-V` | 엑셀 리포트, JSON 결과, 콘솔 출력 생략, 버전 표시 |

- **종료 코드**
  - 0: 반려가 하나도 없음
  - 1: 결과 목록(자동수정 후 재검토 결과 포함) 중 하나라도 반려
  - 2: 파일데이터 모드에서 검토할 파일이 없음
- **오류**
  - 읽을 수 없는 파일은 그 결과만 반려(오류 문구 포함)가 되고, 다른 파일 검토는 계속된다.
  - 자동수정이 실패하면 표준오류에 `[픽스 실패] 파일: 사유`를 쓰고 계속한다.

### 등록 정보 JSON 키
- **파일데이터**: `목록명`, `데이터명`, `기관명`, `키워드`, `설명`, `기타유의사항`, `공공누리유형`, `저작권포함`, `데이터기준일`, `갱신주기`, `차기등록예정일`, `제공신청여부`, `제공번호`, `등록확장자`, `링크URL`, `중복확인`
- **OPEN API**: `목록명`, `기관명`, `기관코드`, `API명(영문)`, `키워드`, `설명`, `등록유형`(`PUBC`·`GW`·`멀티클라우드`·`링크`, 비면 PUBC), `서비스URL`, `링크URL`, `응답포맷`, `전송방식`, `인증모듈적용`, `TESTKEY`, `기술문서검토`, `공공누리유형`, `저작권포함`, `제공신청여부`, `제공번호`, `부담당자`, `담당자연락처`, `중복확인`, `타기관데이터포함`, `비정형포함`
- 예·아니오 값: 파일데이터는 `예`·`Y`·`y`를 참으로 본다(`저작권포함`은 `true`도 참). OPEN API는 `예`·`y`·`yes`·`true`·`1`·`적용`·`완료`·`on`을 대소문자 구분 없이 참으로 본다. 파일데이터의 `중복확인`은 `완료`·`예`·`Y`·`y`일 때만 확인된 것으로 본다.
- 키워드는 쉼표·세미콜론·줄바꿈으로 나눈다.

### 출력
- **엑셀 리포트**: 두 구분을 한 파일에 담는다.

  | 시트 | 내용 |
  |---|---|
  | `검토요약` | 구분(파일데이터·OPEN API), 대상, 판정, 행·오퍼레이션, 열·파라메터, 인코딩·등록유형, 구분자·응답포맷, 반려·보완필요·확인권장 건수, 기준일 후보 |
  | `상세지적사항` | 구분, 대상, 등급, 기준조항, 항목, 지적내용, 조치방법, 건수, 위치(50개까지), 값 예시(5개까지) |
  | `API명세` | 읽어 들인 오퍼레이션·파라메터 전체(OPEN API를 검토했을 때) |
  | `API에러코드` | 기술문서에서 읽은 에러코드(있을 때) |
  | `API실호출` | 호출 URL(키 가림), 상태코드, 응답시간, Content-Type, 응답 항목(실호출했을 때) |

  화면에서 저장하면 기본 이름은 `공공데이터_사전검토_YYYYMMDD_HHMM.xlsx`다.
- **JSON 결과**: 결과 1건마다 객체 하나를 담은 배열이다. 키는 `file_name`, `domain`(`file`·`api`), `verdict`, `counts`, `findings`, `grid`, `api` 등이다. 지적마다 `rule_id`, `level`, `message`, `fix`, `locations`, `samples`, `count`, `fixable`, `fix_tier`, `manual_reason`이 붙는다.
- **자동수정 결과**
  - 파일데이터: `<원본>_수정.<원본 확장자>`. 원본 형식과 인코딩을 따르고, `10-러`를 고르면 UTF-8(BOM)으로 저장한다.
  - OPEN API: 등록 정보 수정본 JSON. 화면에는 '전 → 후' 대조표와 기술문서에서 직접 고칠 값 목록이 함께 나온다.

## 국외지원사항 통계

### 명령줄
```
python 국외지원사항_통계산출.py <연구자raw.xlsx> <과제raw.xlsx> [출력.xlsx]
```
- 출력 이름을 생략하면 현재 폴더의 `통계분석결과_YYYYMMDD.xlsx`가 된다. 양식이 있으면 같은 이름의 `.hwpx`가 함께 생긴다.
- 화면에서 만들면 `통계분석결과_YYYYMMDD_HHMM.xlsx`와 `국외지원사항_등록보고현황_YYYYMMDD_HHMM.hwpx`가 저장폴더에 생긴다.
- 매핑테이블과 양식은 exe(또는 스크립트) 옆 파일을 먼저 쓰고, 없으면 내장본을 쓴다.
- 잘못된 파일을 지정하면 멈추고 사유를 알린다. 과제 raw 자리 파일에 과제번호·연구책임자 값이 하나도 없거나, 연구자 raw 자리 파일에 성명 값이 하나도 없는 경우다. 양식이 없으면 엑셀만 만든다.

### 입력 파일
- **시트**: 연구자 raw는 `연구자raw`·`연구자 raw`·`연구자` 시트를, 과제 raw는 `과제raw`·`과제 raw`·`과제` 시트를 쓴다. 없으면 첫 시트를 쓴다.
- **연구자 raw 12열**: 번호, 소속기관명, 소속기관 사업자등록번호, 성명, 국가연구자번호, 지원·지급 기간(시작·종료), 지원·지급 사유, 지원·지급 내용, 지원·지급 출처 국가, 지원·지급 출처 기관, NRI 등록일자
- **과제 raw 17열**: 번호, 과제번호, 과제명, 정부연구비, 총연구비, 소속기관명, 소속기관 사업자등록번호, 연구책임자, 국가연구자번호, 지원·지급 기간(시작·종료), 과제와의 관련성, 지원·지급 사유, 지원·지급 내용, 지원·지급 출처 국가, 지원·지급 출처 기관, NRI 등록일자
- **머리글 비교**: 공백·가운뎃점·괄호·기호를 무시하고 비교한다.
  - 지원·지급 기간은 두 칸(머리글 병합)이든 한 칸(`시작 ~ 종료`)이든 받는다.
  - 머리글을 알아보지 못하면 열 위치로 대신 읽고, 처리 내역에 그 사실을 남긴다.

### 매핑테이블.xlsx (담당자가 고치는 파일)

| 시트 | 열 | 뜻 |
|---|---|---|
| `기관별칭` | 원본 기관명(별칭) → 정규화 기관명 | 지원기관 이름 통합 |
| `민감국가` | 국가명 → `위험국가` 또는 `민감국가` | 연구보안 우려 판정 |
| `소속정규화` | 원본 소속기관 → 정규화 소속기관 (+비고) | 산학협력단 → 본교 등 |
| `전처리규칙` | 구분 → 제거 기준값 (+비고) | 구분은 `출처국가`·`지원지급내용`·`지원지급사유`. 값은 앞뒤 공백·끝 마침표를 무시한 완전 일치. 시트에 적힌 구분만 기본값을 대체한다 |
| `유형규칙` | 유형 · 구분 · 값 | 구분은 `포함`·`필수`·`제외`·`정확일치`·`조건부`·`근거`. 값에 `{수량}`(숫자+명·인), `{금액}`(숫자+통화·금액 단위)을 쓸 수 있다. `기타` 행은 판정에 쓰지 않는다 |

- 행을 고치고 저장하면 다음 실행부터 반영된다.
- 같은 원본 이름이 서로 다른 정규화 이름으로 적혀 있으면 실행할 때 경고한다.

첫 시트 위에는 작성 방법, 전처리 기준, 시트 구성, 수치 해석 유의사항이 들어간다. 모든 시트는 가로 방향·폭 맞춤으로 인쇄되도록 설정되어 있다.

### 표준보고양식.hwpx가 지켜야 할 문구
- **표를 찾는 머리글**(표 안에 모두 있어야 함)
  - 월별 등록 수: `구분`·`소계`·`등록 수`
  - 국가별: `국가명`·`등록 수`
  - 지원·지급 유형별: `연구장비`·`겸직`·`유가증권`
  - 소속기관 유형별: `학`·`연`·`산`·`기타`
  - 과제와의 연관성: `관련있음`·`관련없음`
  - 상위 소속기관: `순위`·`소속기관`·`보고 수`
  - 상위 지원기관: `순위`·`연구기관명`·`수혜국가`
- **숫자 `n` 자리표시자가 든 문장**: `국외지원사항 등록 수`, `총 등록 데이터`, `국외지원사항 보고된 과제 수`, `과제 협약 시 보고`, `중복제외`
- **날짜 자리표시자 `yy`·`mm`·`dd`**: 산출기준일로 채운다. 다만 같은 문단에 `연구윤리자산보호센터`·`연구윤리`·`자산보호센터`·`보호센터` 중 하나라도 있으면 발행 표기로 보고 오늘 날짜로 채운다. 본문 날짜 문단에 '연구윤리'라는 말을 넣으면 그 날짜도 오늘로 바뀐다.

## 제재통계

### 명령줄 (연구수행 기준만)
```
python run_report.py [rawdata.xlsx] [옵션]
```
- rawdata를 생략하면 파일 선택 창이 열린다.
- 출력은 rawdata와 같은 폴더(`--outdir`로 변경)에 생기며, 이름은 `제재처분집계_YYYYMMDD_HHMM.xlsx`와 `.hwpx`다(`--prefix`로 접두어 변경).
- 양식을 지정하지 않으면 rawdata 폴더·현재 폴더·출력 폴더에서 `*표준양식*제재처분*.hwpx`를 찾고, 없으면 아무 `*.hwpx`나 집어 쓴다. 그것도 없을 때만 내장 `template.hwpx`를 쓴다. 이전 실행이 만든 `제재처분집계_*.hwpx`가 같은 폴더에 있으면 그 파일이 양식으로 쓰이므로, 항상 `--template`을 지정한다.
- 참조데이터를 지정하지 않으면 내장 `reference.xlsx`를 쓴다.
- 명령줄은 참조데이터에 없는 부처만 경고하고, 검산 4종은 하지 않는다. 검산은 화면에서 실행할 때만 계산된다.

| 옵션 | 뜻 (기본값) |
|---|---|
| `--sheet` | 시트명 (`제재정보`, 없으면 첫 시트) |
| `--header-row`, `--data-start-row` | 헤더 행·데이터 시작 행 (자동 탐지) |
| `--min-task-year` | 과제수행연도 하한 (2017) |
| `--year-start`, `--year-end` | 연도 축 고정 (자동) |
| `--year-end-cap` | 자동 결정 때 종료연도 상한 (올해) |
| `--id-strategy` | 과제 묶기 키: `과제명`(기본) · `번호우선` · `번호` · `번호+명` |
| `--task-type` | 원인과제로 셀 과제유형: `전체`(기본) · `세부만` · `공동위탁제외` |
| `--target` | 제재대상: `전체`(기본) · `기관` · `인물` |
| `--end-date-missing` | 종료일 없는 행: `시작일로채움`(기본) · `행제외` |
| `--ministry-pick` | 부처가 둘 이상인 과제: `first`(기본) · `최다레코드` |
| `--ministry-column` | 부처 기준 열: `소관부처`(기본) · `부처명` |
| `--template`, `--ref`, `--outdir`, `--prefix` | 양식, 참조데이터, 출력 폴더, 파일명 접두어 |
| `--no-long` | 엑셀에서 `연도전개` 시트를 뺀다 (기본은 포함) |
| `--make-ref-template` | 참조데이터 입력 양식(`참조데이터_양식_YYYYMMDD_HHMM.xlsx`)을 만든다 |

- rawdata 파일이 없으면 종료 코드 1로 끝난다. hwpx 생성이 실패해도 엑셀은 남기고 경고만 출력한다.

### 화면 출력 이름
- 연구수행 기준: `연구수행기준_YYYYMMDD_HHMM.xlsx`·`.hwpx`
- 처분연도 기준: `처분연도기준_YYYYMMDD_HHMM.xlsx`·`.hwpx`
- 그림: `<접두어>_YYYYMMDD_HHMM_<그림이름>.png`(가로 2400px 이상, 축 이름·범례·각주 포함)
- 기본 저장 위치는 문서 폴더의 `제재통계`다.

### rawdata 열
- **연구수행 기준**
  - 필수: 과제수행연도, 과제명, 총연구기간시작일, 총연구기간종료일, 제재유형구분, 그리고 소관부처·부처명 중 하나
  - 선택: 과제번호, 처분연도, 처분일, 제재ID, 제재고유번호, 제재대상, 사업명, 과제유형
- **처분연도 기준**
  - 필수: 처분연도, 제재유형구분, 제재ID, 그리고 소관부처·부처명 중 하나
  - 선택: 연구수행주체, 연구수행주체(정제), 제재사유(기본법), 제재사유(혁신법), 미납금액, 대상금액(원), 납부금액(원), 처분일, 제재대상, 사업명, 과제유형
- **값 약속**: 제재유형구분 값은 `참여제한`·`환수금`·`제재부가금`이다. 날짜는 문자열·날짜·엑셀 일련번호를 모두 받는다.
- 열 이름이 조금 달라도 각 파이프라인의 별칭 목록으로 알아본다.

### 참조데이터 (국가R&D연구비·과제수)
- **wide 형식**: `부처 | 항목 | 2017 | … | 2025 | 합계`. 항목은 `국가R&D연구비`·`국가R&D과제수`다.
- **long 형식**: `부처 | 연도 | 국가R&D연구비 | 국가R&D과제수`
- `합계` 행이 없으면 부처 값을 더해 만든다. 빈 칸은 공란으로 나가고, 그 연도 비율은 계산하지 않는다.

### 엑셀 시트
- **연구수행 기준**
  - `집계표(양식)`: hwpx와 같은 배치(부처 × 7항목 × 연도)
  - `부처별_판정별`: 부처 × 판정 × 연도 피벗
  - `과제단위_판정`: 과제 1건 = 1행. 과제번호, 제재유형, 제재ID, 집계반영연도가 들어가며 자동 필터가 걸려 있다
  - `연도전개`: 과제 × 연도. `--no-long`이 아니면 항상 들어간다
- **처분연도 기준**
  - `1`~`9`: 통계 9종. 축을 더 고르면 `10`번부터 이어진다
  - `검산`: 표 간·표 안 검산, 전처리 내역, 연도 축, 제외 건수
  - `전처리`: 11열 전처리 결과. 항상 들어가며 자동 필터가 걸려 있다

### hwpx 양식 (표를 위치로 찾는다)
- **`template.hwpx`(연구수행 기준)**
  - 문서의 첫 번째 표를 쓴다. 머리 행 다음에 오는 7행 블록을 부처 하나로 보고, 부처마다 복제한다.
  - 데이터 연도 수에 맞춰 열을 늘리거나 줄인 뒤 너비를 다시 나눈다.
  - 표가 하나도 없으면 멈춘다. 첫 표의 행 배치가 바뀌면 값이 엉뚱한 칸에 들어간다.
- **`template_monthly.hwpx`(처분연도 기준)**
  - 문서에 나오는 순서대로 표 9개를 통계 1~9번에 대응시킨다. 표가 9개보다 적으면 멈추지만, 순서가 바뀐 것은 알아채지 못한다.
  - 분류 블록(참여제한 1행, 금액 5행)은 표준 목록 + 추가 분류 + `합 계`만큼 복제한다. 행은 양식의 기존 분류 행이 아니라 표준 목록으로 다시 만든다.
  - 각주의 `’yy.mm.dd` 9곳이 기준일 자리다.

## 연구보안·연구윤리 동향 리포트

### 명령줄
```
python run_cli.py [--config config.json] [--report security|ethics|all] [--period-mode monthly|weekly]
                  [--month YYYY-MM] [--week YYYY-Www] [--no-excel] [--data 수집JSON] [--open]
                  [--history-report [출력.xlsx]]
```
- `--period-mode`를 생략하면 `config.json`의 `period.mode`를 쓴다. `--month`·`--week`를 생략하면 직전 달·직전 주(월~일)다.
- `--report all`이면 `config.json`의 `reports.*.enabled`가 참인 리포트를 모두 만든다. `--data`는 이미 수집한 JSON으로 다시 렌더링한다(API 호출 없음).
- `--history-report`는 수집하지 않고 이력 엑셀만 만든다. 경로를 생략하면 `output/이력보고서_YYYYMMDD_HHMMSS.xlsx`다.
- **종료 코드**: 0은 모두 성공이다. 1은 리포트 하나라도 실패, 실행할 리포트가 없음, 이력 보고서 실패 중 하나다.

### 파일
- **출력**: `output/<security|ethics>_<YYYY-MM 또는 YYYY-Www>.html`·`.json`, AI 응답 원문 `…_raw.txt`
- **누적 엑셀**: `data/동향_모니터링_누적.xlsx`의 `누적데이터` 시트. 열은 `번호 | 구분 | 발간일 | 국가 | 기관 | 제목 | 주요내용 | 자료 출처(URL) | n대분류 | 원문제목`이다.
- **실행 이력**: `history/history.jsonl`. 실행 1회마다 보고서 유형, 기간 모드, 수집 기간, 이슈 건수, 생성 일시, 상태, 산출물 경로를 한 줄로 남긴다.
- **`config.json`**: 키는 `period.mode`, `excel.path`·`excel.sheet`·`excel.template`·`excel.skip_duplicate_url`, `history.path`, `output_dir`, `log_dir`, `reports.security.enabled`·`reports.ethics.enabled`다. API 키와 메일 항목은 없다. v2의 `config.json`은 형식이 달라 그대로 쓸 수 없다.

### AI 응답 JSON (프롬프트와 검증기가 공유하는 형식)
- **최상위 키**: `period_label`, `executive_summary`(문자열 배열, 5개까지 사용), `issues`, `no_issue_countries`(국가 코드 → 문구), `kr_other_trend`(`text`, `url`), `analysis`(분석 항목 키 → 문장), `source_compliance_note`
- **이슈 필드**: `country`, `title_kr`, `title_original`, `org`, `date`, `category`, `status`, `content`, `source_url`, `sub_url`, `sub_label`
- 필드를 더하거나 바꾸려면 프롬프트, 검증, 렌더러, 누적 엑셀 열을 함께 고친다.

## 회의록 자동정리

### 명령줄
```
python app.py --cli <녹음파일> --attendees "이름/기관/직위, …" --title <제목> --date YYYY-MM-DD
              --place "<일시·장소 표기>" --out <저장 폴더> [--session <세션.json>]
```
- `--session`을 주면 전사를 건너뛰고 그 세션의 전사문부터 이어 간다. 이때 녹음 파일 자리에는 아무 값이나 넣는다.
  - 참석자는 `--attendees`를 주면 그 값을, 주지 않으면 세션에 저장된 명단을 쓴다. 참석자가 있으면 발언자 매칭을 다시 하고, 하나도 없으면 매칭을 건너뛴다.
  - 요약은 항상 다시 한다. 매칭과 요약은 유료 호출이며, 세션에 있던 요약은 새 요약으로 바뀐다.
  - 세션에 회의 정보(제목·날짜·일시·장소)가 저장되어 있으면 `--title`·`--date`·`--place`보다 세션 값이 우선한다.
- 실패하면 표준오류에 `[실패] 사유`를 쓰고 종료 코드 1로 끝난다.

### 산출물
- `<YYYYMMDD>_<제목>_회의록.hwpx`, `<YYYYMMDD>_<제목>_전사문.txt`, `<YYYYMMDD>_<제목>_세션.json`. 날짜는 회의 날짜이고, 없으면 오늘 날짜다.
- 화면의 [세션 저장]은 `<YYYYMMDD_HHMM>_회의록세션.json`이다.

### OpenAI 요청 약속
- **매칭 응답**: `turns` 배열. 원소마다 정수 `from`, 정수 `to`, 문자열 `speaker`
- **요약 응답**: 문자열 `title`, `agenda`, `implications`, `feedback_plan`, 그리고 배열 `institutions`. 기관마다 문자열 `name`과 배열 `items`(`topic`, `content`)가 있다.
- 세 스키마(매칭·요약·연결 확인) 모두 `strict` 구조화 출력, `additionalProperties=false`다.
- **출력 토큰 상한**: 매칭 16,000, 요약 32,000, 연결 확인 2,000. 요청 제한 시간은 900초, 매칭은 400구간씩 나눠 보낸다.

### template.hwpx가 지켜야 할 자리표시자

| 자리표시자 | 채워지는 값 |
|---|---|
| `ㅇㅇㅇㅇ 회의록` | 회의 제목 + ` 회의록` |
| `’yy.mm.dd.` | 회의 날짜(`’26. 9. 4.` 형식) |
| `., KISTEP 연구윤리자산보호센터)` | 설정의 작성 부서 |
| `’yy. mm. dd. / “장소”` | 일시·장소 |
| `참석자1 기관 참석자1 직위, …` | `기관 직위 이름, …` |
| `희의록 기록 키워드 2줄` | 안건 |
| `회의결과에 따른 시사점` | 시사점 |
| `향후 조치계획, 환류계획 등` | 환류계획 |
| `   -  (참석자1) 내용` | 회의록 원문(발언자별로 문단 복제) |

- **기관별 요약 표**는 11행 3열 원형을 바탕으로 다시 짠다.
  - 0행: 머리행 `기 관`·`항 목`·`발언 내용`
  - 1~5행: 첫 기관 블록
  - 6~10행: 둘째 기관 블록
  - 이 구조를 바꾸면 표 재구성이 깨진다.
